## Adversarial edges (not covered by any §3 AC)

1. **Missing `ac_coverage` key** in `prev.data` (direct callers, resume from a pre-upgrade step sentinel) must be treated as unverifiable, never as uncovered and never a KeyError.
2. **Forward Map grouping:** a bullet like `AC1–AC3 → test_x`, `AC1, AC2: test_y` or `AC1..AC3`. Without range/list handling this is a false reject. At cap 2 a false reject on cycle 2 is terminal `E_VALIDATION_FAILED`.
3. **Whole-file id regex:** `^\|\s*(AC\d+[a-z]?)\s*\|` also matches AC rows in non-§3 tables (§5 test tables, matrices quoted from other issues). That creates phantom ACs and false rejects. The canonical section-scoped `verdict_verify.parse_spec_ac_ids` (`verdict_verify.py:43,170`) avoids this but returns empty for headers like `## §3 Acceptance` (no "criteria"), which silently turns coverage off.
4. **Spec Compliance substring:** "missing"/"partial" anywhere in a bullet ("no missing negatives") would uncover the AC. Match only the status token after the id.
5. **Regression shield:** `verify_validation_citations` completeness demotion (verdict forced to FAIL, `helper.py:457-460`) together with `approve:true`. Today structured overrides the demotion. Strict-AND fixes it, but no AC pins it.
6. **ac_gap + validator SPEC_DEFECT** (precedence, finding 4).
7. **Gate env values other than 0/1** (`false`, `off`, empty) once the call sites move to `gate_enabled`: they read as enabled. This should be stated and tested.
8. **`spec_review_repoll_ignored` "once per run"** across several review cycles in one process, and across processes (each phase is a separate `run.py`). The dedupe key is unspecified.
9. **ENFORCE on + spec with an AC table but no "acceptance criteria" header:** `admit()` returns REJECT "no ACs found" and blocks.
10. **`_normalize_ac_id`** uppercases only the `AC` prefix (`ac_dsl.py:145-149`). `AC1A` and `AC1a` count as different ids, so a validator that changes the case looks uncovered.

## Open questions: recommendations

1. **Forward Map format.** The prompt should mandate one bullet per AC: `` - AC<n>: `test_name` `` (or `` `MISSING` ``).
   - Keep the parser tolerant: id matched as a word with the `AC[- ]?` prefix (same as `verdict_verify._AC_TABLE_RE`) and a case-insensitive suffix.
   - Expand explicit lists and ranges (`AC1, AC2`, `AC1–AC3`, `AC1..AC3`).
   - A citation is any backticked token, `test_\w+`, or a `path::name`.
   - `MISSING` is an uppercase whole word; the Spec Compliance status is the first status token after the id.
   - Put the offending bullet text in the `ac_coverage_gap` payload for calibration.
   - Stay blocking (the issue requires it), with no shadow phase.
2. **retire-by:2027-01-15.** Accept. The flags stay kill-switches (`kind: gate`, `"0"` = legacy byte-identical) and are removed only after a clean window. Cite the issue in the description.
3. **ac_gap consumes a cycle.** Yes. It is a FAIL like any other, bounded by `_resolve_validation_cycle_cap`. The uncovered ids go at the head of `findings` so the cycle-2 RED revision is directed (GH706).

Re-poll removal (§2.5) is sound. The premise check on fresh sessions is verified (`llm_subprocess.py:1728`), and handling legacy keys with an event instead of failing is correct. Strict-AND fail-closed on UNKNOWN+approve is the right call and consistent with the `_gate_on_validation` docstring.
