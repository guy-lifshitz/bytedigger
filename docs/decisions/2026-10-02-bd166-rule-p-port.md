## §2 Design

### §2.1 New module `engine_py/bytedigger_engine/one_sided_predicate.py`

Port of HAL `one_sided_predicate.py`. stdlib only, `from __future__ import annotations`,
Python 3.9, no Cyrillic, no env reads, no subprocess, no import from any other
`bytedigger_engine` module. Listed in `core_manifest.json` `core_modules`.

Copied **verbatim** (frozen by HAL GH1373 §2.0): `_FORM_NOT_TO_BE_INT`, `_FORM_NOT_TO_BE_NULL`,
`_POSCTL`, `_BLOCK_START`, `_PRED_ESCAPE = "one-sided-ok:"`, `_CANDIDATE_FORMS`, `_blocks`,
`_scope_for_line`, `_has_escape` (4-line window), `_scope_has_control`, `_iter_candidates`,
`scan_one_sided_predicates`, `summarize_predicates`, `_PREDICATE_IDENTITIES`,
`check_predicate_identities`, the `CANDIDATE_*` constants. Finding dict keys:
`line, subject, form, reason`.

**Declared divergence D1 — the codey test.** HAL's `_CODEY` regex anchors on `[^a-z0-9_]`, so
`exit_code` / `statusCode` are not codey (measured and documented in bd's
`empty_input_assert._tokens`). The port replaces `_CODEY.search(x)` at its two call sites
(`_iter_candidates`, `_scope_has_control`) with the token-based helper that bd already uses:

```python
TS_TEST_SUFFIXES = (".test.ts", ".test.js", ".spec.ts", ".spec.js")
_CODEY_WORDS = frozenset("code rc exit exitcode returncode status".split())
_TOKEN_SPLIT = re.compile(r"[^A-Za-z0-9]+|(?<=[a-z0-9])(?=[A-Z])")
def identifier_tokens(subject: str) -> frozenset[str]: ...   # moved verbatim from empty_input_assert._tokens
def is_codey(subject: str) -> bool: return bool(identifier_tokens(subject) & _CODEY_WORDS)
```

Every subject HAL's regex calls codey is still codey (the word list is identical; the token split
is a strictly finer boundary), so all HAL GH1373 Rule P fixtures give identical results; the port
additionally sees snake_case / camelCase-hump subjects. `_CODEY` is not kept (one rule, one site).

### §2.3 Phase-5 wiring (`workflows/phase_5_implement.py`)

- Import `scan_one_sided_predicates, TS_TEST_SUFFIXES` from `bytedigger_engine.one_sided_predicate`.
- `_ONE_SIDED_PREDICATE_TS_SUFFIXES = TS_TEST_SUFFIXES` and `_one_sided_predicate_hits(resolved_paths)`
  ported verbatim from HAL: only paths ending in the suffix set are scanned; paths that are neither
  in the set nor `.py` emit `red_one_sided_predicate_unmatched_path` (severity warning, never
  silent); an unreadable target yields a hit with `rule="one-sided-predicate-unreadable"`,

  `red_one_sided_predicate_unreadable_target` error event; each finding yields

- `precommit_lints._TS_TEST_SUFFIXES` becomes an alias of `one_sided_predicate.TS_TEST_SUFFIXES`

### §2.5 Registries and documentation of the escape

- `error_codes.py`: `E_RED_ONE_SIDED_PREDICATE` — "phase_5_implement: RED test contains a
  one-sided negative code-exit predicate (`expect(<code>).not.toBe(<int>)` / `.not.toBeNull()`)
  with no live positive control (`.toBe(<int>)`/`.toEqual(<int>)` on a code-like subject) in the
  same test block (Rule P, bd#166). Escape: `one-sided-ok: <reason>` on the line or up to 3 lines
  above; kill switch HAL_ONE_SIDED_PREDICATE_GATE=0"; `E_RED_LINT_TARGET_UNREADABLE` —
  "phase_5_implement: a RED content-lint could not read its target file; 'no violations' is not
  established for it". Both `ERROR_CODES.md` copies regenerated (`error_codes.main(["--check"])`
  rc 0).
- `flags_catalog.py`: description of `HAL_ONE_SIDED_PREDICATE_GATE` updated to name bd#166
  (key, kind, default unchanged).

### §2.6 Design constraints (issue block)

- **Deterministic first:** the check is regex code; no LLM, classifier or check_ladder step.
- **Provider-agnostic:** the module imports nothing provider-related; the phase-5 helper makes no
  `invoke_llm_subprocess` call. Degradation paths: kill switch → `gate_disabled`; unreadable target
  → recoverable finding; out-of-corpus path → warning event. No crash path.
- **Both backends:** the result is a pure function of file bytes; T-B pins identical output under
  `HAL_RUNNER_BACKEND=claude-subprocess` and `=anthropic-api`, and T-C pins that a raising LLM seam
  (provider down) does not change it.
