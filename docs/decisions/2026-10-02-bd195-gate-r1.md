## Q1. Is the scope decision (only ADV-1/ADV-2 go through the adapter) honest?

**It is honest against the frozen text. It is still a narrowing of the issue's literal ask, so it must be recorded, not left implicit.**

- Levels §6 and §9.1 define the adapter interface as exactly two operations: `freeze` and `evaluate` returning one of three states. Only R1.3/R1.4 (ADV-1/ADV-2) are a freeze-then-re-verify question.
- ADV-3..ADV-6 test engine-side checkers (`stub_passability`, `bd_l2`). Routing them through a host `evaluate` would mean either:
  - re-implementing bd's checkers in the adapter, or
  - filing engine results under a host identity. That is the defect §9 names ("publishing a level we have not measured").
- ADV-7, ADV-8 and ADV-10 need host operations (model identity R3.3, capability set R3.4/R3.5) that the interface does not have.
- Recording these as `not_executed` follows the §8 rule ("a level is claimed only over the adversaries actually executed"). The deferral pattern (re-open when the interface grows operations) matches §8's ADV-11 precedent.
- The issue's own acceptance clauses are met: a non-conforming adapter fails ADV-1 (AC1), and adapter=None stays byte-identical (AC7). The tag is deferred to a post-merge release step, and the spec says so.
- **However,** the issue text says "with adapter **each executable adversary** drives adapter.freeze/evaluate". The spec narrows that.
  - Practical consequence for hal-v2#2226: a host attestation via the adapter tops out at BD-L1. The current engine-measured attestation reads BD-L3, with the host "NOT measured".
  - This is a visible, justified narrowing, not a silent cut. It does not need to block GREEN.
  - It must be stated on the issue/PR, and the follow-up issue must exist with a number. The spec says "follow-up issue" but gives no number, and §8 requires a dated decision with a re-open criterion. See finding 5.

## Step 1.5. Rule-overlap simulation

Dispatcher, in order:
1. `adapter is None` gives the engine probes.
2. A name in {ADV-1, ADV-2} gives the adapter protocol.
3. A name in `ADVERSARIES` gives `not_executed` with no adapter call.
4. Any other name gives `not_executed`. This covers ADV-9 and ADV-99.

The branches are mutually exclusive.

Outcome classifier, first match wins:

| Step | Result | Outcome |
|---|---|---|
| freeze | fails | indeterminate |
| control | INDETERMINATE | indeterminate |
| control | REJECTED | undefended |
| attack | REJECTED | defended |
| attack | ACCEPTED | undefended |
| attack | INDETERMINATE | indeterminate |

Every stub, simulated:

| Stub | Path through the classifier | Outcome | Matches the AC |
|---|---|---|---|
| AcceptAll | control A, attack A | undefended | yes |
| RejectAll | control R | undefended | yes |
| Digest, ADV-1 | control A; a.md rewritten, so the digest differs; attack R | defended | yes |
| Digest, ADV-2 | members now {a, b}, so the digest differs; attack R | defended | yes |
| RaisingEvaluate | control I | indeterminate | yes |

| SleepingEvaluate (0.2s) | control I | indeterminate | yes |

CLI cases:
- Digest with L1: ADV-1/2 defended, ADV-3.. `not_executed`, so achieved is L1 and the exit is 0.
- L2 claim: a complaint, exit 1.
- Accept with L1: achieved is L0, so exit 1.
- Unavailable with L0: L0 is achieved and nothing is complained about, so exit 0.

All of these match.

## Adversarial edges (not covered by any spec AC)

1. **Wait-then-relabel timeout.**
   - Example: a `ThreadPoolExecutor` used as a context manager, `future.result(timeout)` followed by an implicit `shutdown(wait=True)`.
   - It blocks until a hung `freeze` returns, then reports `indeterminate`.
   - It passes AC4 because only the outcome is asserted. Against a provider that never returns, the CLI hangs forever.
   - The same applies to any GREEN that wraps `evaluate_guarded` in another blocking join.
2. **Swallowed interrupt.** A GREEN implementing "No crash" as `except BaseException`, or a freeze guard that converts every boxed exception, turns Ctrl-C or `SystemExit` raised from `freeze`/`evaluate` into `indeterminate`.
3. **Identity type edges.** None of these are tested:
   - a non-Mapping identity (`"b/s"`, `None`, a list)
   - a non-str or empty `backend` (only empty is tested)
   - an empty `source`
   - an `identity` property that raises

   A GREEN using `.get` or `[...]` raises `AttributeError`/`TypeError`, not `ValueError`. In the CLI that becomes an uncaught traceback with exit 1, which collides with "written with complaints". Alternatively a broad catch turns it into exit 2 without the spec's `ValueError` contract.
4. **ADV-9 under an adapter.** `only=("ADV-9",)` with an adapter should give `{"ADV-9": "not_executed"}` and zero calls. The unknown-name rule covers it, but no assertion pins it. A GREEN that special-cases ADV-9 as "declarative, ask the adapter" would pass.
5. **Full-run key set.** `run_adversaries(adapter=...)` with `only=None` is not asserted to return exactly the 9 `ADVERSARIES` keys. A GREEN adding an `ADV-9` key, or dropping one, passes AC6.
6. **Conforming adapter per identity shape.** The issue asks for "stub-backed and backend-unavailable adapters for subscription-session and API-token shapes". The RED has unavailable stubs for both shapes. The stub-backed conforming adapter exists only with the `stub-backend`/`cli-backend` identity.
7. **Identity override flag.** There is no assertion that an `--adapter-identity`/`--identity` argument is rejected with exit 2. A GREEN adding an optional override passes AC9.

## VERDICT

VERDICT: REJECTED

(In the orchestrator's vocabulary: **REJECT**. The scope decision is sound and the RED is strong against most wrong GREENs. Two new error and timeout branches of the freeze guard can be implemented wrongly and still pass. Both are cheap RED additions, so a fast r2 is expected.)

### Findings
1. **MAJOR. The freeze timeout is not tested as a timeout.**
   - `freeze_sleeps` and `evaluate_sleeps` assert only the outcome. A guard that waits for the worker and then labels the result `indeterminate` passes (adversarial edge 1).
   - The issue names "timeout -> INDETERMINATE, never crash" as the core property. A hung provider would hang the CLI in CI.
   - Nothing asserts the freeze worker is a daemon. The spec says "same daemon-thread guard semantics".
2. **MAJOR. The §2-vs-§3 mismatch.**
   - Change 4 states that `KeyboardInterrupt` and `SystemExit` from `freeze` are re-raised, and that the "No crash" catch-all covers `Exception` only. No AC exercises this.
   - A `BaseException`-swallowing GREEN passes every test (adversarial edge 2).
3. MINOR. The AC7 literal is never reached on the pre-GREEN tree, because the preceding line raises `TypeError`. Its correctness rests on the gate's hand check. Optional: assert the literal against `run_adversaries()` before the `adapter=None` call, so it is proven green on main now.
4. MINOR. Identity type edges (adversarial edge 3) are unpinned.
5. MINOR, to be done before merge rather than before GREEN. Record the ADV-3..10 scope narrowing against the issue's "each executable adversary" wording:
   - in the PR body and on bd#195
   - on hal-v2#2226, as a "host attestation via the adapter caps at BD-L1" note
   - as a follow-up issue with a number, a date and the re-open criterion (§8 pattern). The spec currently says "follow-up issue" without a number.
6. MINOR. Adversarial edges 4-7 (ADV-9 under an adapter, the full-run key set, a conforming stub per identity shape, rejecting an identity flag) are cheap to add.
7. MINOR. Spec clarity:
   - state the CLI `--timeout-s` default (30.0)
   - state that the timestamp default and `sort_keys` output are unasserted
   - fix the `adapter_identity = adapter_identity(adapter)` wording to the keyword form
8. MINOR. The overclaim case asserts only `stderr.strip() != ""`. A tighter check would be that stderr contains `level_claimed`, which is the `validate_attestation` complaint text.

### Must-fix list (r2 RED + spec)
1. **Freeze guard timeout is real.**
   - In AC4 `freeze_sleeps` and `evaluate_sleeps`, bound the wall time. For example, raise the stub sleep to about 5s and assert that `run_adversaries(only=("ADV-1","ADV-2"), timeout_s=0.2)` returns in under about 2.5s (`time.monotonic()`).
   - While a SleepingFreeze is still sleeping, assert that every alive non-main thread is `daemon is True`, using the same predicate as bd27 `_non_daemon_alive_non_main_threads`.
2. **The BaseException branch has an AC.**
   - Add AC4b (spec plus RED): an adapter whose `freeze` raises `KeyboardInterrupt`, and one that raises `SystemExit`. Make the same two cases for `evaluate`. `run_adversaries(only=("ADV-1",), adapter=...)` must propagate the exception, using `pytest.raises(KeyboardInterrupt)` and `pytest.raises(SystemExit)`.
   - This pins both the freeze guard's re-raise and the "No crash" catch-all being `Exception`-only.
3. Before merge (does not block GREEN): finding 5. A follow-up issue number for "adapter operations for ADV-3..ADV-10" must be written into the spec's "Not in scope" section, and the narrowing stated on bd#195 and hal-v2#2226.
