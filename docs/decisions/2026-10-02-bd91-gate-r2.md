## Findings

1. **MAJOR. The §2.2 markdown axis omits `PARTIAL`.** `helper.py:589-590` sets `verdict = "PARTIAL"` on unverified citations. This verdict reaches `_gate_on_validation` via `prev.data["verdict"]`. No rule matches it, so the "total 24-cell" claim is false. Fix: add an explicit rule for markdown values other than PASS/FAIL. Recommended: fold `PARTIAL` (and any non-PASS/FAIL token) into rule 2 as fail-closed, with reason `markdown_partial` (or `markdown_missing`). Alternatively, rule it as pass-through, but decide one. Then extend AC7 to 4x4x2 = 32 cells and declare the effect on `gh349` `test_canonical_gate_verdict_helper_invariant_matrix`, which already loops over `"PARTIAL"`.
2. **MAJOR. The legacy branch breaks GH517A2 `test_ac12`, which §5 says stays green.** `test_phase_45_ac_dsl_wiring_GH517A2.py:423-428` asserts exactly one `spec_ac_dsl_warn` whose `reasons` list contains `"AC-checks section not found"`. r2 §2.4/AC21 emits `reason="legacy_no_ac_checks"` with `admit` not called, so `reasons` is empty and the test fails. That forces GREEN to edit a test (§1s) or to deviate from the spec. Fix: pin the legacy payload as `{"reason": "legacy_no_ac_checks", "reasons": ["AC-checks section not found (legacy_no_ac_checks)"], "spec_path": …}`, and add the `reasons` assertion to AC21. Alternatively, declare `test_ac12` as a RED-phase edit.
3. **MAJOR. "Citation = any backtick token" lets placeholders count as coverage** (edge 2), so the deterministic coverage check can be satisfied with `` `N/A` ``. Fix: a citation counts only if the token (after stripping a `path::` prefix) occurs verbatim in at least one `red_test_paths` file. These paths are already in `prev.data`. This stays provider- and language-agnostic and degrades to `unverifiable` on read failure. Add the case to AC2 (`` `N/A` `` and a fabricated test name give uncovered with a new reason code `citation_not_found`), and add the code to the §1n list.
4. **MINOR. Header widening risks** (new-surface (a)-(d)). Fix:
   - make it two-pass: first `.*acceptance criteria`, and only if there is none, fall back to `.*\bacceptance\b`;
   - make the `phase_6_review` copy decision unconditional (recommended: widen both in lockstep and add a parity assertion to AC19);
   - list `verdict_gate.run_gate` / GH517 lint as an affected consumer in §5, with `test_GH749`, `test_gh751` and `test_gh1065` AC12 as run-confirmations.
5. **MINOR. AC20 and AC22 are green before the fix** and are not declared as shields. Fix: assert AC20 through the two call sites, and give AC22 a GREEN-only observable (`gate_reason`, or the `ac_coverage_unverifiable` event).
6. **MINOR. §5 accuracy.**
   - gh634 `test_ac9` sets no env. The edit is "add `setenv('HAL_AC_DSL_GATE_ENFORCE','0')`".
   - GH517A2 `test_ac8` (admit raises, env unset) stays green under §2.4, because the result is still `ok` plus one `spec_ac_dsl_driver_error` with `error`. It does not break.
   - `gh1018` and `gh1626d` do not call `_gate_on_validation`.
7. **MINOR. Reject-log `reason_code` literal for ac_gap is undefined.** The existing vocabulary is `VALIDATION_*`. Fix: name it (for example `VALIDATION_AC_GAP`) and assert it in AC1.
8. **MINOR. ac_gap on the terminal cap path.** State which return paths carry `gate_reason`/`ac_gap_ids` (recommended: both the below-cap and the terminal path), and add a cycle==cap variant to AC1.
9. **MINOR. Under-specified AC wording.** AC19's "import check" should be a sentinel monkeypatch of `verdict_verify.parse_spec_ac_ids`. The AC16 dedupe needs a defined behaviour when `run_id` is None (edge 5). AC17's date pin should be stated as deliberate (edge 6).
