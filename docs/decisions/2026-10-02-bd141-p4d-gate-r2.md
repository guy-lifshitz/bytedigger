### AC5b teeth (asked explicitly)

- **`_declared_injections(prev)` with a StepResult.** It returns `()` for a non-dict. Every case passes the real `StepResult` produced by
  the builder as `prev` to the real invoke step (`:742,752`), so the spy records `()`, which is not `expected`, and the test goes **red**.
- **A literal `()`.** It goes **red** the same way.
- **A defaulted pool `injections`.** `_run_satisfaction_evaluators_parallel` resolves `invoke_llm_subprocess` as a module global at call
  time (`phase_6_review.py:3044`). The monkeypatched module attribute is therefore exactly the object `executor.submit` receives.
  `telemetry_ctx.run_with_current_run` (`telemetry_ctx.py:70-87`) calls `fn(*args, **kwargs)`, so the spy sees every submitted kwarg.
  The COMPLEX branch (`:3242`, reading `cfg.get("complexity")` from the invoke ctx, which `ctx_extra` supplies) submits n=3. Suppose GREEN
  adds `injections=()` to the helper and leaves the caller at :3261 unwired. All three calls then record `()` and the test goes **red**.
  The rest of the step (`:3265-3293`) only indexes `raw_response` and the four path keys, which the spy and the builder supply, so the
  assertion is actually reached.
- **Repoll.** `_REVISE` triggers `_frozen_revise_repoll`. With n_repolls=2, after one repoll `_ship_reachable(0,2,1)` is False and the
  loop breaks, so exactly two calls are made, which meets min_calls=2. A GREEN that adds `injections` to the first `invoke_llm_subprocess(**invoke_kwargs)`
  call but not to `invoke_kwargs` turns the repoll call red.
- **The spy does not mock the unit under test.** The unit under test is the invoke step's argument wiring. The spy replaces the dispatch
  target only. AC6 still anchors the real chokepoint and attestation (§1l).
- **Stubbing `ensure_graph` in the phase_1 and phase_2 cases is acceptable.** It is called only inside the invoke step
  (`phase_1_discovery.py:461`, `phase_2_explore.py:378`, after the builder ran unstubbed). Its return value goes only into
  `extra_data["graph_source"]` (`:478`). It never touches `prompt` or `injections`. It shells out to `graphify`, which is not the unit under test.

## Adversarial edges (not covered by any §3 AC)

1. **A spread on a role-bearing producer with no template configured** (M2). `_build_decorr_prompt` returns
   `{**_prev_data, "prompt": prompt}` (`phase_6_review.py:5492`). Its upstream `prev.data` is built by many `{**prev.data}` steps (`:5070,
   5197`) and, after GREEN, can carry the fix step's record. AC3's decorr driver passes an empty `_prev()`. So a GREEN that writes
   `if rt: data["role_template"] = ...` instead of setting the key unconditionally passes every test. That GREEN then leaks a stale record
   whenever upstream data carries one and this ctx has no template, for example on a resume after `role_template_path` was removed from
   org_config. The dispatch then declares content that is not in the prompt, and the run hits `E_INJECT_UNATTRIBUTED`, a hard stop.
2. **Unused-import cleanup** (M1). Once no builder calls `_maybe_role_template`, its import in `phase_5_implement.py:181/183` and
   `phase_6_review.py:150/152` is unused. A tidy GREEN that removes it turns `test_261:110-123` and `test_34AEB235:674,717` red.
   The p4d RED cannot see this.
3. **Double read / a keyword default that conflates "not passed" with "no template"** (N1). If the new keyword on the `str` builders defaults to
   `None` and means "read it yourself", a wrapper that passes `role_template=None` for an unconfigured ctx triggers a second read. Under the
   same config this is harmless. But no test pins the single-read rule at all.

## Findings

**M1 MINOR: the import retention that AC2's sibling-safety depends on is allowed but not required.**
AC2 (§3 :91-94) says that `test_261` and `test_34AEB235` "stay green unedited". That holds only if `phase_5_implement.py:181/183` and
`phase_6_review.py:150/152` keep importing `_maybe_role_template`. After GREEN that import is unused, and nothing in §2 forbids removing it.
The full-suite delta (§1r) would catch the removal, so this is advisory. **Fix:** add one line to §2.1: "phase_5_implement and phase_6_review keep
`_maybe_role_template` in their `phase_workflows_common` import (re-export pinned by test_261:110-123, patched by test_34AEB235:674,717);
do not remove it as unused." The other modules may drop it.

**M2 MINOR: AC4b drives branches that cannot leak. The one spreading producer is untested.**
`phase_45_spec_lite.py:404-418` and `:570-582` build literal dicts. The only role-bearing producer that spreads `prev.data` is
`_build_decorr_prompt` (`phase_6_review.py:5492`). The phase_45_spec producers go through the `_fwd_frozen` whitelist, so absent means None.
**Fix:** add an AC4b case. Call `_build_decorr_prompt` with a ctx that has no `role_template_path` and a `prev.data` that carries
`_stale_record()`, then assert `data["role_template"] is None`. This tests the "explicit on every branch" rule where it can actually fail.

**N1 NIT:** §2.2's single-read rule has no test. The keyword-only `role_template` parameter should use a sentinel default, not `None`,
so that "no template" (`None`) is not read again. A forwarding counter on `phase_workflows_common.load_role_template`, which is not a
mock, could assert one read per producer.

**N2 NIT:** AC5b and AC8 skip the identity pass-through steps (`_check_red_executable`, `_cwd_preflight`, `_check_green_token_budget`,
`_fix_watchdog`), although the AC5b text says intermediate steps are driven. Either chain them in the test (cheap: each takes `(ctx, prev)`)
or reword AC5b to "intermediate steps that transform `prev.data`".

**N3 NIT:** leftover "16" wording. Spec §1.3 :20 says "none of these 16 prompts" (it should be 17). The RED module docstring :6 says "the other 16 builders"
and the section header at :307 says "the 16 builders".

No MAJOR findings. All three r1 MAJORs are closed with evidence. The pool, rewrite and repoll paths are now traced to behavioural tests,
and the AC5b teeth hold for the StepResult slip, a literal `()` and a defaulted pool parameter.
