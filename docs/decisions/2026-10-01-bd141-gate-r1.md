## Step 1: spec-internal consistency

- I hand-walked C1-C9 under the spec rules. C1, C2, C3, C4, C5, C6, C7 and C8 give the stated results. C7 checks out: `&&` split, `NAME=value` strip, `timeout 60s` strip, then `bun test` followed by a space. `python3 -m pytest` is preferred because `pytest` cannot match at position 0. `bun testx` is rejected by `(?!\w)`.
- **Drift 1 (C9 vs the Red section).** The spec gives the bun fail form as `(fail) <name> [12.3ms]`, so the duration looks required. But C9(b) `"... (fail) x"` has no duration and must return `"x"`. C11/C14/C16 use `[1ms]`, an integer. The TS source uses `^P\s*\(fail\)\s+(.*?)(?:\s+\[[0-9.]+ms\])?\s*$`: the duration is optional and the name capture is lazy. The spec text and its own AC disagree.
- **Drift 2 (IGNORECASE scope).** Section 2 says "All regexes use Python `re` with `re.IGNORECASE`". That also covers the red-line regexes. In the TS source those are case-sensitive: `TF_RED_LINES`, `TF_BUN_FAIL` and `TF_RED_WHOLE` have no `i` flag, and only the vocabulary patterns use `giu`. The spec contradicts itself: `[Ee]xit code` would be pointless under IGNORECASE. The divergence is not in the intentional-divergence list, and it changes behaviour: `^P\s*FAILED\b` would mark any line starting with `failed`/`Failed` as red, which gives false `fire` verdicts.
- **Drift 3 (journal dir).** The spec's journal step is "append one JSON line" and says nothing about creating parent dirs. The source does `mkdirSync(dirname(logFile), {recursive:true})` (ld.ts:159). L13 puts `log_path` under a `logs/` dir that does not exist and asserts `log.is_file()`. A GREEN that follows the spec literally fails the journal write silently (as the spec allows) and then fails L13.
- Minor: the advisory text is wrapped across two markdown lines (spec 156-157). L16 asserts a single line. Say explicitly that it is one line with no newline.

## Adversarial edges (not covered by any AC)

1. Negation scope: `"Not yet. Done."` must return `"Done"`. A GREEN that scans the whole text before the match passes C2 but gets this wrong (blocker 5).
2. Red-line case sensitivity: a line like `"failed to resolve host"` or `"Failed: 0"` must not be red (part of blocker 2).
3. Thrash counted over the last `thrash_span` entries, not the whole window. Example: 3 failed Bash calls, then 9 other-tool calls, then 2 Bash calls. That should give no thrash, but a whole-window GREEN passes L4 and still gets it wrong.
4. Mixed-episode refresh: when one hit key is live and a new hit key appears, the new key must be refreshed into `live` with no alert. Not tested.
5. `runner_id` first-hit order across segments: `"pytest; bun test"` -> `"pytest"`. Untested, low risk.
6. A user entry whose list content mixes `tool_result` and `text` blocks counts as a turn boundary. Untested.
7. `load_state` with a `bool` `live` value or a `bool` `last_alert_n`. The spec covers this but no test does.

## 3. Verdict

VERDICT: REJECTED

### Blockers (MAJOR)

1. **test_bd141_claim_evidence.py:404, test_bd141_loop_detector.py:391.** Both B2 regexes `"[<U+0400>-<U+04FF>]"` contain literal Cyrillic-block characters. Fix: write it as the ASCII escape `"[Ѐ-ӿ]"` (normal or raw string, so the source stays ASCII).
2. **Spec section 2, op1 header ("All regexes use ... re.IGNORECASE") and the Red paragraph.** IGNORECASE is applied to the red/bun-fail regexes, which are case-sensitive in the source. It is not a declared divergence and it causes false `fire`. Fix: limit IGNORECASE to the Vocabulary patterns and `runner_id`, and state that `bun_fail_identity`/`text_is_red` are case-sensitive. Add C8 false cases such as `"failed to resolve host"` and `"Failed: 0"`.
3. **Spec Red paragraph vs C9.** The bun fail form shows a required `[12.3ms]` suffix, but C9(b) expects a match without it. Fix: write out the exact regex, `^P\s*\(fail\)\s+(.*?)(?:\s+\[[0-9.]+ms\])?\s*$`, together with the exact P, `(?:[^\t\n]*\t){0,2}(?:\S+Z\s+)?`.
4. **Spec section 2, op2 Event (journal bullet) vs test_bd141_loop_detector.py:272,276.** L13 needs the journal's parent dir to be created, and the spec does not say so. Fix: add "makes parent dirs of `log_path` (failure = journal failure)" to the spec, matching ld.ts:159. Do not loosen the test.
5. **test_bd141_claim_evidence.py:93-96 (C2).** A GREEN that applies negation to the whole prefix instead of the clause still passes. Fix: add `_claim("Not yet. Done.") == "Done"` to C2, and add the same case to the C2 row of the spec.

### Notes (MINOR, advisory)

1. Spec 156-157: say the advisory string is one line.
2. Spec section 2 Claim: define "the clause it sits in ends with `?`" as "the next clause-boundary char after the match is `?`" (TS line 349).
3. No test covers the save_state tmp cleanup on write failure. L14 fails at mkdir, before any tmp file exists.
4. CLI missing `--transcript` -> rc 2 is specified but not tested.
5. Journal `session_id`: say whether it is raw or sanitized (the TS writes the sanitized sid).
6. The `gh ` prefix exemption is broader than the TS (`gh pr checks` / `gh run`). That is acceptable because the runner list is vocab data, but list it as a divergence.
7. Adversarial edges 3 and 4 above (thrash span and mixed-episode refresh) are worth one assert each.

VERDICT: REJECT
