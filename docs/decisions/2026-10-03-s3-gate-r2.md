## Step 1.5: Rule-overlap simulation (new r2 grammar)

**Comparison extraction, then pairing, then ok-set** (simulated on realistic 1668 phrasings):

1. `- AC1: prose share < 0.25 over 12 real stubs`, `sample:` real file, `measured: 0.31`.
   Comparisons with non-trivial N, in order: `< 0.25` (non-integer), `over 12` mapped to `> 12` (integer >= 10). k = 2, one measured value, so the count does not match. §3: "not checked, ... `unverified` with `ambiguous_pairing` (never a contradiction)". Result: **no finding, status `clean`, exit 0 in ENFORCE.** This is the exact 1668 shape (0.25 vs real 0.31).
2. Same with `on at least 20 stubs`, `up to 12 workers`, `in under 30 lines`, `max 15 files`: each incidental count adds a second non-trivial comparison, which turns a k=1 AC into k=2, and that again lands on `ambiguous_pairing`, so the AC is clean.
3. The leak continues into the RED half. §4's ok-set is "equals a `measured` value or the threshold of an AC with no finding of its own". The ambiguous AC has no finding, so `0.25`, `12` and `0.31` all become "calibrated". A RED that asserts `0.25`-calibrated synthetic values against a lot fixture is then **not** flagged either.
4. If the `measured:` segment ends right after the numbers, a natural line `measured: 0.31 over 12 stubs` leaves ` over 12 stubs` in the block, which triggers the same k=2 escape. (The segment extent was r1 MINOR 7 and is not re-raised; it only makes item 1 easier to hit.)

r2 introduces this fail-open path through the interaction of two r2 choices. The word forms (`over`, `under`, `up to`, `max`, `min`, `at least`) turn incidental counts into comparisons, and the mismatch rule is "never a contradiction". r1 finding 2 asked that "a count mismatch counts as a finding" (or that every value must satisfy every comparison). r2 chose neither. **MAJOR 1.**

**Phrase precedence:**
- Overlapping phrases are `no more than` / `not more than` (`<=`) vs `more than` (`>`), and `not less than` (`>=`) vs `less than` (`<`). A single leftmost-match regex resolves them correctly. A per-phrase loop instead finds both. It either inverts the operator (`no more than 0.4`, `measured: 0.5` read as `> 0.4`, which is clean: fail-open) or produces k=2 on the same N, which falls into `ambiguous_pairing` (also clean). The spec does not state leftmost-longest / no-double-count. In the RED, the containing forms appear only in NO_SAMPLE rows, which cannot tell the operators apart, so the RED does not pin this. MINOR 2. It is cheap, and the fix for MAJOR 1 covers the k=2 branch.
- Reversed vs forward: `0.25 > share` matches only the reversed form, because `>` is followed by an identifier, not N. `p95 < 200`: the reversed form needs an identifier after the operator, and `200` is not one, so there is no double match. `10 <= x <= 20` yields `>= 10` and `<= 20` (k=2). Consistent with §3.
- Word-form boundaries are unspecified (`min` inside `admin 15`, `max` inside `maximum 20`, `over` inside `turnover 20`), and so is the left boundary of N (`p95`). Implementations can diverge. MINOR 4.

**Run-status dispatcher (r2):** F1-F6 give `unavailable`. That beats expiry (stated and tested). Next comes expiry in SHADOW (`flag_expired`), then `flagged` / `clean`. F6 is checked against `<base>`, so it needs a resolvable base: F1 `git_failed` comes first, which is consistent.

**Lot set A (r2):** `git diff --no-renames --name-only --diff-filter=ACMRT <base>` compares base with the work tree, so committed lot changes are included. `git mv` + edit shows as A (new path) + D (old path, filtered out). The test simulates correctly. Untracked files are added via `ls-files --others`. Correct.

## Findings

**MAJOR (blocks GREEN)**

1. **`ambiguous_pairing` is fail-open on the target class, and r2's broader word grammar makes it easy to reach** (§3 pairing rule, §4 ok-set, AC14). Any 1668 AC that mentions a sample size or bound in prose (`over 12 stubs`, `on at least 20 files`, `up to 12 workers`) gets a second non-trivial comparison. A single `measured` then gives "not checked, never a contradiction": status `clean`, ENFORCE exit 0. The AC also stays in the ok-set, so its thresholds and measured values calibrate RED numbers and hide the RED circularity finding as well. r1 finding 2 required that a count mismatch is a finding (or that every value satisfies every comparison). r2 adopted neither, and the RED pins the fail-open as correct (`test_ac14_count_mismatch_is_unverified_ambiguous_pairing_no_finding`).
   Required, in both spec and RED. Pick one:
   - (a) A count mismatch with k>1 is a finding (for example a new code `MEASURED_UNPAIRED`, or reuse of `MEASURED_CONTRADICTS` with a `detail` that names the mismatch).
   - (b) On a mismatch, every measured value must satisfy every non-trivial comparison, and violating any one is `MEASURED_CONTRADICTS`.

   Either way, an AC with a mismatch is excluded from the ok-set. Update `test_ac14_count_mismatch_*` to the chosen rule. Add a regression test: `prose share < 0.25 over 12 real stubs`, real sample, `measured: 0.31`, ENFORCE gives exit 1. Optionally pair it with a RED asserting `0.2` from a lot fixture, which must still be flagged.

**MINOR (advisory, new in r2; r1 minors not re-raised)**

2. Phrase precedence: state "leftmost-longest match; a phrase contained in a longer matched phrase is not matched again" (`no more than` / `not more than` over `more than`, `not less than` over `less than`). Add MEASURED_CONTRADICTS rows: `no more than 0.4` with `0.5` contradicts, `not less than 11` with `5` contradicts, and `not more than 40` with `40` gives no finding.
3. §3 carries two AC regexes (the line regex with `AC[0-9A-Za-z_-]*` and the id regex `AC[-_]?\d...`). Fold the id regex into the line regex so there is one literal.
4. Word forms and N need explicit boundaries: `\b` around word phrases (`min`, `max`, `over`, `under`), and N not preceded by `[\w.]` (the same rule as the §4 whole token). Otherwise `admin 15` or `p95` yield comparisons depending on the implementation.
5. Echo the resolved `--base` SHA in the verdict (r1 MAJOR 3 suggested it; not adopted). Without it, a wrong but resolvable base (edge 6) is invisible to the reviewer. This needs a `VERDICT_KEYS` change, so it can be deferred to the wiring follow-up.
6. F6 makes a lot that edits an existing, base-tracked spec unrunnable. State this in §5/§8 as a known limit (or as a waiver need before the flip).
