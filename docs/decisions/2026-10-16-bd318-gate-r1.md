## Adversarial edges (not covered by any AC)

1. Composition collision: `FanoutJob(role="a", prompt="P\n\nIN")` and `FanoutJob(role="b", prompt="P", input_text="IN")`. The tuples differ, so `assert_distinct` passes, but the *invoked* prompt is byte-identical. Structural-guard escape.
2. Whitespace / case / trailing-newline bypass: `prompt="P"` vs `prompt="P "` or `"P\n"`, and the same for `input_text`. Exact tuple equality passes them, the model sees identical work. Spec does not state a normalization policy. A whitespace-only prompt (`"   "`) as "blank prompt" is also unpinned (the test uses `""` only).
3. Role-only difference with `input_text` empty vs None-equivalent: covered. Not covered: two jobs whose only difference is the role *and* the other job has a blank role. Error precedence (ValueError vs IdenticalFanoutError) is unspecified.
4. Helper exemption by basename: a `workflows/llm_fanout.py` (or any file named `llm_fanout.py` outside `lib/`) must NOT be exempt. A basename-based exemption passes AC8.
5. Real-site shape: `submit(wrapper_callable, ctx, invoke_llm_subprocess, prompt=...)`, model callable at positional index 2 behind a wrapper. An implementation that checks only `args[0]` passes AC5-AC9 and misses the one site that exists.
6. Dispatcher forms listed by the spec but with no fixture: `starmap`, `apply_async`, `run_in_executor` (model callable at index 1), `from threading import Thread`, attribute form `llm_subprocess.invoke_llm_subprocess` (used by `lib/plugins/anti_hallucination/semantic_verifier.py:229`).
7. Inline wrappers: `submit(lambda: invoke_llm_subprocess(...))`, `submit(functools.partial(invoke_llm_subprocess, ...))`, `asyncio.to_thread(invoke_llm_subprocess, ...)`, `Thread(target=lambda: ...)`. The spec's out-of-scope clause excludes "wrappers", but lambda/partial are the most common bypass and the spec should state the decision explicitly.
8. Direct non-pooled `telemetry_ctx.run_with_current_run(ctx, invoke_llm_subprocess, ...)` must not be a finding (false-positive guard).
9. `HAL_LLM_FANOUT_LINT` values other than `0` and `1` (`""`, `"false"`, `"off"`, whitespace). Unspecified.
10. AC10 post-#317: function `_run_satisfaction_evaluators_parallel` deleted (see finding 2).

## Findings

1. MAJOR (AC2, the owner's top priority) - structural guard is escapable. `assert_distinct` compares exact `(prompt, input_text)`. (a) Different splits of the same composed text (`prompt="P\n\nIN"` vs `prompt="P", input_text="IN"`) pass the guard but send identical prompts. (b) Trailing whitespace / newline / case changes pass. Fix in the spec: the identity key is the *composed* invoked prompt, normalized (strip, collapse whitespace, decide casefold), and also reject a whitespace-only prompt. Add RED tests for (a), (b) and the whitespace-only blank prompt, each with zero model calls.
2. MAJOR (AC10) - the test is both vacuous and not "green after #317".
   - Vacuous: it asserts only subset ("no stray"). A `fanout_findings` returning `[]` on the real tree passes, so nothing pins that the real site is detected before #317. The real site has a shape (model callable behind `run_with_current_run`, positional index 2) that no other fixture covers.
   - Broken post-#317: `fn = next(n for n in ast.walk(tree) if ... name == "_run_satisfaction_evaluators_parallel")` has no default. Once #317 deletes the function, `next()` raises `StopIteration` and the test fails. The claim "stays green then" is false. Fix: `next(..., None)`; if the function exists, require exactly 1 finding and it inside lo..hi; if absent, require `[]`. Plus add a fixture replica of the real shape (`executor.submit(run_with_current_run, ctx, invoke_llm_subprocess, prompt=...)` inside a ThreadPoolExecutor) expecting exactly one finding, so detection is pinned independent of the HEAD file.
3. MAJOR (AC5-AC7) - the stub-passable rule: all fixtures put `invoke_llm_subprocess` as the first argument of the dispatcher (or `target=`). A first-arg-only implementation passes every RED test and misses the real site (finding 2) and `run_in_executor`/`starmap`/`apply_async` forms. Fix: add fixtures for the wrapper/positional-index shape and at least `run_in_executor`, `starmap`, `apply_async`, attribute form `llm_subprocess.invoke_llm_subprocess`, plus the spec's decision on lambda/partial (either flagged or explicitly documented as known-limit with a test that pins the chosen behaviour). Pin the `run_with_current_run` direct-call false-positive decision (edge 8).
4. MAJOR (AC5/AC7/AC9) - spec incompleteness the RED silently fills. The RED assumes `main([str(root)])` takes the tree root as the sole positional argv and calls module-level `lint.load_inventory()` (monkeypatched). The spec says only `main(argv=None)`. A GREEN that picks any other contract (e.g. `--root`, `check(root, inventory)` with an inventory loaded elsewhere) fails the RED for a reason the spec cannot justify. Fix: state argv grammar (root positional, default = package root), inventory source (module-level `load_inventory()`), and the output stream (stdout, asserted).
5. MINOR - AC8: add the basename-exemption decoy (`workflows/llm_fanout.py` with pooled call must yield 1 finding).
6. MINOR - Change A behaviours with no observation: (a) telemetry run carried into workers (add a fake that records `telemetry_ctx.get_current_run()` in the worker with a run set in the parent); (b) concurrency (a serial implementation passes; use a `threading.Barrier(n, timeout=...)` fake rather than timing); (c) job-order returns (the fake returns instantly, so completion order == submission order; make the first job slow via an Event).
7. MINOR - AC9: only `0` vs `1` pinned; spec should say whether `""`/`false`/`off` are off. AC9 also does not show that, with the switch off and a non-empty `check()` problem set, `main` still reports exactly that set (empty inventory makes the claim untested).
8. MINOR - spec cites 3229-3245 (actual 3229-3248); preflight facts "10 fail" vs 18 collected items. Orchestrator to confirm all 18 are red at assert time.
