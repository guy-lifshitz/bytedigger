## Step 1.5: Rule-overlap simulation

**AC-line recogniser, then block, then numeric test (per AC):**
- `- AC1: prose share < 0.25` gives a numeric AC with threshold 0.25. The `sample:` / `measured:` lines are stripped first, so `with01` / `0.31` do not count as thresholds. This matches every AC1 test.
- `count >= 1 and share < 0.25`. §3 says "the AC's **comparison** is the first operator form in its block", so `>= 1` is selected. Measured values are compared only with it. With `measured: 0.31` we get 0.31 >= 1, which is false, so the AC is flagged (by luck). With `count >= 1 and p95 < 200 ms`, `measured: 300` we get 300 >= 1, which is true, so the AC is **clean. That is fail-open.** **MAJOR (finding 2).**
- `p50 < 100 ms and p95 < 250 ms`, `measured: 90, 240`. Only `< 100` is used, and 240 violates it, so the AC is flagged even though it is correct. No rule pairs measured values with thresholds. MINOR, folded into finding 2.
- `prose share below 0.25`, `less than 0.25`, `no more than 0.4`, `under 0.25`, `0.25 > share`, `exceeds 0.9`, `up to 0.5`, `\u043c\u0435\u043d\u044c\u0448\u0435 0.25`: **none of these matches** the §3 grammar. There is no comparison, no listed phrase, and no unit, so the AC is not numeric: no `NO_SAMPLE`, clean. That is fail-open by ordinary English (and Russian) paraphrase. **MAJOR (finding 1).**
- Unit form `N (%|ms|s|...)` has no trailing word boundary in the spec. `task 1668 shape`, `bd#231 says`, `#2208 shows` and `12 samples` all match `N s...`, so they become non-trivial numeric ACs. That is a false `NO_SAMPLE`, and implementations diverge depending on whether they add `\b`. MINOR (finding 7).
- An AC line regex with a case-sensitive `AC[0-9A-Za-z_-]*` matches `ACME:`, `ACL.` and `ACK -` as AC lines. A `#` line inside a fenced code block (a Python comment) ends the AC block as a "heading". MINOR (finding 7).

**Per-AC check dispatcher (in the order of §4):**
1. `NO_SAMPLE`: numeric with no `sample:`. Tested.
2. `SAMPLE_NOT_REAL`: per cited sample. Tested for missing, empty, untracked, modified and directory cases.
3. `NO_MEASURED`: "with a valid sample". Tested.
4. `MEASURED_CONTRADICTS`: **no precondition is stated.** If the sample is invalid or missing and `measured` contradicts, the result could be both findings or only the first. Tests use `in` (AC3) or exact lists only where no overlap occurs, so nothing contradicts. But two GREENs could produce different code lists. MINOR (finding 9).

**Run-status dispatcher:** F1-F5 give `unavailable`; otherwise expiry (SHADOW only) gives `flag_expired`; otherwise `flagged` / `clean`. The precedence between `unavailable` and `flag_expired` (for example a bad base after the expiry date) is unspecified. Both are non-zero, so this is not fail-open. MINOR (finding 9). `flag.expired` in ENFORCE after the date (true or false?) is unspecified. MINOR.

**Lot-set A computation (`git diff --name-only --diff-filter=AM <base>` ∪ untracked):**
- Default `--base HEAD` after the lot has committed its spec, RED and fixtures (a RED checkpoint commit is normal under §1z). Then A = {spec, RED} only. Committed synthetic fixtures count as base-tracked, so they are **real samples**, and no lot data files exist. Both checks report `clean`. **Fail-open via the default. MAJOR (finding 3).**
- `--diff-filter=AM` with porcelain `git diff` (rename detection is on by default) leaves out R, C and T. A staged `git mv` of a fixture plus an edit is not in A, so the RED-circularity check fails open for that file. MAJOR (finding 3).
- `--root` set to a subdirectory of a work tree passes F1 ("is a git work tree"), but `git diff --name-only` prints paths relative to the top level, while `ls-files --others` and the cited paths are relative to root. A lot-modified tracked fixture is then not matched to A and counts as real. Fail-open by misalignment. MAJOR (finding 3).

## Step 3: RED adequacy

- **Collection vs assert time (§1q):** OK. Nothing imports the script. `_exec` and the AC10 static test both `assert SCRIPT.exists()` inside the test body. The guard against the interpreter's own exit 2 on a missing file is correct. It matters here because 14 tests expect exit 2.
- **No self-mocking (§1l):** OK. The UUT runs as a real subprocess against real `git init` repos. Nothing is shimmed except PATH hygiene. AC12 is a real end-to-end shape that exercises the verdict (exit code plus JSON), which is the production side effect of a standalone gate script.
- **`_verdict` helper:** strong. It requires one JSON object, the exact key set, the exact finding key set, an rc consistent with status and mode, and no Traceback.
- **Stub-passability:** a constant `clean` stub fails every positive test. A stub that flags every numeric-looking token fails the many negative cases (trivial numbers, non-whole tokens, non-data extensions, base-tracked fixtures, off-assert lines, bools). The positive and negative tests are paired for every check, so no single heuristic passes the set.
- **Contradictions between tests and spec or between tests:** none found. I simulated all 126 cases against §3/§4, including the whole-token cases (`ends 0.31.` flagged, `0.31.2` / `1_0.31` / `0.310` not), the `31%` sign test, `== 0.5000000001` against the 1e-9 tolerance, and the `samples` directory (note that `git cat-file -e HEAD:samples` succeeds for a tree, so GREEN must check `is_file()` on disk, and the test enforces this).
- **Weak or vacuous asserts:** `test_ac7_no_shadow_log_flag_creates_no_log_file` only looks for `*.jsonl` under `tmp_path`. AC11's snapshot covers root, so this is acceptable. `test_ac10_dynamic_*` is mainly a precondition check, but it also asserts a real flagged verdict, so it is not vacuous.
- **Test-to-implementation coupling (MINOR, finding 10):** (a) the AC10 env-read check only records calls whose first argument is a literal `ast.Constant`. `ENV = "HAL_SPEC_SAMPLE_ENFORCE"; os.environ.get(ENV)` yields `read_names == set()` and fails, although it is correct. `consts` is already computed and could resolve the name. (b) AC10 rejects *any* string constant ending in `.ts`, which is broader than the spec's "subprocess argv" (a help string like `"... (.py, .ts)"` would fail). (c) `detail` must contain the number (Step 1).
- **Coverage gaps (tied to the MAJOR findings):** no test for phrase or reversed comparisons (finding 1), for trivial-first multi-comparison ACs (finding 2), or for a committed lot / non-HEAD base / subdirectory root / renamed fixture (finding 3).

## Does the circularity definition catch the 1668 shape?

- **Spec half: yes, but by `NO_SAMPLE`, not by the tested path.** In the real 1668 the threshold was frozen with no measurement at all, so the real shape is "numeric AC, no `sample:`", which gives `NO_SAMPLE`. `MEASURED_CONTRADICTS` only fires when the author honestly measured the real value and still froze a contradicting threshold. AC12 tests only that second variant. The literal 1668 variant (no `sample:`, ENFORCE gives exit 1) is covered only by composing AC2 and AC7. MINOR (finding 5): add it to AC12.
- **But the spec half fails open by paraphrase** (finding 1): `prose share below 0.25` is the same 1668 spec in different words and is not caught.
- **RED half: only the literal-echo shape.** The RED checks fire only when the asserted number appears verbatim in a lot data file or in a single string literal of 8 or more characters. The typical 1668 RED (synthetic text built in code, asserting a derived ratio, or asserting the threshold itself: `assert share(stub) < 0.25`) produces no RED finding, because `0.25` does not appear in the fixture text, and a concatenated fixture (`"stub " * 3 + "0.31"`) is excluded by the length rule (finding 6). This is acceptable because the spec half is the real catcher. But §4 must state this limit outright, so that nobody reads the RED checks as covering derived circularity. MINOR (finding 5).
- **Gaming surface (not a blocker, must be disclosed):** a lot can cite any base-tracked non-empty file (`README.md`) with an invented satisfying `measured`, or write a "sample" to an absolute path outside root (`/tmp/...`, an agent scratchpad), which rule (ii) accepts as real. Both cases end up in `unverified` at best. MINOR (finding 4).

## Adversarial edges (not covered by the §6 AC table)

1. **Paraphrased comparisons:** `less than 0.25`, `below 0.25`, `under 0.25` (no unit), `no more than 0.4`, `more than 0.9`, `greater than 15.5`, `exceeds 0.9`, `up to 0.5`, `max 0.25`, `0.25 > share` (reversed operands), `10 <= x <= 20` (lower bound lost), `\u043c\u0435\u043d\u044c\u0448\u0435 0.25` / `\u0431\u043e\u043b\u044c\u0448\u0435` / `\u043d\u0435 \u043f\u0440\u0435\u0432\u044b\u0448\u0430\u0435\u0442`. All of them give "not numeric", so the AC is silently clean. (Finding 1.)
2. **Trivial comparison first:** `errors == 0 and p95 < 200 ms`, `measured: 300` is compared only with `== 0`. `count >= 1 and latency < 200 ms`, `measured: 300` is clean. (Finding 2.)
3. **Several non-trivial comparisons in one AC** with a measured list: there is no pairing rule, so you get false contradictions or missed ones. (Finding 2.)
4. **Lot committed before the gate**, default `--base HEAD`: lot fixtures become "real", and the verdict is clean. (Finding 3.)
5. **`git mv` plus an edit of a fixture** (status R), or a symlink-to-file type change (T): left out of A by `--diff-filter=AM`. (Finding 3.)
6. **`--root` is a subdirectory of the work tree:** toplevel-relative diff paths vs root-relative cited paths, so A misses modified files. (Finding 3.)
7. **Absolute sample outside root written by the lot** (`/tmp/s.txt`, scratchpad), or **a symlink**: an outside-root path pointing into root, or an in-root sample symlinked to a lot file. Realpath handling is unspecified. (Finding 4.)
8. **Assert messages and docstrings in the RED:** `assert x == 0.31, "expected 0.31 here"` contains the asserted number in a literal of 8 or more characters, giving a false `RED_EXPECTED_FROM_INLINE_FIXTURE`. **Parser and extractor tests** (inline input `"measured: 0.31"`, assert `== 0.31`) are flagged by construction even though they are not circular. (Finding 6.)
9. **Unit without a word boundary:** `task 1668 shows`, `#2208 says`, `12 samples`, `10 sessions` become numeric ACs. (Finding 7.)
10. **Fenced code inside an AC block:** a `# comment` line ends the block. AC-like lines inside fences (meta-specs, like this very spec) are parsed as ACs. `ACME:` / `ACL.` lines are parsed as ACs. (Finding 7.)
11. **Self-application:** run on its own spec, the tool reports `NO_SAMPLE` for AC1/AC2 (`< 0.25`, `200 ms` are test data, not thresholds). Meta-specs need the waiver that §8 already lists as a flip precondition. Advisory only.
12. **Number grammar:** `1,000 ms`, `1e-3`, `-40`, `.5`, `1_000` (Python literal; textual vs value matching against fixtures), and `1.0` (is it "non-integer"?) are all undefined. (Finding 7.)
13. **Non-UTF-8 sample or lot data file:** it is unspecified whether that is exit 2 or decoded with replacement. (Finding 8.)
14. **`--shadow-log` inside root on repeated runs:** the log is an untracked `.jsonl` file, so it becomes a "lot-authored data file" in the next run, and its `ts` digits (`2026`) can match asserted numbers. (Finding 9.)
15. **`approx(0.31, abs=0.01)`:** the tolerance `0.01` counts as an asserted number. Advisory.

## Findings

**MAJOR (any one of these blocks GREEN)**

1. **The threshold grammar fails open on common English and Russian comparison phrasing** (§3). Only symbols, `at least/at most/not less than/not more than`, `\u043d\u0435 \u043c\u0435\u043d\u0435\u0435/\u043d\u0435 \u0431\u043e\u043b\u0435\u0435`, and unit numbers are recognised. `less than`, `more than`, `greater than`, `fewer than`, `below`, `above`, `under`/`over` (without a unit), `no more than`/`no less than`, `exceed(s)`, `up to`, `max`/`min`, reversed operands (`N < x`, `N > x`) and `\u043c\u0435\u043d\u044c\u0448\u0435`/`\u0431\u043e\u043b\u044c\u0448\u0435`/`\u043d\u0435 \u043f\u0440\u0435\u0432\u044b\u0448\u0430\u0435\u0442` are all missed. Each of them turns a 1668-class spec into a silent `clean`. Required: extend §3 with these forms and an explicit phrase-to-operator mapping (for example `below`/`under`/`less than` → `<`, `no more than`/`up to`/`max` → `<=`), and treat reversed operands by flipping the operator. Add the forms to `test_ac2_threshold_and_unit_forms_without_sample_are_no_sample`, and add at least two `MEASURED_CONTRADICTS` cases on phrase forms (for example `below 0.25` with `measured: 0.31`, and `0.25 > share` with `measured: 0.31`).
2. **Comparison selection is "first operator form", which can pick a trivial comparison** (§3). An AC like `count >= 1 and p95 < 200 ms` with `measured: 300` is reported clean, which is fail-open. Required: the comparison is the first comparison whose N is **non-trivial**. Specify what happens when there are several non-trivial comparisons: either measured values pair positionally with non-trivial comparisons (and a count mismatch counts as a finding), or every measured value must satisfy every non-trivial comparison, with that limit stated. Add tests: `count >= 1 and share < 0.25`, `measured: 0.31` gives `MEASURED_CONTRADICTS`, and the multi-threshold case behaves as the chosen rule says.
3. **The lot-authored set A can be silently empty or misaligned, and that fails open** (§3, F1). (a) With the default `--base HEAD` after the lot has committed, the lot's fixtures count as real. Required: a fail-closed rule, for example "if the `--spec` file is tracked at base and not in the diff (that is, the base already contains the lot), exit 2 `git_failed`" (or a new named reason such as `base_includes_lot`), or make `--base` mandatory. Echo the resolved base SHA in the verdict. (b) Compute A with `--no-renames` and `--diff-filter=ACMRT` (or equivalent), so that renamed, copied and type-changed lot files count. (c) Require `realpath(--root) == realpath(git rev-parse --show-toplevel)`, otherwise exit 2 (F1), or normalise all paths to the top level. Tests: lot committed plus default base gives exit 2. The same lot with `--base <pre-lot sha>` gives the expected findings (this is also the missing positive `--base` test). A staged `git mv` of a fixture plus an edit is flagged. A subdirectory root gives exit 2.

**MINOR (advisory; fix in the same revision where cheap)**

4. Disclose the gaming surface in §4: an arbitrary base file with an invented `measured`, and lot-written absolute samples outside root. Recommended: mark outside-root samples in `verified`/`unverified` entries (for example `"external": true`), and specify realpath resolution before the inside/outside test (symlink cases).
5. AC12 tests only the "honest measurement" variant. Add the literal 1668 variant (numeric AC with no `sample:` under ENFORCE gives exit 1, `NO_SAMPLE`). State in §4 that the RED checks detect literal echo only, not derived values, threshold asserts or programmatically built fixtures.
6. AC6's example `"stub " * 3 + "0.31"` is not caught by §4's literal-length rule. Either reword AC6 to match the single-literal test, or extend the rule (for example constant-fold `BinOp` over string constants), and add a test. Also exclude assert messages (`ast.Assert.msg`) and docstrings from "inline fixture" literals, or document the false positive. Note that parser and extractor tests are flagged by construction, which strengthens the "waiver before flip" precondition.
7. Grammar determinism: define the number grammar (sign, leading `.`, exponent, thousands separators, `1_000`; whether matching against fixtures is by source text or by value; whether `1.0` is trivial), put `\b` after units, state that AC-line matching is case-sensitive and requires `AC` followed by a digit (to keep out `ACME:`), and say whether fenced code blocks are skipped for both AC lines and the heading terminator. Define how far a `sample:`/`measured:` segment extends (to end of line?) and what happens to unparseable `measured` tokens (`~0.31`, `0.31 on 7 stubs`).
8. Specify decoding for samples and lot data files (recommended: bytes, or UTF-8 with `errors="replace"`, never exit 2 just because a real sample is binary or latin-1), and say that relative `sample:` paths resolve against `--root` (not against the spec's directory; the tests assume root).
9. Fill in the unspecified outcomes: whether `MEASURED_CONTRADICTS` is still evaluated when the AC already has `NO_SAMPLE`/`SAMPLE_NOT_REAL`; the precedence of `unavailable` over `flag_expired`; `flag.expired` in ENFORCE after the date; `would_block` for `unavailable`/`flag_expired`; whether `--shadow-log` is written in ENFORCE, on `unavailable` and on `flag_expired`; the outcome for an unwritable shadow-log path; leaving the shadow-log path out of A; the shape of `verified` entries with several samples ("occurs in any cited sample" vs "in each"); and that the ok-set "clean AC" condition applies to measured values as well.
10. Test coupling: let the AC10 env-read check resolve module-level string constants through `consts` (or state the literal-argument requirement in the spec); narrow the `.ts` literal ban to subprocess argv or note it in the spec; state in §1 that `detail` contains the offending number and file.
11. Add a non-UTF-8 RED file case to AC9 (F2 lists it, but no test covers it).
12. §1b: before freeze, run a one-off dry run of the token rules over this repo's `docs/decisions/*.md` and `tests/*.py` and record the false-positive count in §7, so that the SHADOW flip has a baseline to compare against. Fix the typo "precondition ." in §7.
