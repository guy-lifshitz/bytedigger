## Principles

- **Deterministic first:** coverage is decided by the engine, and the prompt is only the secondary layer.
- **Provider-agnostic:** a missing or broken structured block falls back to markdown plus coverage, and the fresh session is enforced by `hard_gate`.
- **Degrade, not fail:** §4 holds. Unreadable inputs, missing keys and parser errors all give `unverifiable` and never fail the step.

## Adversarial edges (not covered by any §3 AC)

1. **Class-qualified, Rust-module, dotted, parametrized, call-suffixed and subtest citations:** `path::Cls::test_m`, `tests::it_works`, `Cls.test_m`, `test_m[case]`, `test_m()`, `TestFoo/sub`. Each false-rejects today (finding 1).
2. **AC id mentioned outside the bullet head**, e.g. `- AC5: \`MISSING\` (unlike AC1)`. AC1 becomes uncovered (finding 2).
3. **Forward Map written as a table** (`| AC1 | test_x |`) instead of bullets. Every AC is `absent`, which gives `ac_gap` every cycle (finding 2).
4. **Prose backtick identifier present in a RED file**, e.g. `- AC3: no test asserts \`gate_reason\``. Counts as covered. This is fail-open and should be declared (finding 8).
5. **Worktree mode with only `current_worktree_path` set** (no `git_cwd`) and process cwd elsewhere (finding 3).
6. **`red_test_paths` empty in `prev` but persisted** (`_read_red_test_paths(scratchpad)`, the fallback `_build_validation_prompt` already uses at `:6481-6486`). Coverage degrades to `unverifiable` silently. This is acceptable, but should be stated.
7. **Spec table row with a range id `| AC1-AC3 |`.** `_AC_TABLE_RE` yields the phantom id `AC1-AC3`. The Forward Map expands the range and never matches it, which gives `absent`. This is a pre-existing parser quirk that now has blocking effect. Advisory only.
