## Step 1.5: Rule-overlap simulation

**Classifier (Dockerfile vs IaC vs none), first match wins:**
- `Dockerfile`, `Dockerfile.dev`, `app.Dockerfile`, `sub/Dockerfile.prod` → Dockerfile. Matches the tests.
- `k8s/Dockerfile.yaml` → matches both `Dockerfile.*` and "`*.y*ml` under k8s". The spec gives no precedence. MINOR (finding 19).
- `Dockerfile.dockerignore` (a real BuildKit per-Dockerfile ignore file) → matches `Dockerfile.*` and goes to hadolint. That gives a parse error (DL1000, level error) and a false block. MINOR (finding 19).
- `charts/app/values.yaml` → IaC. `src/app.yaml` / `config.yaml` → none. Matches the tests.
- `compose.yaml` / `compose.yml` (the canonical Compose v2 file name), `Containerfile`, `*.tf.json`, `kustomization.yaml` outside the listed dirs → none, so these files go unscanned without any signal. MINOR (finding 18).

**Status dispatcher. I simulated every branch in order:**
1. `--root` missing → F5, exit 2. Tested.
2. Candidate enumeration: `git ls-files`, or `--files`. **No branch exists for `git ls-files` failing** (root is not a git repo, `git` is not on PATH, dubious ownership rc 128). The first branch that would match in a natural implementation is "empty candidate list", which gives `nothing_to_scan` and **exit 0**. That is fail-open. **MAJOR (finding 1).**
3. No candidates → F4, exit 0, and no binary is needed. Tested.
4. Binary missing for a present class → F1/F2. Tested, including the mixed-class cases.
5. Scanner run: timeout / bad rc / non-JSON / wrong shape → F3. With two scanners, or several hadolint runs, the spec does not say which outcome wins when **one run blocks and another is unavailable**. Both outcomes are non-zero, so this is not fail-open, but the reported status is not deterministic. MINOR (finding 12).
6. Severity mapping, then gating vs nongating, then waivers → blocked / clean. Overlaps:
   - The gating set comes from `--fail-on`. An empty or unknown token (`--fail-on ""`, `--fail-on CRTICAL`) gives a gating set that matches nothing, so every finding is nongating and the run exits 0. Fail-open. **MAJOR (finding 4).**
   - An empty or whitespace allowlist pattern is a substring of every `scanner|file|id|description`, so it waives every gating finding. Fail-open. **MAJOR (finding 5).**
   - An unknown or missing hadolint `level` has no branch. Only unknown trivy severities fail closed. **MAJOR (finding 6).**

## Step 3: RED adequacy

- **Collection vs assert time:** OK. Nothing imports the script. `_run` and the AC8 static test both `assert SCRIPT.exists()` inside the test body, so all 64 tests fail at assert time with an AssertionError. The guard that stops a missing script from passing the exit-2 cases through the interpreter's own exit 2 is correct and important.
- **No self-mocking:** OK. The UUT runs as a real subprocess. Only the external scanners are shimmed. The hermetic env (PATH limited to the shim dir plus `/usr/bin:/bin`, temp HOME, no API key) is sound.
- **`_verdict` helper:** strong. It requires exactly one JSON object, an exact key set, an exact finding key set, rc consistent with status, and no Traceback.
- **Coverage per AC:** AC1–AC9 each have at least one discriminating assertion. There are control runs in AC6 and AC7, an AC9 run that cannot pass vacuously (AVD-X-1 still gates), and the per-finding waiver test catches an implementation that waives everything.

**Gaps (an implementation could pass every test and still fail open):**
- **Masked wrong-shape test (finding 2).** In `test_ac4_f3_wrong_json_shape_exit2`, the bad hadolint output alone already forces exit 2. The trivy shim's `[]` is never checked on its own. An implementation that accepts any JSON from trivy (`[]`, `{}`, `{"Results":"x"}`) as "zero findings, clean" passes all 64 tests.
- **Hadolint "parse only when rc==1" shortcut (finding 3).** Every hadolint shim that has findings exits 1. An implementation with `if rc == 0: return []` passes all 64 tests. In real use, hadolint exits 0 with warning-level findings when `failure-threshold` is set to `error` in config, so `--fail-on MEDIUM` would fail open. Also untested: rc 1 with empty stdout. Real hadolint exits 1 with an empty stdout (stderr only) when it cannot read the file. An implementation that defaults empty stdout to `[]` fails open.
- **F5 tests can be passed by an argparse usage error (finding 13).** Both F5 tests check only `rc == 2` and the absence of a Traceback. argparse exits 2 on any usage error. They do discriminate against the silent-default fail-open in the allowlist case, because the fixture has a gating finding and a silent default gives exit 1. But they never check that a verdict JSON is emitted, which §1 requires.

## Step 4: Reachability (§1y)

- **Point:** `scripts/devops_scan.py` `main()`, the single verdict producer named in the spec's chokepoint. The file does not exist yet, as expected before GREEN.
- **Host:** `main()`, which calls the scanners through `subprocess`. AC8 statically pins exactly one `main` and exit codes in {0,1,2}.
- **Test-path:** every behavioural test runs `sys.executable scripts/devops_scan.py --root …` as a subprocess, so the real Point is exercised. For the AC9 side effect, the tree hash under `--root` (excluding `.git`) is taken before and after a run that has findings, waivers and both scanners. The trace is complete.
- One reachability caveat: AC9 excludes `.git`, so `git ls-files` refreshing the index is allowed. That is acceptable and intentional.

## Adversarial edges (not covered by the §3 AC table)

1. **Non-git root without `--files`.** `git ls-files` returns rc 128, or `git` is missing from PATH. The likely result is an empty candidate list, `nothing_to_scan`, exit 0. (Finding 1.)
2. **Clean output from real trivy.** Trivy's `Report.Results` and `Result.Misconfigurations` are both `omitempty`. A clean real run has **no `Results` key**, and a result with no failures has no `Misconfigurations` key, or a null one. The `_tv()` fixture always emits `Results:[{Misconfigurations:[]}]`. A strict implementation would report every clean real run as `unavailable`. A permissive one would accept any dict. The spec has to define the minimal valid shape. (Finding 2.)
3. **Trivy-only wrong shape.** `[]`, `{"Results":"x"}`, `{"Results":[{"Misconfigurations":"x"}]}`, or a misconfiguration item without `ID`. None of these is tested in isolation. (Finding 2.)
4. **Hadolint exits 0 with an `error` or `warning` finding** (because of a config `failure-threshold`), and **hadolint exits 1 with empty stdout** (unreadable file). (Finding 3.)
5. **`--fail-on ""`, `--fail-on CRTICAL`, `--fail-on ,`.** The gating set ends up empty or matching nothing, so the run is always green. (Finding 4.)
6. **Allowlist line `  :: ABCDEF12 :: kill-by:2099-01-01`** (empty pattern) waives every finding. Patterns like `|` or `hadolint` are similar: by-design substring matching, but there is no guard. (Finding 5.)
7. **Hadolint item with unknown or missing `level`**, or missing `code`. Mapping it to LOW by default fails open. (Finding 6.)
8. **Scanner-native suppression that bypasses the allowlist:** a repo-local `.hadolint.yaml` (`ignored:`, `override:`), inline `# hadolint ignore=DL3006` pragmas, `.trivyignore` / `trivy.yaml` in the cwd, and inline `#trivy:ignore:AVD-…` in `.tf`. Any of these removes a finding before the script sees it, with no agreement ID and no kill-by. This matters because GREEN/LLM agents write to these repos. (Finding 7.)
9. **Several Dockerfiles where one hadolint run fails** (timeout or rc 3) and the others succeed. A per-file loop that uses `continue` on error fails open. Not tested. (Finding 8.)
10. **Tracked file deleted in the worktree.** `git ls-files` still lists it, hadolint is fed a missing path, exits 1 with empty stdout, and the run is unavailable. That is a false fail-closed. The "missing entries are ignored" rule should also apply to git-sourced candidates. (Finding 9.)
11. **Non-ASCII file names.** With the default `core.quotePath`, `git ls-files` prints `"\303\251/main.tf"` quoted and escaped. The path "does not exist", gets ignored, and the file is never scanned. Use `git ls-files -z`. (Finding 9.)
12. **`--files` with absolute paths inside root, or paths relative to a different base.** Every entry is silently ignored, giving `nothing_to_scan` and exit 0. The verdict does not show that inputs were dropped. (Finding 10.)
13. **Trivy dir scope vs candidate scope.** `trivy config infra/` scans everything under `infra/` recursively, including untracked files and files outside `--files`. If GREEN filters findings back to candidates, a `Target` relative to the scanned dir (`main.tf` vs `infra/main.tf`) can be dropped by a naive comparison. AC9 catches only the most naive version of this. The spec does not say whether findings are filtered or how `file` is composed (`dir + Target`). (Finding 11.)
14. **Mixed outcome:** hadolint blocked and trivy timeout. The status/reason precedence is unspecified. (Finding 12.)
15. **Coverage claims for compose and tfvars.** `trivy config` has no Docker Compose misconfiguration checks, and `*.tfvars` is only used together with `.tf` (`--tf-vars`). A compose-only change reports `clean` when nothing was actually checked. (Finding 18.)

## Findings

**MAJOR (any one of these blocks GREEN)**

1. **Fail-open when candidate enumeration fails** (§1/§2). There is no rule for `git ls-files` failing: root is not a git repo, git is absent, or rc is non-zero. Required: add an F-row ("no `--files` and `git ls-files` rc≠0 or git missing → exit 2, reason `git_ls_files_failed`"), plus a test that uses a non-git root without `--files` and a Dockerfile present, and expects exit 2.
2. **Trivy JSON shape undefined, and the wrong-shape test is masked** (§2 F3, AC4). Required in the spec: give the minimal valid trivy shape, for example: top level is a dict; `Results` is absent, null, or a list of dicts; each `Misconfigurations` is absent, null, or a list of dicts each carrying a string `ID` and `Severity`. Anything else is F3 with reason `json_decode_error` or a named `bad_shape`. Also state how `Status: "PASS"` items are handled. Required in RED: (a) a real-style clean document with no `Results` key → `clean`, exit 0. (b) trivy-only wrong shapes (`[]`, `{"Results":"x"}`, an item without `ID`) with only `main.tf` in the repo → exit 2. (c) Split the existing combined test so hadolint and trivy wrong shapes are each tested alone. Do the same for hadolint: an item missing `code` or `level` → exit 2.
3. **Hadolint rc semantics have no discriminating test** (§2 "Findings rc"). Required: (a) hadolint rc 0 with an `error` finding → exit 1, blocked. (b) hadolint rc 1 with empty stdout → exit 2, `json_decode_error`. The spec should state that empty stdout is never `[]`.
4. **`--fail-on` validation is missing, which is a fail-open path.** Required: the spec states that the `--fail-on` set must be non-empty and drawn from {CRITICAL, HIGH, MEDIUM, LOW, UNKNOWN} (case-insensitive). Otherwise → exit 2 (an F5 extension, "no silent default"). Add a test for `--fail-on ""` and for `--fail-on CRTICAL`, each with a CRITICAL finding, expecting exit 2.
5. **An empty allowlist pattern waives everything** (§3). Required: the spec defines an empty or whitespace-only pattern as malformed (skipped). Add `f" :: ABCDEF12 :: kill-by:{FUTURE}"` and `f"   :: ABCDEF12 :: kill-by:{FUTURE}"` to the `test_ac5_malformed_line_*` parametrization.
6. **Fail-closed severity rule is asymmetric** (§3). Only trivy's unknown severity maps to HIGH. Required: the spec says an unknown or missing hadolint `level` maps to HIGH (or counts as wrong shape, F3), and a missing trivy `Severity` maps to HIGH. Add one test per scanner.
7. **Scanner-native suppression bypasses the allowlist governance** (§3, a SECURITY class). Required: an explicit spec decision on repo-local `.hadolint.yaml`, inline `# hadolint ignore=` pragmas, `.trivyignore` / `trivy.yaml`, and inline `#trivy:ignore:`. The recommended decision is to neutralise them: run the scanners with cwd outside `--root` and HOME/XDG pointed at an empty dir, pass `hadolint --disable-ignore-pragma` with an explicit neutral config, and pass `trivy --ignorefile <empty>` / `--config <empty>`. Pin the decision with a shim-argv assertion and a cwd assertion. Inline trivy ignores that cannot be disabled must be listed as a known limit. If the decision is instead to honour these files, the spec must say so and explain why that does not reopen GH#342.

**MINOR (advisory; fix in the same revision where cheap)**

8. Add a test with several Dockerfiles where one hadolint run fails (shim switching on argv) → exit 2, not a partial verdict. This guards against a per-file `continue`.
9. Candidate enumeration: specify `git ls-files -z` (unicode paths) and say that a git-tracked path missing on disk is ignored, the same as `--files`.
10. Put a count of dropped `--files` entries in `reason` (for example `"ignored 3 of 3 --files entries"`), so an "all inputs dropped" `nothing_to_scan` can be told apart from a real one. Also say whether absolute paths inside root are accepted.
11. Trivy scope: say whether findings outside the candidate set are kept or filtered, and that `file = relpath(dir/Target, root)`. Add a test asserting `file == "infra/main.tf"` for a trivy finding.
12. Define precedence when outcomes are mixed. Recommended: unavailable > blocked > clean, because a partly unscanned tree is not "blocked with known findings". Optionally list known findings in the unavailable verdict.
13. The F5 tests (`test_ac7_f5_nonexistent_root_exit2`, `test_ac5_f5_unreadable_explicit_allowlist_exit2`) should call `_verdict(r)` and assert `status == "unavailable"` with a non-empty reason. Right now an argparse usage error passes them. Also make the spec say a top-level exception handler emits an unavailable verdict with exit 2, never an uncaught traceback with rc 1. rc 1 would be misread as "blocked".
14. The AC8 static test requires literal int exit codes (`assert codes`). `return EXIT_BLOCKED` with module constants would fail it even though it is correct. Either let the test resolve module-level int constants, or state the literal-int requirement in the spec. This is test-to-implementation coupling.
15. Spec drift: add `--timeout` (and its default) to the §1 synopsis. Add the "wrong shape" and "unreadable allowlist" cases to the AC4/AC5 text. Name the wrong-shape and F5 reasons.
16. Allowlist details: say whether lowercase hex is valid for `AGREEMENT-8HEX`, and whether kill-by has a maximum horizon. A 2099 date currently gives a permanent waiver.
17. `test_ac1_dockerfile_hadolint_error_blocks_exit1_high` asserts `"-f" in words`. `--format json` would be equally valid. Accept either, or keep the spec literal and note the coupling as intentional.
18. Coverage honesty: `trivy config` does not check Docker Compose, and `*.tfvars` alone yields nothing. Either drop these from the IaC class or document that a compose-only change is checked by nothing. Consider adding `compose.y*ml`, `Containerfile`, and `*.tf.json` to the classifier, or list them under Out of scope.
19. Classifier precedence: say which class wins for `k8s/Dockerfile.yaml`, and exclude `Dockerfile.dockerignore` from the Dockerfile class.

VERDICT: REJECTED

(In the caller's terms: REJECT.)

Required fixes before GREEN, all MAJOR:
1. Add a fail-closed rule and a test for `git ls-files` failure, or git missing, when `--files` is not given (non-git root → exit 2).
2. Define the minimal valid trivy and hadolint JSON shapes in the spec. This includes treating real trivy's omitted `Results`/`Misconfigurations` as clean. Add an isolated trivy-only wrong-shape test, and split the masked combined test.
3. Add hadolint rc 0 with an error finding → exit 1, and hadolint rc 1 with empty stdout → exit 2. State that empty stdout never means `[]`.
4. Validate `--fail-on`: an empty or unknown severity set → exit 2. Add tests.
5. Treat an empty or whitespace allowlist pattern as malformed. Add it to the malformed parametrization.
6. Make the fail-closed severity rule symmetric: an unknown or missing hadolint level, and a missing trivy Severity, map to HIGH (or count as wrong shape). Add tests.
7. Make an explicit spec decision, pinned by a test, on scanner-native suppression (`.hadolint.yaml`, ignore pragmas, `.trivyignore`/`trivy.yaml`, cwd/HOME isolation) relative to allowlist governance.
