## Step 1.5: rule-overlap walk of the new tests

- **C2 `"Not yet. Done."` -> `"Done"`.** No downgrade alternative matches. The only claim match is `Done` at index 9. Its clause starts after `. `, so it holds only a space and contains no negation. The next boundary char after the match is `.`, not `?`. Result: `"Done"`. A GREEN that checks negation over the whole prefix would find `Not` and return `None`, so the test discriminates. The existing C2 cases still give `None`, because `not` and `will` are in the same clause as the claim.
- **C8 case-sensitive false cases.** Every red pattern was walked case-sensitively:
  - `"3 FAIL"`: `fail` is lowercase in the pattern, so no match.
  - `"failed to fetch"`: `^P\s*FAILED\b` is uppercase, and no other pattern matches.
  - `"EXIT CODE 1"`: `[Ee]xit` does not match.
  - `"Conclusion: Failure"`: both conclusion forms are lowercase.
  - Result: all four are `False`. An IGNORECASE GREEN makes each of them `True`, so each one discriminates. The seven true cases and the three earlier false cases still hold.
- **C9 `"(fail) x"` -> `"x"`.** P matches empty. The lazy group grows to `x`, the optional suffix is absent, and `\s*$` matches. The plain and gh-prefix forms give `a > b` and `x`. In the gh form, P takes two tab groups plus `2026-...Z `.
- **C17 missing `--transcript` -> rc 2, empty stdout, non-empty stderr.** This matches spec 112. Under RED, `-m` on a missing module gives rc 1, so the test fails at assert time.
- **L13 missing log dir and sanitized sid.**
  - Payload: sid `a/b..c` sanitizes to `abc`. Three identical `{"command":"ls"}` calls give a repeat alert at n=3.
  - Journal: the parent dir is created, there is one row, and `session_id == "abc"`.
  - First L13 test: the `blocker/sub` mkdir fails, which is a journal failure, and the alert is still returned. This is consistent with spec 160.
- **L10 save_state tmp cleanup.**
  - Setup: the target `s.json` is a directory. Its parent exists, so mkdir is a no-op. The tmp file `s.json.<pid>.tmp` is written in the same dir.
  - Failure: `os.replace` of a file onto a directory raises `IsADirectoryError`, which is an `OSError` (rename(2) EISDIR, on Linux and macOS alike).
  - Result: the tmp file is removed and the error re-raised, so only `s.json` is left. This matches spec 131-133.
  - Round-trip control: the 3-repeat state is `{live: {rep:..: 3}, last_alert_n: 3}`, with `f` a bool and ints that are not bools. It passes the shape check and round-trips equal.
- **L4 thrash span boundary.** The sequence is 3 failed Bash, 9 Glob, then 2 Bash, 14 calls in total.
  - At n=14 the last 8 entries hold 2 Bash calls, below the call threshold, so there is no thrash.
  - Glob calls never fail, inputs are all distinct (so no repeat), and there is no x-y-x-y pattern. Result: no alerts.
  - The window-wide alternative sees 5 Bash calls with 3 fails at n=14 and alerts, so the test discriminates.
- **L6 mixed-episode refresh.** Five identical failed Bash calls.
  - n=3: repeat alert, live is `{rep:3}`.
  - n=4: `rep` refreshed to 4. AAAA is not an oscillation, and 4 calls is not thrash.
  - n=5: hits are `rep` and `thr:Bash` (5 calls, 5 fails). `rep` is live, so every hit key is refreshed to 5 and there is no alert.
  - Asserts: alerts `[3]` and `live["thr:Bash"] == 5`. Both hold under spec 146.
