## Probe results (orchestrator list)

1. **Green clobbers red.** The only `receipt_rung` reader in the engine is `_invoke_validation_llm` (phase_5_implement L6907). With default config it always runs the producer before reading, so a re-entered pre-GREEN gate rewrites red. `produce:false` applies to both gates through the same `preflight_rung` key, so the config stays consistent. `phase_6_fix_integrity` reads no receipt. No breakage found. One residual: a receipt written by a human `preflight --spec` CLI run is replaced silently. s2 already does this. Adversarial edge 3.
2. **Header parsing.** Renames: the `b/` side is the new path. OK. Deleted: the `b/` path does not exist and drops out. OK. Binary: has a header, and is non-`.py` so stub skips it. OK. Quoted paths (`core.quotePath`, non-ASCII, tab, `"`, `\`): `"b/\303\244.py"` does not resolve, drops silently, and can leave a partial scope that reads `fresh`. Spaces: `a/x y b/x y` is ambiguous under naive `" b/"` splitting. Finding 1.
3. **Subdirectory `git_cwd`.** Headers are toplevel-relative. "Existing file under the tree" against `git_cwd` drops everything. Root-relative paths handed to `run_engine_preflight(tree=subdir, …)` resolve against `cwd_abs` (L842) and fail. Result: the rung is permanently `missing` for that config. Finding 1.
4. **Once per step.** The block is placed before `reroll_until_verdict`, and AC13 pins it. Resume replays the cached step; no AC, but the precedent accepts that. OK.
5. **Add-only.** AC9 compares all kwargs minus `extra_data["preflight"]`, normalised for tmp paths. The prompt and `stable_prefix` cannot change unless `prev.data` is mutated. `test_gh705_callsite_stable_prefix.py` AC2i text-scans `stable_prefix=prev.data.get("stable_prefix"` in the body. That text must stay verbatim, and it does if the block only adds. OK.
6. **Inventory.** class-I keys are `file::function::kind#N`. A `read_text` of the diff in a named helper needs `workflows/phase_5_integrity.py::<helper>::read_text#0` (`not-prompt`). §4 covers this. tree_scan_lint kinds (`git-status`, `git-ls-files`, `git-add`, `git-diff-names`, walk/glob) are not touched by parsing a diff file. A `git rev-parse --show-toplevel` added for finding 1 is not a tree-scan kind, but if it goes through `git_port.git_read` it needs a class-I `git_read` row. §4 already names this.
7. **RED vacuity.** None found (Step 3).
8. **0-LLM / no test run.** The engine steps are `syntax`, `stub` and `facts`. `facts_pack` imports no subprocess or LLM module. `stub_passability` is pure AST. `step_syntax` spawns only `bash -n` and `bun build --no-bundle`. `_run_tests` (pytest / bun test) is reached only from `scoped`/`siblings`, which are not in `_ENGINE_STEPS`. AC5 guards this. OK.

## Adversarial edges (not covered by §3)

1. **Subdirectory `git_cwd`** (decoy root). The diff is built from `cwd=git_cwd`, and headers are toplevel-relative. No AC pins the root against which "existing file under the tree" is checked, or the form passed to the producer. Outcome: permanent `missing`. With mixed roots, a partial scope is possible.
2. **Quoted or space-containing header paths** (regression shield for false `fresh`). For example, `tests/test_ä.py` mocks its UUT and `tests/test_calc.py` is clean. The quoted header drops out silently, the scope is `[tests/test_calc.py]`, and the result is `fresh`. This contradicts "Limit stated".
3. **Human CLI receipt replaced.** A `bytedigger-engine preflight --spec … --phase red` receipt in the same worktree is deleted by the integrity producer.
4. **Non-test files matching `*spec*` or `*test*`** (`inspect_utils.py`, `spec_cite.py`, deliberately broken fixtures such as `tests/fixtures/bad_syntax.py`) enter `red_tests`. They get stub-linted as tests or syntax-checked, which can give a false `red` in the shadow table.
5. **Symlinked or `..`-escaping header path, or engine-owned path.** The producer keeps an outside-tree path as absolute (L847-848). "Under the tree" needs a realpath check. `red_tests` does not pass through `drop_engine_owned`.
6. **`diff_command` override with `--no-prefix` or `--relative`.** There are no `b/` prefixes, or the paths are relative to the subdirectory. The parse result is unspecified.

## Findings

VERDICT: REJECTED

1. **MAJOR: the diff-header → producer-path contract is unspecified, which allows a false `fresh` and a silent permanent `missing`.** op2 says "`b/<path>` side of every `diff --git` header … existing file under the tree", but:
   - (a) The root is not named. Headers are toplevel-relative. `tree` is `git_cwd`, which may be a subdirectory (s1 AC17 / s2 finding 3 precedent). `run_engine_preflight` resolves relative entries against its `top` argument (L842).
   - (b) There is no rule for C-quoted headers (`core.quotePath`) or for paths that contain spaces. A silent drop of an unparsed mocking test file next to a clean one gives `fresh`, which breaks the spec's own "Limit stated".

   Required:
   - State that the helper resolves `git rev-parse --show-toplevel` of `tree` and passes **absolute** paths (or toplevel-relative paths with `top=toplevel`).
   - State the parse rule: C-unquote quoted paths, or take `+++ b/` / `rename to` lines. A header the helper cannot parse makes the whole scope empty (producer fails, rung `missing`); it is never silently dropped while other paths stay.
   - State the realpath "under toplevel" check.
   - Add RED tests: (i) subdirectory `git_cwd` with a mocking test file → event `red`, `red_step=="stub"`; (ii) a diff with a quoted-path header for a mocking file plus a clean file → status never `fresh`.
