## 4-step audit

### Step 1: spec-internal consistency
These tokens are consistent across §3–§7 and the ACs: `HAL_RUN_LOG_ROOT`, `run_log_root`, `run_scoped_log_path`, `event log disabled:`, `_log_implicit`, `events_log_path`, `phase_sentinel_resumed`, `E_ORACLE_INDETERMINATE`. §3's "raises anything (see §5)" matches §5. AC5c's wording ("only hal_root/path") is looser than the test's six-method minimal provider, but both lack `event_log_path_override` and `run_log_root`, which is what matters. No drift.

### Step 1.5: rule-overlap simulation
- **Resolution, a → b → c → degrade.** `--event-log ""` is falsy, so it goes to b/c (declared in §4; untested, A4). A relative or empty (b) also degrades or falls through: a relative value raises `ValueError` and degrades (AC5c), an empty one falls to (c). A bad id with (b) set means (b) wins and validation is skipped. That is correct.
- **Freeze branch in `_oracle_after_execute`, with `_log_implicit` added:**
  - not an oracle workflow → None
  - no log → None
  - status not ok → None
  - resume → None
  - **implicit and no scratchpad → None (new)**
  - explicit and no scratchpad → INDETERMINATE
  - first freeze → FROZEN
  - re-entry → AMENDED, or `E_ORACLE_AMENDMENT_UNREASONED`
- The new branch must come before the `if not scratchpad: raise` at L190. Whether it sits before or after the resume check makes no observable difference.
- **One new reachable outcome for logless callers:** re-entering an oracle phase with an implicit log and the same `--run-id` and changed ctx (so the sentinel misses) now reaches the amendment rule (`oracle.py:308-314`). That is consistent with "same run" semantics but not declared (A1). No measured in-tree caller is affected. `build-cli.ts:40` passes no `--run-id`, so it gets a random id and a fresh directory, and the HAL and dogfood drivers pass `--event-log`.

### Step 2: §2-vs-§3 cross-check
- §3 degrade ↔ AC5 and AC5c. §3 injection (truthy-only, absolute) ↔ AC6, including the falsy parametrisation. §4 sentinel ↔ AC9a. §4 freeze skip ↔ AC9b/AC9c. §7 ↔ AC8. §1 catalog ↔ AC10.
- §4 declares positive behaviour with no AC: "`phase_45_spec` → `phase_5_implement` with the same `--run-id` works with no flags". This needs an implicit freeze when a scratchpad is present, then an entry verify that finds it. A GREEN that skips every implicit freeze passes all 44 tests and silently drops this claim. That is not worse than today, so it is not blocking (A3).
- Governor and `--restart-reason` consumers are declared but not pinned. Their behaviour is the existing explicit-log behaviour, unchanged, so this is acceptable.

## Findings

**MINOR (advisory)**
1. **A1:** Declare in §4 and the CHANGELOG that re-entering an oracle phase with an implicit log and the same `--run-id` follows the amendment rule (`E_ORACLE_AMENDMENT_UNREASONED` without `org_config["oracle_amendment_reason"]`), exactly as with an explicit log.
2. **A2:** §4 says `[bd8:6b]` "is kept", but only its no-scratchpad half is. With a scratchpad, an implicit-log oracle phase now emits `oracle_frozen`, which contradicts `conformance/ORACLE_SPEC.md` L243-249, L493-495 and G11 L567-568 ("a logless oracle phase … emits no `oracle_frozen`"). The `test_bd8_l1_oracle.py:825-831` docstring has the same contradiction. Amend that text in the GREEN commit. The test assertions (rc 0, no code) still hold.
3. **A3:** Add AC9d. Run the oracle stub with an implicit log and a `scratchpad_dir`, then assert `oracle_frozen` is present in `<root>/R9/events.jsonl` (and optionally that an implementing stub with the same id passes the entry verify). This pins the §4 positive claim.
4. **A4:** Add a one-line test that `--event-log ""` resolves via (c).
5. **A5:** Name the `_log_implicit` carrier precisely (for example, an attribute on `args`) so GREEN and the docstrings agree. Only the freeze branch may read it.
6. **A6:** Implement the per-test root fixture as its own autouse fixture, not as a new entry in `_STATE_LOG_ENV_SEAMS`. The GH1113 "exact-5" invariant guards that dict (`conftest.py:233-234` precedent).
7. **A7:** AC8 distinctness is vacuous across xdist workers. Optionally derive distinctness from `request.node` names instead of a module global.
8. **A8:** The orchestrator should confirm the failure line of `test_ac5c_minimal_provider_no_event_log_still_runs_ok` on main is the file assertion. After GREEN, run `test_bd8_l1_oracle.py`, `test_gh603_governor_auto_resume.py`, `test_39AF5B04_dbos_teardown_on_exit.py` and the full `engine_py` suite as the regression shield. Those run `run.main()` without `--event-log` and are now on the implicit-log path.
9. **A9:** The entry-verify suffix `" (no --event-log was given)"` (`run.py:150`) becomes dead for implicit logs. This is cosmetic. Optionally key it on `_log_implicit` or drop it.
10. **A10:** Declare in the CHANGELOG that a custom non-file EventSink factory still gets a filesystem directory under the root for governor and sentinel state.

The bd#150 claim (mkdir only, no new inventory key) still holds for r2. Re-check after the rebase onto #201.
