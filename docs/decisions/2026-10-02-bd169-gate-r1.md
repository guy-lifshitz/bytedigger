## Step 1.5: regex simulation
- Negation `\b(?:do\s+not|don't|must\s+not|never|no(?=\s))\b`. `no(?=\s)\b` works: the lookahead needs whitespace, so `\b` between `o` and whitespace always holds. The trailing `\b` is redundant for `no` but harmless. `\bdon't\b` works: the leading `\b` comes before `d`, the trailing one after `t` when followed by a space or punctuation. "do nothing" fails (`not` is followed by `h`). Whenever, casino, piano, nevertheless all fail. "no-op" and "no." still fail, so keeping `(?=\s)` is correct. Judgement on the deviation: **accept**. `\bno\b` would newly prohibit "no-op edit" and "no." text, which would be a regression. The issue's AC2 examples hold either way.
- Verb regex: Python alternation backtracks, so `changes` matches through `es` after `e` fails `\b`, and `modifying` matches through `ying`. Whole-word controls hold: `editor`, `changelog`, `address`, `writer`, `additional` and `rewrite` do not match.
- gh1600 corpus, checked line by line: `_TD_*` constants, L518, L661, L691, L720, L756 ("Never mind about `lib/a.py` for now, but ...": `now,` does not match `no(?=\s)`, and the Never window has no verb in either the old or new form). **No gh1600 test flips.**

## Adversarial edges (not covered by any AC)
- **Descriptive negation in bug-report prose, widened by the inflections.** Examples: "`parse()` never writes the header in `src/p.py`; fix it", "the cache is never written to `src/cache.py`", "`total` is never updated/modified in `src/calc.py`", "no tests were added for `src/x.py`". Today, base-forms-only means none of these prohibit. After r2 all of them prohibit the very file the task asks to fix. The spec MODIFYs it, SHIP becomes REVISE on every retry, and the build ends in E_REVIEW_FAILED. That is the bug class bd#169 is meant to fix, and r2 introduces it on a larger and more common input class: bug tasks are written in passive or past tense.
- Inflected verb in a following clause of the same negation window: "No flag exists today, so `src/f.py` needs it added" now prohibits `src/f.py`.

## Findings
1. **MAJOR: the verb widening is broader than the issue needs and adds false positives.** §2 says "this widens nothing without a negation". That is true but beside the point: bug descriptions routinely contain a negation together with a past-tense, participle or 3rd-person verb about the target file. The issue needs only nominal forms ("no changes / edits / modifications to"). Required change, either (a) or (b):
   - (a) Limit the widening to `changes|edits|modifications?|additions?|touches|writes|appends` style plurals/nouns. Drop `-ed`, `-ing`, `written`, `wrote` and `-ies/-ied`. Remove "never touched" from AC3b.
   - (b) Keep the full inflections, but justify the trade-off explicitly in §2.

   Either way, add a pinned AC with a descriptive-negation bug sentence → `{}` (at least "is never written to `src/x.py`" and "was never modified in `src/x.py`"). Under (a), document "never writes" (3rd-person `-s`) as residual risk. Not pinning this lets GREEN ship the regression unobserved.
2. **MINOR: the AC4 LLM fence is vacuous.** `monkeypatch.setattr(llm_subprocess, "invoke_llm_subprocess", ...)` does not intercept `phase_45_spec.invoke_llm_subprocess`, because it is imported by name at `:82`. Patch `phase_45_spec.invoke_llm_subprocess` as well (or instead), and correct the AC4 wording. The `status == "ok"` assertion is still real.
3. **MINOR:** the trailing `\b` after `no(?=\s)` is redundant. Add a one-line comment so a later reader does not "simplify" it to `\bno\b`.
4. **MINOR:** AC3 and AC3b both contain "no changes to `src/z.py`". This is harmless duplication.
