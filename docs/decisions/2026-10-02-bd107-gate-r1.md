## Step 1.5: rule-overlap simulation

The `_resolve_effort` classifier is simulated in order: path/read → decode/JSON → top-level type → `claude` type → `effort` type → container types → family → consulted entry.

- AC1 a-c: the read/parse branches → `unreadable`. The directory case raises `IsADirectoryError`, an OSError other than FileNotFoundError. Invalid UTF-8 raises `UnicodeDecodeError` (a ValueError) → `unreadable` as specified. Correct.
- AC1 d-g: the first type-check branch that matches → `malformed`. Correct.
- AC1 h, i: family `opus` resolves and the consulted entry is `7` / `""` → `malformed`. Correct.
- AC2: `by_model` is non-empty and the stub family is None → `family_unresolved`. That is the first match, before the entry check. Correct as specified, but see F1.
- AC4: worker with family None → silent. `effort=None` is passed (`takes_effort`, `:1466-1467`). Correct.
- AC5: each of the five shapes reaches a "not configured" branch first. Correct.
- **Overlap not settled (F3).** Container checks are unconditional (spec:43-44), but "entries that are not consulted are not judged" (spec:45-46) applies only to entries. Two cases follow:
  - `{"by_phase": "x", "by_model": {"opus": "high"}}` refuses a gate whose pin is valid, although gates ignore `by_phase` (GH439).
  - For a worker, `{"by_phase": {"bd107": "low"}, "by_model": "x"}` discards a valid `by_phase` value.

  The first matching branch decides the outcome, so this is defined behavior. But the spec does not say it is intended, and no AC covers it.

## Adversarial edges

Only edges not covered by AC1-AC8:

1. **Non-Claude provider whose family resolves to a key that is not in `by_model`.** Example: a `gpt` family under `{"opus": "high"}` → no pin, dispatched. Nothing shields this case, and it shows the asymmetry with F1: family `"gpt"` is dispatched while family None is refused.
2. **Ignored container malformed next to a valid pin** (F3): `by_phase: "x"` with a valid `by_model` pin on a gate; `by_model: "x"` with a valid `by_phase` entry on a worker.
3. **Worker on configs h/i** (F4). §2.1 makes `by_model[family] = 7` malformed for a worker that has no `by_phase` entry. Untested.
4. **Write race / half-written file.** A transient unreadable read makes the gate refuse with `recoverable=False`. §1 names this very scenario. The spec does not say whether the refusal should be retryable.
5. **NotADirectoryError** (a path component is a file). It falls in the "other OSError → unreadable" branch, which is specified but untested. This is low risk because it shares the branch with case (b).
6. **GH1169 fallback re-entry** (`:1816`). A worker that falls back calls `_dispatch_backend` a second time and emits a second `effort_config_invalid` for one logical step. The spec does not say whether that is intended.
7. **Tier rebinding on the same corrupt file.** `_load_tier_model` (`:325-335`) stays fail-open. A corrupt config therefore also drops GH375 rebinding silently, and the worker's event names only effort.

## Findings

1. **MAJOR: `family_unresolved` refusal violates the provider-agnostic principle and contradicts the spec's own Principles paragraph.**
   - The branch can never fire on the claude provider: its argv always carries `--model`, and family None fails `_meets_gate_floor` (`llm_subprocess.py:3669-3672`) at `_assert_hard_gate_opus` (`:3796`) before the effort check.
   - It therefore fires only when the active provider's argv carries no `--model`, which `_extract_model` (`:3431-3438`) reports for any CLI that uses a different flag. That is in practice a non-Claude provider: the floor is skipped and its own `model_family` returns None.
   - Such a gate is refused because a `claude.`-namespaced pin exists, even one for an unrelated family (`{"haiku": "low"}`). Spec:49-51 justifies silence for workers with exactly this mixed-provider reasoning, and spec:83 promises "a non-Claude provider ... never refuses". AC2 (test:151-176) pins the violation.
   - Fix options, author's choice:
     - (a) `family_unresolved` becomes signal-only (event, gate dispatched at default effort) and AC2 asserts dispatch + event;
     - (b) drop it;
     - (c) apply `claude.effort` only when `get_provider().name == "claude"`. On the claude provider the branch is unreachable, so this leaves the refusal effectively dead and AC2 must change.

   Whichever is chosen, add an AC for adversarial edge 1.
2. **MAJOR: §5 scope omits `engine_py/ERROR_CODES.md`.** AC8 in the RED checks both catalogues (test:308). `test_bd8_l1_oracle.py:1315-1317` requires `engine_py/ERROR_CODES.md` to be byte-equal to `render_markdown()`. A §1v-conformant GREEN cannot regenerate it and fails AC8 plus a sibling. Add it to §5 as "regenerated" and say both files are regenerated from `render_markdown()`. bd82 set the precedent: `test_bd82_role_backend_effort.py:577`.
3. **MINOR: container-level malformed checks are unconditional** (spec:43-46). The result: a gate with a valid `by_model` pin is refused for a malformed `by_phase` it never reads, and a worker loses a valid `by_phase` value when `by_model` is malformed. State the intent explicitly ("any malformed container is a problem, consulted or not") or limit the check to containers that are consulted. Add an AC either way (edge 2).
4. **MINOR: AC3 covers worker configs a-g only.** §2.1 classifies h/i as `malformed` for a worker too, since the worker consults `by_model[family]` when it has no `by_phase` entry. Add h/i to `_WORKER_CASES`, or say why they are excluded.
5. **MINOR: AC8 `CODE not in dead` is vacuous** (test:312). `check()` harvests from `engine_py/`, including `tests/`, so the RED file's own literal satisfies it. Either harvest only `bytedigger_engine/`, or drop the leg and rely on AC1.
6. **MINOR: §2.3 obligations with no AC:**
   - one WARNING per `(problem, detail)` (the dedup set);
   - the refusal message naming the problem and the config path;
   - the tools-before-effort-config order (a hard gate that fails both should return `E_TOOL_RESTRICTION_UNSUPPORTED`).

   Add one assertion each, or downgrade them to non-normative in the spec.
7. **MINOR: principle 3 (subscription + API) is exercised by shape only.** In AC7, "subscription" and "api" have identical capability sets and differ only in `manifest_source` (test:273-277). The real `claude-in-session` / `agent-sdk` / `anthropic-api` registrations are never reached. This is acceptable, because the refusal precedes any backend call and a real backend on the RED base would spawn a CLI or block on the file protocol. Record the rationale in the spec rather than calling it a subscription-vs-API test.
8. **MINOR (advisory): `recoverable=False` on a transient unreadable config** (edge 4). The spec should say whether a half-written models file is meant to be terminal for the gate.
