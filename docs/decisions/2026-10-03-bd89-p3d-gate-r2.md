## Step 1.5: rule-overlap simulation

How `lint()` dispatches (§10):
- (a) The entry is not a dict, and its name is in `_EXTRA_ROLLOUT` or ends with `_ENFORCE`: report it.
- (b) `is_rollout` is true: check `owner` and `provenance`.
- (c) Anything else: skip.

`is_rollout` is true when the entry is a dict, its kind is `flag` or `gate`, and at least one of these holds:
- (i) the name ends with `_ENFORCE`;
- (ii) the description has `flip-by:`, `retire-by:` or `kill-by:`;
- (iii) the entry has an `owner` or `provenance` key;
- (iv) the name is in `_EXTRA_ROLLOUT`.

Results per AC:
- **AC3/AC5/AC13 (live).** The 19 entries go to (b) through (i), (ii) or (iv). The other 95 go to (c). After GREEN there are no violations, so exit 0.
- **AC6.** `HAL_OLD_ENFORCE` goes to (b) through (i). `HAL_OLD_RETIRE` goes to (b) through (ii). Both have both fields, so exit 0. Any date logic would see 2020-01-01 as expired, exit 1, and fail the test. AC6 therefore actively proves the lint does not duplicate `flip_horizon`.
- **AC7/AC8.** Every entry goes to (b) through (i), and the first missing or blank field fires. The control entry is clean.
- **AC9.** `None`, `[]` and `"oops"` go to (a) through the suffix. `HAL_SIBLING_AUDIT_GATE: None` goes to (a) through `_EXTRA_ROLLOUT`, which closes r1 edge 3. Non-str `owner` or `provenance` goes to (b). The control entry is clean.
- **AC10.** The `path` and `int` entries fail the kind check, go to (c), and exit 0. `HAL_ROLLOUT_NOSUFFIX` goes to (b) through (ii) for both `flip-by:` and `kill-by:`.
- **Branch with no AC: clause (iii).** No synthetic case puts an entry in the set only because it has an `owner` or `provenance` key. A GREEN that drops (iii) passes all 14 tests today. Clause (iii) is load-bearing for lifecycle. `flip_horizon`'s prescribed resolution is to flip and remove the token. When that happens to `HAL_SPEC_PREFLIGHT_BATCH` or `HAL_SPEC_DEFECT_REROUTE`, only (iii) keeps the entry in the set. Without (iii), the entry silently leaves owner/provenance enforcement and AC3's superset check goes red on main. See adversarial edge 1 and F2.

## Adversarial edges (not covered by §3)

1. **Clause (iii) regression shield: token removed after a flip.** Someone later resolves `HAL_SPEC_PREFLIGHT_BATCH` the way `flip_horizon` prescribes: flip it and remove the `flip-by:` token (and its ledger line). With clause (iii) missing from `is_rollout`, the entry leaves the rollout set. The lint goes silent on it, and AC3's `ROLLOUT_NAMES <= rollout` goes red on main with no clear pointer. Today nothing forces GREEN to implement (iii). Example: a synthetic `{"kind": "flag", "description": "no token", "owner": "x"}` with no provenance must be reported by name.
2. **Malformed field inside a dict entry.** Examples: a `description` that is `None` or an int, a missing `description` key, a non-str dict key (`5: {...}`), or an unhashable `kind`. A naive `"flip-by:" in entry["description"]` or `name.endswith(...)` raises. The script then exits 1 with a traceback, the same exit code as a real violation, so it fails closed but not cleanly. AC9 covers only non-dict entries and non-str owner/provenance. `flip_horizon` has the matching N2 test (`test_n2_non_string_description_ignored`); this lint has no equivalent.
3. **Placeholder provenance.** `"provenance": "TBD"` or `"introduced: ?"` on every live entry passes AC3, AC5, AC13 and the A1 diff (F1).
4. **Catalog that raises `SystemExit` (or other `BaseException`) at import.** `sys.exit(0)` in the catalog plus an `except Exception` loader would make the lint exit 0 with no `OK:` line. This is low probability, and AC11's `raise RuntimeError` does not reach it. The case is advisory.
5. **Dead-token scan sees untracked files.** AC1 walks every file under `engine_py/` and `scripts/` (skipping only `__pycache__`, `.git` and `node_modules`), not just tracked ones. A local `engine_py/.venv` or `build/` holding a pre-GREEN copy of `flags_catalog.py` makes AC1 red on a dev machine while CI is green. The spec says "tracked". This is advisory.

## Findings

1. **MAJOR F1: provenance content is untestable, so the rule can be met with a placeholder.** §10 (Data) and §8 define the provenance line format (`introduced: <issue/PR> - what it protected against - why it stays`, or `introduced: no provenance found in this repo`), derived from each entry's description. No AC checks it. Not the lint (§8/§10: "non-blank str"), not AC3/AC4 (presence only), and not A1 (line kinds only). This field is the reason r3/r4 exist (Guy's provenance rule before any removal). Without a deterministic check it is honour-system only. **Required fix (spec errata line plus RED edit, before GREEN):**
   - (a) The lint rule becomes: `provenance` is a str whose stripped value starts with `introduced:` and has non-blank text after it. Otherwise it is a violation by flag name. This is a durable rule that also binds future flags, and CONTRIBUTING states it. AC7 adds a synthetic `provenance: "TBD"` case that is reported by name. The AC7/AC8/AC9 helpers' `_PROV` already conforms.
   - (b) AC3, restricted to `ROLLOUT_NAMES` (migration content, so no lifecycle snapshot): extract reference tokens from the entry's own description at test time (for example `(?:bd|GH)?#?\d{3,}`-style issue refs and 8-hex agreement ids). Assert that the provenance contains at least one of them. If the description has none, assert that the provenance contains `no provenance found in this repo`. This is derived, not pinned: it survives renewals and new flags.
   - Mirror (a) in the AC3 loop over all live rollout entries so that the lint and the test agree. That avoids a lint-green / test-red split.
2. **MINOR F2: clause (iii) of `is_rollout` has no AC (edge 1).** Recommended: in AC10, add a synthetic kind-`flag` entry with no suffix and no dated token that carries only `owner`. It must be reported by name for the missing `provenance`. This shields the "flip removes the token" lifecycle path.
3. **MINOR F3: residual `flag_expiry_lint` drift.** Add one line to §10 that also supersedes §0, §5 and §6 file names and voids §7 A2. Alternatively, strike the old names. This needs no RED change.
4. **MINOR F4: the §10 expected-red summary is wrong.** Change it to "AC2 green; AC1, AC3-AC14 red (AC4 because the fields are new)". The RED and the measurement are already correct.
5. **MINOR F5: degrade coverage for malformed fields inside a dict (edge 2).** Recommended: add to AC9 a kind-`flag` entry with `description: None` and one with no `description` key, both without `_ENFORCE`, and assert only that there is no `Traceback` and the exit code is 0 or 1. Optionally state in §10 that a non-str description counts as having no dated token, matching `flip_horizon` N2.
