## Step 1.5 — rule-overlap simulation

Mode dispatch in `main()` checks `list_declarations`, then `write`, then the default `check`. `--check-release`
sits in the same mutually exclusive group, so only one mode flag can be set. GREEN has to put the
`check_release` branch before the default `cmd_check` fall-through, and has to reject `--tag` before dispatch
whenever `check_release` is false. Simulating each case:
- `--tag X` alone or with `--check`: the custom `parser.error` fires and exits 2 (AC8 covers this).
- `--check-release --write`: argparse prints "not allowed with" and exits 2 (AC8).
- `--check-release`: the tag floor runs, then the `--tag` check, then the problems are collected (AC3 and AC10).
No overlap.

Classifier for the tag floor: a tag either matches the strict regex or is ignored. A loose `re.match` without
`$` would accept `v9.0.0-rc1`, and AC5 catches that. Selecting the newest tag among matching tags is NOT
exercised by any AC (finding 1).

## Step 3 — RED adequacy (mutation per AC)

Everything goes through a subprocess, and the UUT is never imported or mocked. Failures happen at assert time:
the `tvp` registry parse at import time belongs to the sibling suite and is unaffected. Mutations killed:
- AC1: reverting the bump.
- AC2: failing when there are zero tags.
- AC3: dropping the tag floor, or using `<`.
- AC4: a lexical compare.
- AC5: `>=`, or a regex without `$` or without the filter.
- AC6: skipping `--tag`, or `lstrip('v')` without a malformed check.
- AC7: fail-open on non-zero git exit.
- AC8: `--check-release` outside the group, or a missing `--tag` rule.
- AC9: missing trigger, fetch-depth, step, or ref_name.
- AC10: early return.

Surviving plausible mutations:
- **S1 (MAJOR, finding 1):** newest-tag selection by git's default lexical listing order, e.g. `tags[-1]` or
  `sorted(tags)[-1]` followed by an integer compare. Every AC with an ahead tag has exactly one tag, so it
  survives. Example: tags `v0.9.0`, `v0.10.0` with C=`0.9.0`. The lexical last is `v0.9.0`, the run reports
  OK, and that is wrong.
- **S2 (MAJOR, finding 1):** a patch-insensitive compare (`[:2]`, or major.minor only). No AC has a tag that is
  ahead only by patch, and patch releases are the most common release. A guard that misses `v1.1.2` over
  `1.1.1` defeats the purpose of the lot.
- S3 (MINOR): catching only a non-zero exit and not `FileNotFoundError` when git is missing produces a
  Traceback. This is covered by finding 2.
- S4 (MINOR): CI always appends `--tag ${{ github.ref_name }}`, which gives `--tag main` or `--tag N/merge`.
  AC9 accepts this. It shows up on the first PR run, so it is advisory.

## Adversarial edges (not covered by §3)

1. **Multi-tag newest selection:** `v0.9.0` and `v0.10.0` with C=`0.9.0`. The expected line names `v0.10.0`
   (finding 1).
2. **Patch-only ahead:** `v0.2.1` with C=`0.2.0`, expected exit 1 (finding 1).
3. **git not on PATH:** `env PATH=""` with the absolute `sys.executable`, expected `git tags: unreadable` and no
   Traceback (finding 2).
4. **Canonical missing/unparseable under `--check-release`**, expected `engine_py/pyproject.toml: missing`,
   exit 1 (finding 2).
5. **Canonical not X.Y.Z** (e.g. `1.1`, `1.1.1rc1`): the integer-triple compare of C is undefined. The likely
   GREEN raises ValueError and prints a Traceback (finding 3).
6. **Hook-leaked git env:** `_git_env()` and `_run` do not scrub `GIT_DIR`, `GIT_WORK_TREE` or
   `GIT_INDEX_FILE`. If someone runs pytest from a git hook, the fixture `git add`/`commit`/`tag` would write
   into the *real* repo, and the UUT would read the real repo's tags. No hook runs pytest today (finding 4).
7. **Tags not reachable from HEAD:** `git tag -l` lists all tags. On a maintenance branch (1.1.x after v1.2.0),
   or when testing an old checkout after fetching newer tags, AC1 and CI go permanently red.
   `git tag --merged HEAD` would still catch the incident, because v1.1.0 is on main history. This is a
   design choice the spec should state (finding 5).
8. `v01.2.3`: it matches the regex and compares as (1,2,3). That is harmless, but `--tag v01.2.3` with C=1.2.3
   is reported as a mismatch. This is consistent, so no action is needed. Annotated and lightweight tags
   are listed identically by `git tag -l`, so no gap there.
9. Tag-push concurrency/heartbeat interplay: none. The group is `ci-refs/tags/vX` with cancel-in-progress
   true, and `ci_main_heartbeat.py` filters on `head_branch == main`, so tag runs are excluded. No edge.
10. Python 3.9: the RED uses nothing beyond 3.7. GREEN has to stay 3.9-safe: no `match`, no runtime `X | Y`
    outside annotations, no `str.removeprefix` reliance... (3.9 has it, fine). No issue forced by the tests.

## Findings

1. **MAJOR — the core compare is under-tested.** The newest-tag selection and patch-level compare survive
   (mutations S1 and S2). Fix: add multi-tag cases to AC4 or a new AC:
   - `v0.9.0` + `v0.10.0` with C=`0.9.0` → 1, naming `v0.10.0`.
   - `v0.2.1` with C=`0.2.0` → 1.
2. **MAJOR — §2 error branches without an AC (§2-vs-§3 mismatch).** Two branches are uncovered:
   - (a) git not runnable → `git tags: unreadable`. Fix: test with PATH stripped; no Traceback allowed.
   - (b) canonical unreadable under `--check-release` → `<path>: <reason>`, exit 1. Fix: add a test.
3. MINOR — spec ambiguity: the behaviour when C is not `X.Y.Z` is unspecified. Recommend
   `engine_py/pyproject.toml: <C>`, exit 1, mirroring `_resolve_flat_json`.
4. MINOR — hermeticity: scrub `GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE` and `GIT_COMMON_DIR` in
   `_git_env()`. Running the UUT with that env also needs a local env-passing runner, because `tvp._run`
   inherits `os.environ`. `GIT_CONFIG_GLOBAL` needs git ≥ 2.32. That is fine on ubuntu-latest and current
   macOS.
5. MINOR — state the all-tags vs `--merged HEAD` design choice in §2, along with its maintenance-branch
   consequence.
6. MINOR — move the spec to FROZEN, and name the CHANGELOG follow-up issue number in §4.
7. MINOR — CI: pass the ref through `env:` (`REF_NAME: ${{ github.ref_name }}`) and test
   `$GITHUB_REF == refs/tags/v*` in bash. Do not interpolate `${{ }}` directly into `run:`, because that is a
   script-injection vector. AC9 could also assert the conditional (S4).
