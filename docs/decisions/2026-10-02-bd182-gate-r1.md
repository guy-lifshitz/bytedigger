## The orchestrator's adversarial questions

### (1) Spellings the scanner misses

| Spelling | Caught? | Why | Realistic here? |
|---|---|---|---|
| `Path(...).joinpath("bytedigger_engine", "lib")` | yes | the string constants are inside the argument expression | - |
| f-string `f"{ROOT}/bytedigger_engine/lib"` | yes | the JoinedStr's constant part `"/bytedigger_engine/lib"` splits to that component | - |
| `PKG = "bytedigger_engine"; ROOT / PKG / "lib"` | yes | name is followed | - |
| `from sys import path [as p]; p.insert(...)` / `p[:0] = ...` | **NO** | `_is_sys_path` needs `Attribute(Name in aliases, "path")` | bd44 AC7 already records GREENs evading this way (test_bd44_package_namespace.py:241-258) |
| `site.addsitedir(str(LIB))` | **NO** | not a recognised mutation | same bd44 record. It is also in-process, and it processes `.pth` files |
| helper return: `def _lib(): return ROOT / "bytedigger_engine" / "lib"`, then `sys.path.insert(0, str(_lib()))` | **NO** | `_collect_bindings` ignores FunctionDef / Return. The Name `_lib` has no binding | **high**: test_doctor.py:119/143 and test_doctor_v2.py:38 already do `sys.path.insert(0, str(_engine_py_root()))` with a path-returning helper. A `_lib_dir()` next to it is one edit away |
| path built from function parameters / defaults (`def _ensure(p=LIB_DIR)`) | partly | defaults are not bound. A call-site argument is not bound to the parameter | medium |
| `Path(model_config.__file__).parent`, `bytedigger_engine.lib.__path__[0]` | **NO** | no string constant; the imported name is not bound | medium ("insert the dir of the module I just imported"). Caution: `Path(bytedigger_engine.__file__).parent.parent` is legitimate (it is `engine_py/`), so a naive rule would give false positives |
| `os.environ["PYTHONPATH"]` / `env=` for subprocesses | no | out of process | acceptable as out of scope: a child interpreter cannot pollute this process's sys.path. The spec should say so explicitly |
| sys.path code embedded in subprocess driver strings (test_gh1939_disk_truth_tmp_leak.py:36-37, which also points at a stale nonexistent `engine_py/lib`) | no | it is a string, not a call | acceptable (child process only) |

**Verdict on (1).** Three gaps must be in scope: `from sys import path`, `site.addsitedir` and following helper return values. All three are in-process, all are cheap (about 15 lines in total), two are already handled by the bd44 AC7 scanner in this tree, and the third is the most natural shape of the "in-body helper" that the spec's own Problem section names as the reason the static fence exists. The other gaps (`__file__` / `__path__` of an imported module, parameter flow, subprocess env) can be a MINOR follow-up if the spec lists them as known limitations instead of claiming "any spelling".

### (2) False positives that could block legitimate tests

- **Name following ignores scope.** Every binding of a name anywhere in the module is unioned. Common names (`p`, `path`, `root`, `d`, `engine_root`) used as a package-file path in one function, then as a legitimate insert target in another, would be flagged. There is no allowlist, so GREEN's only fix would be a rename. No current instance was observed: all 20 hits are true positives. MINOR.
- **The target-name walk is too wide.** `_names_in_target` walks Subscript and Attribute targets, so `d[key] = ROOT / "bytedigger_engine"` binds `key` and `d`, and `self.x = ...` binds `self`. MINOR.
- **The component match is too wide.** Any constant with a `bytedigger_engine` path component counts. That includes a tmp copy of the package (`tmp_path / "engine_py" / "bytedigger_engine" / ...`), which is a legitimate pattern in copy-the-engine tests such as bd66. None currently inserts such a path, but nothing allows it later. MINOR.
- **Fixture `.py` data under `tests/` is scanned.** Data such as suite_safety or mutation-matrix corpora is scanned too, so a future fixture that embeds a real `sys.path.insert(..."bytedigger_engine/lib")` as *data inside a .py file* blocks. String literals in normal tests are safe: they are constants, not calls. MINOR.
- **Runtime fence and cwd.** `Path("" or ".").resolve()` is the cwd, so running pytest from inside `engine_py/bytedigger_engine/` fails the runtime fence spuriously. MINOR.

### (3) Is the cyclic-binding / name-following logic sound?

Yes for termination and for reachability.
- `seen` is shared across one `check`, and each name is expanded at most once. A name expanded while walking argument 0 has already contributed its strings, and those strings are tested in argument 0's list, so sharing `seen` loses nothing.
- Expansion is transitive through Assign, AnnAssign, AugAssign, For/AsyncFor iterables and walrus. That covers the module-constant and `for p in (...)` offenders.

Limits:
- Over-approximation: it ignores scope, and an assignment that happens later in the file still counts. That is the false-positive class in (2).
- Under-approximation: no FunctionDef/Return, Import or parameter bindings. That is the miss class in (1).
- Note: comprehension targets (`[x for x in ...]`) are also not bound. That gap is small.

### (4) The F3A8F4FC decision (drop the guard)

It preserves test intent.
- The guard `if "phase_1_discovery" in sys.modules: del sys.modules["bytedigger_engine.workflows.phase_1_discovery"]` has been dead since bd#44. The flat key is absent unless something leaks it. If something does leak it while the package key is absent, the guard raises `KeyError`, so it is a latent crash, not a protection.
- `_default_llm_command()` calls `_default_model()`, then `get_claude_discovery()` / `get_claude_explore()`, at call time (phase_1_discovery.py:82-88, phase_2_explore.py:86-92).
- Those functions read `model_config._CONFIG_PATH` and `_cache` through their own module globals. The test patches the same object (`from bytedigger_engine.lib import model_config`, line 41) and calls `reset_cache()`.
- So the asserted argv reflects the patched config with no re-import. Since bd#44 the test has never re-imported, so dropping the guard changes nothing observable and removes the KeyError trap. The source-text sub-checks are unaffected.
- One loose end: the trailing comment on the import lines (261 and 317, "drops the module from sys.modules to force a re-execute") must go with the guard, as the spec says.

### (5) Is the runtime fence meaningful?

Yes as defence in depth, but it is weaker than the spec implies.
- In a full serial run, every module-level insert has already run at collection, before any test runs. That covers 16 of the 20 offenders, so the entry check catches them whatever the file order.
- In-body inserts are caught only if their test runs before `test_bd182_*`: BC45C403, 090ED35B and EEFD480F (the `_ensure_lib_on_path` helpers), and gh891's function body. pytest collects case-sensitively, so uppercase-prefixed files sort first. `-p randomly`, xdist and `-k` subsets each reduce this further.
- `find_spec` checks `sys.modules` first, so a flat module cached by an earlier leak is still detected after the path entry is removed. That is good.
- In isolation, which is what the orchestrator ran, it is green by construction. The static fence carries the guarantee. That is correct design, but the Acceptance claim "runtime fence fails in a full-suite run" is unverified (finding 5).

## Adversarial edges (not covered by any spec AC)

1. **Empty-scope / vacuous pass.** The tree scan has no corpus-size floor. `rglob` returning nothing, or a mass `SyntaxError` skip, passes silently. The bd44 AC7 precedent asserts `>= 40` files.
2. **Unparseable files are skipped, not reported.** bd44 AC7 reports "unparseable — not scanned". Here a `SyntaxError` file is dropped with no trace.
3. **Helper-return decoy.** `sys.path.insert(0, str(_lib_dir()))` with a path-returning helper is not flagged (see the table). A sibling pattern already exists in test_doctor*.py.
4. **Bare-path and site decoys.** `from sys import path; path.insert(...)` and `site.addsitedir(...)` are not flagged.
5. **Module-attribute decoy.** `sys.path.insert(0, str(Path(model_config.__file__).parent))` is not flagged.
6. **Order-dependent runtime fence.** In-body leaks from files that sort after `test_bd182_*` are never seen by the runtime check.
7. **Scope-collision false positive.** The same short name is bound to a package path in one function and inserted as a legitimate root in another.
8. **Spurious runtime failure when the cwd is inside the package.** The `""` sys.path entry resolves to the cwd.

## VERDICT

VERDICT: REJECTED

(In the orchestrator's vocabulary this is REJECT, but a narrow one. The spec and RED are sound in structure. The 20 current offenders are correctly found. The fixes are small amendments to the spec and scanner, then a re-gate.)

### Findings

1. **MAJOR: the static fence can be bypassed by realistic in-process spellings.** It misses `from sys import path [as x]` (insert/append/extend/assign/augassign on the bare name), `site.addsitedir(...)`, and a package path reached through a helper's return value. The spec's Problem section justifies the static fence by in-body helpers, yet the most natural helper shape (return the path, insert it at the call site) is invisible to it. The bd44 AC7 scanner in the same tree already covers the first two, so this fence is weaker than existing in-repo practice.
2. **MAJOR (spec): scope claim vs coverage.** Change 1 says "any spelling" and Change 3 implements a closed list. Either widen Change 3 (finding 1) or write an explicit "known uncovered spellings" list: `__file__` / `__path__` of imported package modules, parameter flow, subprocess `PYTHONPATH` / driver-string code (out of process, so acceptable).
3. MINOR: name following ignores scope and walks Subscript/Attribute targets, which risks false positives with no allowlist escape. Consider scoping the bindings (module plus the enclosing function), or binding only Name / Tuple-of-Name targets.
4. MINOR: there is no corpus-size floor, and unparseable files are skipped silently. Add `assert scanned >= N` and report the skipped files, as bd44 AC7 does.
5. MINOR: the Acceptance clause "runtime fence fails in a full-suite run" on origin/main has not been demonstrated. Run the full suite on the pre-GREEN tree, or soften the clause to "the static fence is RED".
6. MINOR: self-test gaps. There are no snippets for an f-string target, `.joinpath`, a keyword argument, a walrus, or two hits in one file (line ordering).
7. MINOR (process, must be acknowledged): the worktree was being changed during this gate (see top). Re-confirm the spec and RED bytes, and do not attribute any dirt in bd182 to this gate.
