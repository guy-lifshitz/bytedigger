## Adversarial edges (not covered by the section 2 AC list)

1. **Hook budget overrun:** a fake that sleeps 20 s. Today the harness kills the gate at 15 s, losing both the scan verdict and the existing 5.5 soft verdict. Expected: unavailable within budget.
2. **Regression shield, soft and SHADOW together:** state without `test_integrity_check` plus a SHADOW rc 1 fake. Must still exit 2 with `test_integrity_check has no value`, plus the WARN and the event.
3. **Regression shield, ENFORCE plus soft:** missing deliverable plus an ENFORCE rc 1 fake. The hard block must win (exit 1).
4. **Stdout fence:** in SHADOW with rc 1 or rc 2, `GATE_OUT` must be byte-empty. This also keeps the dispatcher-shadow and bd136 parity checks unaffected.
5. **Production defaults:** `BD_GATE_TODAY` and `DEVOPS_SCAN_SCRIPT` both unset. Copy the gate into a tmp `scripts/` dir with a fake sibling `devops_scan.py`, as bd136 line 244 does. Expected: no "unbound variable", the sibling is invoked, and today comes from `date -u`.
6. **Decoy script:** `DEVOPS_SCAN_SCRIPT` pointing at a script that prints `{"status":"clean"}` with exit 0 while the real repo has findings. Shows the override env is a bypass of the security verdict in production (minor 5).
7. **rc/JSON disagreement:** rc 0 with stdout `{}` or `[]`, or with `status:"blocked"`. Fail-closed expectation: unavailable.
8. **rc 1 with `gating` not a list.**
9. **JSON-breaking finding id:** an id or reason containing `"` or `\` in ENFORCE. The hard_block stdout must stay valid JSON.
10. **Malformed `BD_GATE_TODAY`** (empty or `garbage`). Must not silently fall past expiry.
11. **Non-git CWD in production:** the real `devops_scan.py` returns G1 `git_ls_files_failed` (rc 2) on every 5.5 SubagentStop. Under ENFORCE that is a permanent hard block. CWD as a subdir of a repo silently narrows the scan.
12. **Concurrent SubagentStops** appending to the same jsonl. Single-line `>>` appends are atomic for short lines, but the spec should say so.
13. **Expiry boundary under TZ skew:** "today" is UTC, so a local-evening run on 2026-10-17 in UTC-x already counts as 10-18 in UTC. Advisory.

## Findings

### MAJOR

1. **Hook timeout vs scanner cost (fail-open plus regression).**
   - The cost: `hooks/hooks.json` gives `gate-dispatcher.sh` a 15 s timeout. The spec calls `devops_scan.py` with the default `--timeout` (60 s per scanner run, M1 F3). Runs are sequential: one hadolint per Dockerfile, one trivy per IaC dir. There is no caching, and the scan repeats on every SubagentStop while `current_phase` is 5.5. `trivy config` also fetches its checks bundle from the network on first use or when stale, which contradicts AC9's "no network call added" in effect if not in text. Under `shadow` backend the bash gate and the TS gate also run in series inside the same 15 s.
   - The consequence: when the harness kills the hook, (a) under ENFORCE the security verdict is lost, so the gate fails open; (b) under SHADOW the pre-existing 5.5 soft verdict (`check_deliverables`, emitted only after the scan returns) is lost too, a regression of an existing gate.
   - Required: section 1 must state an explicit wall-clock budget well under the hook timeout (pass `--timeout`, plus a total cap the gate enforces; macOS has no GNU `timeout`). An overrun maps to unavailable. Alternatively, raise the hook timeout, which the spec's out-of-scope list must then permit. Add an AC with a sleeping fake.

2. **TS gate and dispatcher backends not addressed.**
   - With `gate_backend=ts` (`GATE_BACKEND=ts` or config), the scan and the expiry forcing function never run: a silent bypass of ENFORCE once flipped.
   - Under `shadow` the bash and TS outputs diverge in every case where bash exits non-zero: ENFORCE blocks and post-expiry blocks. The mismatch logger then fires on each 5.5 stop.
   - `tests/test_bd136_gate_counter_table_parser.py` asserts bash/TS parity for 5.5 (`test_a5_parity_phases_that_drifted`, `test_guard_satisfied_state_passes`).
   - Required: the spec must choose one of two options. Either (a) port to `build-phase-gate.ts` with a parity AC, or (b) declare the TS backend explicitly out of scope with the accepted risk, plus an AC or guard showing that `ts` and `shadow` behave as declared (for example, the TS backend emits a loud WARN that the scan is not wired, or the dispatcher refuses `ts` once ENFORCE=1).

3. **Expiry hard-block: blast radius and CI time bomb.**
   - Blast radius: after 2026-10-17 every consumer of the plugin is hard-blocked at 5.5, unless it exports `DEVOPS_SCAN_ENFORCE=1` (an env var, not config). That includes repos with nothing to scan. The block cannot be bypassed: hard_block skips loop prevention.
   - Escape routes: the only ones are `gates_enabled:false` (disables all gates) or ENFORCE=1. ENFORCE=1 in turn hard-blocks permanently when hadolint or trivy are absent and a Dockerfile or IaC file is tracked, or when CWD is not a git repo (G1).
   - The MGR decision says "owner + expiry +14 days". It does not say "hard-block every consumer at expiry". That interpretation needs explicit MGR sign-off in the spec, or a narrower behavior (for example a loud WARN plus an event after expiry, or a block only when the scan would actually report blocked or unavailable).
   - CI time bomb: the existing suites that exercise 5.5 without pinning `BD_GATE_TODAY` start failing on 2026-10-18 by construction. Affected: `test_bd136_gate_counter_table_parser.py` 5.5 cells (bash side), and the bash/TS parity test.
   - From GREEN onward those suites also run the real `devops_scan.py`, non-hermetically. The copied-gate fixture at bd136 line 244 has no sibling script, so it takes the unavailable path.
   - AC9 lists `build-gate.bats` and `gate-dispatcher.bats`, which have only one 5.5 cell (a pre-scan hard block) and none, respectively. It omits bd136, the suite actually at risk.
   - Required: decide how those suites stay green (pin `BD_GATE_TODAY`, a fake script, or an explicit disable seam), and list bd136 in AC9.

4. **RED lacks regression shields; production defaults are untested.**
   - Missing cells:
     - (a) MISSING_FIELDS plus SHADOW finding: the gate must still exit 2 with the deliverable reason. Every RED state sets `test_integrity_check: pass`, so a GREEN that `exit 0`s after the SHADOW WARN passes all 26 cells while killing the 5.5 soft gate.
     - (b) SHADOW stdout must be empty for rc 1 and rc 2. No cell asserts `GATE_OUT` empty, so a scan-JSON leak to the hook's stdout (parsed by the harness on exit 0) passes.
     - (c) Production defaults: with `BD_GATE_TODAY` and `DEVOPS_SCAN_SCRIPT` unset, an unguarded reference under `set -u` crashes production and is invisible to this file.
   - Required: add these cells; edges 2 to 5 above give their shape.

### minor (advisory)

1. `hard_block` does not JSON-escape its argument (`block` does). The reason now carries scanner-derived ids and reasons. Require escaping, reusing the `block` sed, or sanitize ids.
2. `--root "$CWD"`: CWD is `dirname $BYTEDIGGER_CONFIG` or `pwd`. A non-git CWD gives permanent unavailable (G1). A subdir CWD silently narrows `git ls-files`. State the intended root semantics, or resolve it via `git -C "$CWD" rev-parse --show-toplevel` with a fallback.
3. Section 1 should name the `DEVOPS_SCAN_SCRIPT` override. It should also define the reason tokens for the unavailable cases the gate detects itself (for example `script_missing`, `python3_not_found`, `non_json_output`, `rc_<n>`) and the exact rc 2 WARN format.
4. Define the rc vs JSON precedence: rc is the verdict per M1; stdout must be an object whose `status` is in the allowed set, otherwise unavailable. Also define the hard-block text when `gating` is absent.
5. `DEVOPS_SCAN_SCRIPT` and `BD_GATE_TODAY` are honored unconditionally in production, so the security verdict producer and the expiry clock can be replaced from env. The dispatcher precedent uses a `_TEST_OVERRIDE` suffix; apply the same naming.
6. The event file lands in consumer repos (`$CWD/.bytedigger/`). Only bytedigger's own `.gitignore` covers it. It grows by one line per rc!=0 SubagentStop, which is every stop in a non-git or tool-less repo. Add a note, or a rotation and size cap. Also specify how the event is written when python3 is absent; AC5 python3-absent does not assert the event.
7. Explain the 5th `ok` in the RED run. If it is `ok # skip` from a python3-absent cell, that cell is vacuous on this host and must be fixed (MAJOR in r2).
8. `make_nopython_path` whitelists a fixed tool set (no `mktemp`, `awk`, `jq`, `python3`). GREEN must not depend on other tools in that path, or the cell fails for environmental reasons. Document the constraint in the spec.
9. Under ENFORCE, a full-tree scan (no `--files`) makes pre-existing repo findings block unrelated builds. Record this as an owner input for the flip decision.
10. Pre-existing and out of scope, but the "hard_block cannot be bypassed" rationale depends on it: in the Claude Code hook contract, a SubagentStop exit 1 is a non-blocking error (only exit 2, or exit 0 with decision JSON, blocks). The `exit 1 = pipeline stops` semantics rest on the orchestrator, not the harness. Worth an OFI.
