## Adversarial edges (not covered by §3)

- **E1 BaseException swallowed.** §2.2 says `except Exception` only, but no test raises `KeyboardInterrupt` from a hook. A GREEN
  written with `except BaseException` would pass every test and would turn Ctrl-C into a worker degrade.
- **E2 remap with no run context.** AC13 covers *unresolved* with no context. §2.3.6 does not say "only when `run_ctx` has an
  event log" for the remap event, and no test remaps with no context. A GREEN that dereferences `run_ctx.event_log` unguarded
  in the remap block would raise on a context-free worker dispatch (AC-P8: MUST NOT raise).
- **E3 event order not asserted.** AC12 (refused) asserts that the remap event is *present*, not that it precedes `hard_gate_refused`.
  The evidence value holds either way, so this is low-risk.
- **E4 case/alias-only remap** (`"opus"` → `"Opus"` or `"claude-opus-4-8"`): effective != model, so a remap event is written and the attestation
  records the verbatim string. This is consistent with "verbatim" in §2.2 and R3.3 family-compares. It is documented-by-implication, not tested.
- **E5 hook with side effects / non-determinism.** It is called once per dispatch (AC8), but the fallback re-dispatch to
  claude-subprocess drops it. This is consistent with the design, and nothing tests it (carried over from r1 E8).

## Findings

1. **MINOR (m1): the AC-M3 amendment covers only half of AC-M3.** AC-M3 has two normative sentences: `model_requested`
   is the post-rebind dispatched model (:643), and "the comparison target is likewise the **dispatched request model**"
   (:649). §2.3.5 amends only the first. After GREEN, `_pin_mismatch_refusal` compares against `effective`, so the
   :649 sentence also needs the same "as resolved by the backend's `effective_model` hook" qualifier. Otherwise the two
   halves of AC-M3 disagree for a remapping backend. :644 ("the same value the comparison uses") ties them, so the
   intent is recoverable. GREEN or the doc step should edit both sentences.
2. **MINOR (m2): the remap event's no-context guard is unstated** (E2). Add "via `_emit_safe`, only when `run_ctx` has an event log"
   to §2.3.6 to mirror §2.3.2. Ideally also extend AC13 with a worker remap and no context that must not raise.
3. **MINOR (m3): the `_dispatch_backend` docstring "THE ORDER OF OPERATIONS IS THE CONTRACT"** (:1409-1426) needs a new step 0
   (resolve the effective model; emit unresolved/remapped; these events are not attestations, so `[bd10:27]` still holds). GREEN
   should update it together with the `_attest_payload` docstring. It is in the §5 prod file already.
4. **MINOR (m4): E1 is untested.** A one-line `KeyboardInterrupt` hook test (`pytest.raises(KeyboardInterrupt)`) would pin the
   §2.2 statement. Advisory.

There are no MAJOR findings. The r1 MAJOR is resolved, the r2 additions introduce no contradiction with the `bd_l3`/R3.3 consumers, the remap
event ordering is consistent with the floor refusal, the AC8b fixture really activates tier rebind, and the AC14 stubs are boundary
recorders, not UUT mocks. RED is adequate and fails at assert time for the correct reasons.
