1. **[MAJOR] N1: the F2 closure is partial. The §2.2-7 post-self-heal re-read (`phase_6_fix_integrity.py:354`) has no failing assertion.**

2. **[MINOR] N2: the `content_scan` split is not uniform across read sets.**
   - preflight `_Run._changed` (L353-361) feeds `step_syntax`, which reads the files (L403-429). Spec §2.2-11 and RED L713-714 pin `content_scan=False` for it.
   - The walkers (§2.2-9/-10) prune by dirname only. `harvest_codes` reads file-symlink targets.
   - Fix (recommended in the same r3 delta):
     - give `_Run._changed` `content_scan=True` under its own step, e.g. `"preflight_changed"`;
     - keep `compute_state_hash` at False, since it is a fingerprint and must see user links;
     - in the RED, split the preflight AST pin per producer;
     - declare the walker choice in §2.2.

3. **[MINOR] N3: the §2.3 token definition contradicts AC7's `-C` case.**

   - Fix: define the tokens as all elements in order, with a non-literal element kept as a placeholder (it can satisfy an option value but is never a verb). The RED already pins the intended outcome.

4. **[MINOR] N4: the varargs rule over-matches.** About 30 `x.get("status"[, …])` calls in scope become `git-status` sites, and `guard_git(…, "add", False)` becomes a `git-add` site. GREEN can satisfy AC6 by inventorying them, but `not-a-gate` becomes reflexive noise. Fix: apply the varargs form only when the callee name contains `git` (as r1 F1(b) proposed), or when a leading string literal is `"git"`. AC7 `f_varargs` (`_git`) still passes.
