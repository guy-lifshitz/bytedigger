## Adversarial edges (not covered by the spec's AC table)

- **A. Step 3 block shape.** The phase6-satisfaction-steps block must be one contiguous span from the SIMPLE heading to COMPLEX item 1, but the COMPLEX item 1 has hand-typed sub-bullets "Evaluator A / B / C" (three named evaluators) and "each with different focus". If they sit inside the block, the generator hard-codes three evaluators and with `evaluators=5` renders "Launch 5 Opus agents" above three bullets; if outside, the bullets sit between block and items 2-6. AC4 only checks the `Launch 5 Opus agents in parallel` string, so neither is caught.
- **B. `--check` / `--write` when `load_claims` raises** (e.g. `bytedigger.json` malformed, policy made non-literal). Spec leaves the CLI exit code open; a GREEN that catches `PhaseClaimsError` and returns 0 would pass every RED test (AC8 tests only the function).
- **C. `--write` on a doc with unbalanced markers** must refuse, not rewrite a partial span (data loss on prose between a stray BEGIN and the next END).
- **D. Marker text in a code fence or inline backticks in prose** (phase-6 documents code fences heavily). `_GEN` in the RED guard is a lazy non-id-matched regex: a stray BEGIN of one id paired with an END of another blanks arbitrary prose and hides claims from the guard; the generator's regex may differ from the guard's.
- **E. Claim-shaped prose with no digits**: "one composite reviewer" (phase-6 l.17, l.161), the word "Opus", "majority vote", "2/3" spelled out. Not machine-checked (spec lists only the model-name limitation, not the reviewer count).
- **F. Threshold off-by-one / typing**: `satisfaction_thresholds` value 0 or 101 or negative is an int and passes AC8; the render would print `>=101%`. Out of range not rejected.
- **G. Extra tier key** in `satisfaction_thresholds` or policy (e.g. "TRIVIAL"): AC8 covers missing tiers, not extras, which would silently never be rendered.
- **H. Policy literal duplicated** (two `SATISFACTION_TIER_POLICY =` assignments, or one inside `if TYPE_CHECKING`/function): which one `load_claims` reads is unspecified (first? last? top-level only?).
- **I. Block-level interaction with bd#89 pins**: a rendered line such as "3 agents" or "3x reviewers" would trip bd89 AC3; the generator's text must avoid them (only matters if wording changes).

## Findings

1. **MAJOR: AC6 false-positives on prose the spec leaves in place.** `\b\d+ (composite |parallel )?(reviewers?|...)\b` matches "Phase 6 reviewers" at phase-6 l.52, l.149, l.180. Spec section 2.C does not list them, and the RED regexes are fixed, so `test_ac6_no_typed_claims_outside_generated_blocks` stays RED after a spec-literal GREEN. Must-fix: either (a) add to spec C "reword `Phase 6 reviewers` to `the reviewers in this phase` at l.52, l.149, l.180" (preferred, RED untouched), or (b) change the pattern to `(?<!Phase )\b\d+ ...` in both spec AC6 and the RED. State explicitly which.
2. **MAJOR: Step 3 block boundary / evaluator bullets unspecified (Edge A).** Spec must say where the block ends and what happens to the hand-typed "Evaluator A/B/C" bullets: either generate them from `evaluators` or move them out of the block and state it, and add an assertion (e.g. in AC4: with evaluators=5 the doc does not still list exactly three named evaluators in the block). Otherwise the generated doc can say 5 while listing 3, which is the bug class being closed.
3. **MINOR: AC9 reads at call time.** Spec section 2.A should say the call site reads the module global at call time (a default arg `n=SATISFACTION_TIER_POLICY[...]` evaluated at def time would defeat the monkeypatch).
4. **MINOR: CLI exit on `PhaseClaimsError` (Edge B).** Specify non-zero exit with message and add one RED row (malformed `bytedigger.json` copy -> `--check` returncode != 0, `--write` leaves docs untouched).
5. **MINOR (advisory, OFI): doc vs enforcement.** The engine enforces `cfg["satisfaction_threshold"] or 80` flat (l.3147/3665/3984); `bytedigger.json` `satisfaction_thresholds` is consumed by no code, so the rendered 85/90 are a documented intent the engine does not apply. The owner's reference case (md = json -> pass) is met, but the "source of truth in code/config" is a config nobody reads. Also only `COMPLEX.evaluators` is bound to behaviour; `reviewers`, SIMPLE/FEATURE `evaluators` and `dimensions` are a second hand-typed copy (the Known limitations mention dimensions only). Add them to Known limitations and file an OFI to wire the threshold into the engine.
6. **MINOR: spec says "stdout"** for the names in AC3/AC4/AC7 (RED asserts stdout).
7. **MINOR: edges C, D, F, G, H** (refuse `--write` on unbalanced markers; fence/backtick markers; threshold range; extra tiers; duplicate policy assignment) are unspecified; at least C and H should get one line in the spec.
8. **MINOR: weak adv assertion** `test_adv_nested_begin_fails_check` (`"phase6-" in stdout`); assert the id of the nested block.
9. **INFO:** CHANGELOG (D) has no test; AC10 pin is green today and unaffected provided the two literals live in the generated block (confirmed against bd89 AC1/AC3/AC11).

Findings 1 and 2 block. GREEN may not proceed until the spec is amended (frozen-spec errata round) and, if option (b) of finding 1 is chosen, the RED regex is updated.
