## Adversarial edges (not covered by §3)

1. **`fix_commit_sha` != HEAD.** The diff is `pre_fix..fix_commit_sha`, which can come from cfg or `scratchpad/integrity/fix-commit-sha.txt`. The producer and rung judge the working tree at HEAD, so `_green_test_paths` checks existence on the HEAD tree, not on the commit the diff came from. If the engine's HEAD moved after the fix commit, or cfg pins an older SHA, the receipt describes a different tree than the diff the gate reviews. §2 "freshness is judged on the post-fix HEAD the gate saw" overstates this. The gate sees a diff between two SHAs, not HEAD.
2. **`cfg["cycle"]` != 1 while `prev.data` carries a different or absent `cycle`.** This is the discriminating input for the s5→s6 cycle-source change. No AC (finding 1).
3. **`{"mode":"off","produce":"no"}`.** `off` wins, so there is no event and no `config-error`. This is consistent with the spec but unpinned (same as s5).
4. **Clobbering a `phase: red` receipt.** `run_engine_preflight` deletes the single `receipt.json` whatever its phase. A fix-side run before a later-cycle phase-5 validation rung (`receipt_rung("red")`) leaves that rung `missing`. s5 already does this, and it is shadow-only. §2 mentions only the green-on-green overwrite.
5. **`prev.data["git_cwd"]` set while `cfg["git_cwd"]` is unset.** Step 1 (L400) resolves `resolve_git_cwd_with_source(cfg)` without `prev.data`, but the rung uses `(cfg, prev.data)`. The diff tree and the receipt tree could then differ. This is unreachable today, because step 1's data never carries `git_cwd`, but nothing pins it.
6. **Event-before-LLM ordering.** Not asserted. The fake LLM could record `len(events)` at call time.

## Findings

1. **MAJOR:** The fix-side `cycle` source has no AC and no test. §2 L23 sets the event's `"cycle": cfg.get("cycle", 1)`, a deliberate change from s5's `prev.data.get("cycle", 1)`. Phase 6 step 1 never puts `cycle` into `prev.data` (L436-451, L511-527, L565-582), so a verbatim s5 copy would report `cycle: 1` on every fix cycle. All 16 tests pass on that wrong GREEN, because `_ctx` sets no `cycle` and no test reads `ev["cycle"]`.
   - **Spec:** add an AC, e.g. "AC14: `org_config["cycle"] = 3` and `prev.data["cycle"] = 7` → event `cycle == 3`. No `cycle` in cfg → `cycle == 1`."
   - **RED:** add a test driving `_drive(..., git_cwd=..., cycle=3, prev_extra={"cycle": 7})` that asserts `ev["cycle"] == 3`. Also assert `ev["cycle"] == 1` in AC1's default run.
2. **MAJOR:** AC4 (add-only) is relative only and cannot detect a uniform change to the gate call. `norm(on)==norm(off)==norm(red)` compares three post-GREEN calls with each other. It misses a GREEN that copies s5's `_attempt` (adding `stable_prefix=...`) or changes `model` / `timeout_sec` / `allowed_tools` / `injections` / `step_name` the same way in every mode. The s1 precedent (`2026-10-03-bd218-s1-preflight-rung.md` AC5) asserted against an explicit expected dict for this reason.
   - **Spec:** AC4 must also state the absolute baseline. The kwargs key set must be exactly `{prompt, model, timeout_sec, step_name, extra_data, hard_gate, gate_label, allowed_tools, injections}`. `extra_data` minus `preflight` must be exactly `{doc_path, diff_path}`. `step_name == "invoke_fix_integrity_llm"` and `allowed_tools == ["Read"]`.
   - **RED:** add these absolute assertions to `test_AC4_gate_kwargs_equal_across_modes_and_receipts`. Include a `{"mode":"off"}` call in the equality chain, since it is the closest thing to today's call.
3. **MINOR:** §4 says "two imports", but GREEN also needs `is_ambient_git_cwd`. Change it to three import edits, and add: append `is_ambient_git_cwd` to the existing L67 line and keep the literal `from bytedigger_engine.lib.git_cwd import resolve_git_cwd` intact. GH381 AC9(c) (`test_gh381_git_cwd_resolver.py` L383-394) does a text match on that literal. A sorted, parenthesised rewrite breaks it.
4. **MINOR:** §2 L24 "Resume replays the cached step result (neither producer nor rung re-runs)" is not backed for this step. `invoke_fix_integrity_llm` has no `resume_sentinel` (L718; the default is `False`). Either cite the replay mechanism, or state that on resume the step re-runs and the producer rewrites the receipt on the then-current tree (idempotent).
5. **MINOR:** AC12's second half ("`preflight.py`, `phase_5_integrity.py` byte-unchanged") has no executable check. Name the check, e.g. `git diff --exit-code <base> -- engine_py/bytedigger_engine/preflight.py engine_py/bytedigger_engine/workflows/phase_5_integrity.py` in the GREEN-verify step, or move it into AC13.
6. **MINOR:** Under "Limit stated":
   - Add adversarial edge 1 (the receipt reflects HEAD, not `fix_commit_sha`) and edge 4 (a fix-side run also deletes a `phase: red` receipt).
   - Carry over the s5 r3 advisory: renames, `diff.noprefix`, and a `diff_command` override without `a/`/`b/` give a fail-safe `missing`.
7. **MINOR:** Clarify "Both `_emit_safe` names already exist in the module" (cosmetic).
