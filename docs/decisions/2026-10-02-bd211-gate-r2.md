## Adversarial edges (not covered by §3)

1. **Unconditional `--tag "$REF_NAME"`.** AC9 would still accept it. On a PR the ref name is `N/merge`,
   and on main it is `main`; both produce `malformed`. This PR's own CI run would show it, so it is
   self-revealing (MINOR, finding 2).
2. **Pre-release tag push** (`v1.2.0-rc1` matches the `v*` trigger): `--tag` reports it as malformed and CI
   goes red on rc tags. This is consistent with the strict regex. It is a policy note only, and the
   CONTRIBUTING text should say it (finding 3).
3. **AC13 runs the UUT through a symlinked interpreter.** A venv symlinked from outside its directory loses
   site-packages but keeps the stdlib, and the UUT is stdlib-only, so this is fine. If GREEN ever imports a
   third-party module in `version_parity.py`, AC13 would fail for an unrelated reason. No action needed.
4. **Several tags ahead** (`v0.10.0`, `v0.11.0`): a GREEN that reports the first ahead tag would name the
   wrong one. It still exits 1, so the guard holds and only the message would be off. Advisory.
5. Annotated tags, `v01.2.3`, and the tag-push concurrency/heartbeat interplay were re-checked: tag runs
   have `head_branch` set to the tag name and are excluded by the heartbeat filter. No issue.
