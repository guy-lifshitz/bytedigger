## Adversarial edges (not covered by the §3 ACs)

1. **Cycle ≥2 scaffold with a valid SHIP sidecar.** `_prior_ship_base_block` (`:1155`) and the S10b read (`:1199`)
   inline the same `spec.md`. The record should then have two chunks with the same `source_id`, in prompt order:
   `strip()`, then whole. No AC pins this, and §2.2's order sentence does not say that both apply.
2. **GREEN retry-once (`GREEN_NO_MARKER`).** The same prompt is re-sent, and F2/F3 must be declared again. See
   MAJOR-4.
3. **Ordinal insertion.** A new `read_text` placed above an existing one in the same scope takes the old `#0` key and
   its class. The old read reappears as `#1` and is the one reported as unkeyed. See MINOR-4.
4. **A builder reaching a class-I read through a root-level helper.** `role_template.py` is the current example. The
   lint cannot see such a read at all. See MINOR-5.
5. **A security fragment override that points at an empty file.** It returns `""` without `FileNotFoundError`, so no
   block is declared and the prompt carries nothing. That is fail-open on an empty file, and no AC covers it.

## Findings

**MAJOR-1: the lint cannot see the engine's real subprocess chokepoint, or its named read wrappers.**
- Spec §2.6 (spec:106-109, 126-127) sets the callee set to `subprocess.run/check_output/Popen`.
- Workflows spawn through `lib/bounded_spawn.bounded_run` (A375DD88, `bounded_spawn.py:32`). Of the 62 wrapper calls in
  workflows, the subprocess ones go through it. A grep finds only two direct `subprocess.run` calls under `workflows/`:
  `_baseline_delta.py:53` and `phase_05_inject.py:568`.
- Under the "counted at the wrapper's raw call, once" rule, every subprocess output in the engine collapses into one key,
  `lib/bounded_spawn.py::bounded_run::subprocess.run#0`, and that key can carry only one class.
- The same happens to `run_test_command` (`disk_truth/test_runner.py:233/257`), `_read_text_or_empty`
  (`phase_5_implement.py:4604`) and `_read_or_empty` (`phase_6_review.py:1275`).
- Result: the "contiguous slice of a subprocess's output" class (§4) has no detection. A new `bounded_run(...)` tail
  inlined into a prompt never reddens the lint. For that family, the detection chokepoint the spec claims does not
  exist.
- **Required fix:** name a wrapper-callee list in §2.6 (at least `bounded_run`, `run_test_command`,
  `_read_text_or_empty`, `_read_or_empty`, `_git_read`) whose calls are keyed **at each caller**, or derive that list
  transitively in the lint. Add an AC11 case where a `bounded_run(...)` call with no key reddens.

**MAJOR-2: AC12's deferred test cannot be satisfied honestly. T1/T2 have no correct keys under §2.6.**
- T2 (`phase_5_implement.py:3569-3580`) is in-memory `bounded_run` stdout. Under the spec's callee set,
  `phase_5_implement.py` has no call site for it.
- T1 (`:5153`) reads through `_read_text_or_empty`, whose single raw site (`:4608`) also serves two not-prompt callers
  (`:4597, :4695`).
- `test_ac12_inventory_classifies_deferred_sites` (test:764-766) requires at least 2 `I-deferred` keys in
  `phase_5_implement.py`. GREEN can only meet that by misclassifying an unrelated read, or by over-classifying a shared
  helper.
- **Required fix:** after MAJOR-1, pin the exact T1 and T2 keys in §2.5 (caller-scoped, for example
  `...::<collect-probe fn>::bounded_run#0`) and assert those exact keys in AC12.

**MAJOR-3: the key grammar leaves callee and scope resolution undefined, so the inventory depends on the implementation
(Q3).**
- Spec:106-109 does not say:
  - whether `open` means only the builtin, or also `p.open()` / `Path.open`, `io.open`, `os.open`, `gzip.open`;
  - how `import subprocess as sp`, `from subprocess import run`, `from json import load` and
    `read = p.read_text; read()` resolve;
  - what qualname nested defs get (`f.<locals>.g` or `f.g`), or where lambdas, `async def` and class-body reads go.
- Two conforming GREENs would emit different key sets. AC11's ordinal test pins only the builtin `open` and
  attribute-form `read_text`.
- **Required fix:** add a normative matching rule: match by resolved import binding and by attribute name for
  `.open/.read_text/.read_bytes`, and give the qualname format. Declare as limits what stays undetectable (bound-method
  aliasing, `getattr`). Add AC11 cases for `p.open()`, an aliased-module import, a nested-function qualname and a
  lambda.

**MAJOR-4: the GREEN retry-once path re-sends the prompt without its F2/F3 record (§1ab per entry path).**
- `_invoke_green_llm`'s `extra_data` (`phase_5_implement.py:7568-7587`) forwards `prompt` and `role_template` but not
  `injected_blocks`.
- `_write_green_artifact` then retries with `injections=_declared_injections(prev_data)` (`:7682`), so the retry
  declares only the role template.
- §2.4 names only `phase_6_review.py:2620`. The RED's direct-dispatch harness cannot observe this path.
- **Required fix:** in §2.4, add `"injected_blocks": prev.data.get("injected_blocks")` to the `:7568` forward. Add an
  AC that drives `_invoke_green_llm` and then `_write_green_artifact` on `GREEN_NO_MARKER`, using the recording backend,
  and asserts that both attestations carry the same F2/F3 entries. Also audit every other `extra_data`-rebuilt retry.

**MINOR-1.** §2.5 (spec:100-101) says the lint "stays green only while the issue is open". The lint is pure AST and has
no issue state or `kill-by`. Either correct the text, or add a deterministic check that each `I-deferred` issue number
is listed in `AUTHORSHIP_SPEC.md` §4 "not yet declared", and the reverse.

**MINOR-2.** At test:767-768, every `I-deferred` entry must carry `"192"`. That over-constrains future deferrals: a later
lot deferring to bd#151 or bd#152 would redden bd#150's test. Assert `"192"` on the T1/T2 keys only. AC11(c) already
covers "issue required".

**MINOR-3.** The out-of-scope `_standards_context.py` (spec:13) no longer exists. Drop it, and in §2.7 reconcile the S4
entry in `AUTHORSHIP_SPEC.md` §4.

**MINOR-4.** Ordinal keys churn, and they let a new read inherit a class (Adversarial edge 3). Declare this as a limit.
Better: have `check` print the source line for each reported key, or add a normalized argument fingerprint to the key.

**MINOR-5.** Root-level modules are outside the lint scope (`role_template.py`, `facts_pack.py`, `spec_cite`). A reach
from a workflows builder into one of them is invisible to the lint. Declare this in §2.6 next to the wrapper limit.

**MINOR-6.** S10c is not cycle-1-only (Adversarial edge 1). State the two-chunk record and pin it with an AC5 variant
that has a valid sidecar.

**MINOR-7.** `not-prompt` is undefined. Define it, and say how to classify a read whose content reaches the model only
through a file the model reads with tools (`phase_05_inject.py:1278, :1308`) or a backend tool response
(`reference_backends/pydantic_openai.py:224`).

**MINOR-8.** F3's default asset uses an absolute `str(path)` as `source_id`, while F1/F2 use package-relative IDs to stay
stable across install locations. The asymmetry is defensible, because the override must stay absolute, but the spec
should state it. §1.5's "142 call sites" should be re-measured once the matching rule is fixed.

**Q2 (Principle B):** deferring T1/T2 with a named issue and an `I-deferred` class is not a band-aid. It is a declared,
tracked residual that keeps the chokepoint. The mechanism is unsound only as described: MINOR-1, MINOR-2, and MAJOR-2
for the keys.
**Q6:** the design is provider-agnostic: it uses only the chokepoint and AST, with no backend coupling. It is
deterministic-first: an AST lint plus a JSON inventory is the cheapest layer. No issue.
