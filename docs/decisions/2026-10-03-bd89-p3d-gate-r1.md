## Step 1.5: rule-overlap simulation

Dispatcher `lint()`: (a) the entry is not a dict and the name ends with `_ENFORCE`, so it is reported; (b) `is_rollout` is true, so `check_entry` runs; (c) otherwise the entry is skipped. `is_rollout` returns true if the entry is a dict AND its kind is flag or gate AND at least one of these holds: the name ends with `_ENFORCE`, the description has `flip-by:` or `retire-by:`, the entry has an `owner` or `expires` key, or the name is in `_EXTRA_ROLLOUT`.

- AC5/AC6 live run: all 18 rollout entries hit branch (b). `HAL_ORPHAN_CALLSITE_GATE` (gate, no suffix, no date text, no fields) hits (c). The 91 non-rollout entries hit (c). No `path`/`int`/`str`/`binary` entry has `flip-by:` text, so the kind check never decides anything on the live data.
- AC7/AC8: every entry is a `_ENFORCE` dict, so all go to (b) and the first `check_entry` violation fires. `HAL_GOOD_ENFORCE` and the full `HAL_FOO_ENFORCE` produce no violation. Correct.
- AC9: `None`, `[]` and `"oops"` have the `_ENFORCE` suffix, so they go to (a). They never reach `is_rollout`, which would return false for a non-dict. The int `5` fails the str check. `"2026-13-45"` passes the 10-character regex and then raises ValueError in `fromisoformat`, which the spec requires to be caught. `"soon"` fails the regex. `["x"]` fails the owner-not-str check. Each case gets a name-prefixed line. Correct, provided `check_entry` catches the ValueError (it is a GREEN obligation, and AC9 tests it).
- AC10: the `path` entry fails the kind check and goes to (c), exit 0. `HAL_ROLLOUT_NOSUFFIX` (flag, `flip-by:`) goes to (b), missing fields, exit 1. Correct.
- AC6 boundary: the comparison is `expires < today`. With `expires == today == 2026-11-02` there is no violation and the exit code is 0. On 2026-11-03 all 16 renewed entries fail and the two 2027 entries pass. Correct.
- Overlap gap: a non-dict entry that is in the rollout set by date text or by `_EXTRA_ROLLOUT`, but has no `_ENFORCE` suffix, falls through to (c) and is silently skipped. Its description cannot be read, and the `_EXTRA_ROLLOUT` membership is ignored. See adversarial edge 3.

## Adversarial edges (not covered by §3)

1. **Lifecycle vs pins (new flag).** After merge, a contributor adds `HAL_BAR_ENFORCE` with a valid owner and expires, exactly as CONTRIBUTING and AC8 prescribe. The lint passes. The CI step `pytest tests/test_bd89_p3d_flag_expiry_lint.py` fails twice: the AC2 `stray` check ("unpinned *_ENFORCE entries") and AC3 `rollout == ROLLOUT_NAMES`. Spec AC2 does not require the `stray` check; the RED added it.
2. **Lifecycle vs pins (renewal / time).** On or before 2026-11-02, someone renews `HAL_SIBLING_AUDIT_GATE` (or any renewed entry) to a later date, which is the op5 renewal path. AC4 (`== "2026-11-02"`) then fails, and so does AC6 (`--today 2026-11-03` must exit 1 and name `HAL_SIBLING_AUDIT_GATE`). If nobody renews, the lint step fails from 2026-11-03 on, which is intended. Either way, the pinned test file goes red on a documented legitimate action within 30 days.
3. **Non-dict entry in the rollout set without the `_ENFORCE` suffix** (for example `HAL_SIBLING_AUDIT_GATE: None` or a broken `HAL_SPEC_DEFECT_REROUTE`). `lint()` reports a non-dict entry only when its name has the `_ENFORCE` suffix. `is_rollout` requires a dict. So `_EXTRA_ROLLOUT` membership is silently lost, and the entry escapes the lint.
4. **Catalog loads but is malformed.** A catalog with no `FLAGS`, with `FLAGS = []`, or with a module that raises at import (`raise RuntimeError`) is untested. A naive `mod.FLAGS` / `.items()` crashes with a traceback, which violates the binding "lint degrades, not crashes" constraint for the exit-2 class.
5. **Collateral edits to the 91 non-rollout entries, or to rollout descriptions.** op2 says "descriptions and default values are unchanged", but no AC pins any non-rollout entry, `len(FLAGS) == 109`, or the descriptions of rollout entries. Example: GREEN strips the `flip-by:` text from descriptions after adding `expires`. That passes every AC, because the owner/expires keys keep those entries in the rollout set.
6. **Timezone at the day boundary.** `date.today()` on the CI runner is UTC. Near midnight it can disagree with a local run of the same commit by one day. This is the off-by-one at the `expires == today` boundary in production, not in the tests.

## Findings

1. **MAJOR F1: migration snapshot pinned into a permanent CI step.** op4/AC12 make `tests/test_bd89_p3d_flag_expiry_lint.py` run on every CI push. These assertions in that file are migration-time snapshots, and each one fails on a lifecycle action the spec documents (op5 renewal, AC8 new flag):
   - `test_ac2_...`: the `stray` block (lines 172-176). It goes beyond spec AC2 and fails on any new `*_ENFORCE`.
   - `test_ac3_...`: `assert rollout == ROLLOUT_NAMES` (lines 184-187). It fails on any new rollout entry.
   - `test_ac4_...`: `expires == "2026-11-02"` / `== "2027-01-15"` (lines 208-215). It fails on the first renewal.
   - `test_ac6_...`: live-catalog expiry on fixed dates (lines 228-232). It fails once `HAL_SIBLING_AUDIT_GATE` is renewed past 2026-11-03.

   The result is a guaranteed red CI on main within 30 days on the happy path, with nothing pointing the renewer at this test. **Required fix (RED author lane plus a spec errata line, before GREEN):**
   - (a) Delete the AC2 `stray` block. Keep the per-name default pins, because a conscious edit at the wave-2 flip is the intended shield.
   - (b) AC3: change to `ROLLOUT_NAMES <= rollout` (superset), and keep the owner/expires/floor checks for every rollout entry.
   - (c) AC6: move expiry and the boundary to a synthetic catalog. Use one rollout entry with `expires: "2026-11-02"`. `--today 2026-11-02` must exit 0, and `--today 2026-11-03` must exit 1 with the line starting with the entry name. The live-catalog run may keep only a date-independent form such as `--today 2999-01-01` exits 1.
   - (d) AC4: the spec must choose one of two options and record the choice in the errata. Option 1: relax the dates to `expires >= "2026-11-02"` (late-dated entries: `>= "2027-01-15"`), with the exact date values checked by the orchestrator diff at GREEN. Option 2: keep the exact pins, mark AC4 as a migration-only test the CI step deselects (for example a `-k "not ac4"` on the CI command, which AC12's regex still matches), and run it once at §6 verify.
   - Update the §3 expected-red summary if the count changes.
2. **MINOR F2: AC2/AC3 wording.** Errata: "AC2 pins 19 names: the 18 rollout entries plus `HAL_ORPHAN_CALLSITE_GATE`"; "AC3 floor = base date 2026-10-03".
3. **MINOR F3: exit-2 class coverage (edge 4).** Recommended: add to AC11 a catalog without `FLAGS`, a catalog with `FLAGS = []`, and a catalog that raises at import. Each must exit 2 with one line and no `Traceback`. Spec op3 already places them under "unloadable", so this needs no design change. It directly defends the coordinator's "degrades not crashes" constraint.
4. **MINOR F4: non-dict rollout entries without the suffix (edge 3).** Recommended op3 clarification: `lint()` reports any non-dict entry whose name is in `_EXTRA_ROLLOUT` or ends with `_ENFORCE`. Optionally, add `HAL_SIBLING_AUDIT_GATE: None` to the AC9 synthetic catalog.
