## Step 3: RED adequacy

- The test module imports only names that exist (`llm_subprocess`, `telemetry_ctx`, `StepResult`, `EventLog`). Every red is at
  assert time; nothing is red at collect time.
- The unit under test is the real chokepoint (`invoke_llm_subprocess` → `_dispatch_backend`). Only the backend is a double, and
  it is registered through the public `register_backend` seam. Events are read back from a real `EventLog` file, and the
  expected digests come from `hashlib` (test:66-68, :203). Nothing is stub-passable.
- I checked wrong GREENs that the RED catches:
  - an id stamped on the result but different from the event's (AC5/6/7/8/9 compare against the logged payload);
  - one id per `invoke_llm_subprocess` call instead of per dispatch (AC8);
  - a digest of `str(data)` or of another field (AC2, AC3);
  - in-place stamping while in a run (AC5 snapshot plus `not in original`);
  - an unstamped refusal, or a refusal still carrying "forged" (AC7);
  - the first id returned after a fallback (AC8 `ids[1]`);
  - stamping with no run context (AC6b);
  - a GREEN that suppresses the id when emit fails (AC9).
- `claude-in-session` goes through the same `_BACKENDS[...]` call (:1692, registered at :2686). There is no second dispatch
  path (grep `_BACKENDS\[` / `_invoke_in_session`), so the generic fixture covers it structurally.
- NIT-3: `backend.last_data is original` (test:271) is tautological, because the double returns its own field. The content

## Adversarial edges (not covered by the §3 AC table)

1. **Exact-equality siblings:** `test_bd167:867/:883` (see above). Not listed by the RED.
2. **In-place removal with no run context:** `result.data.pop("invocation_id", None)` on the backend's own dict passes AC6b,
   because AC6b never checks the backend's dict. The same holds for in-place overwrite on the forged path in AC6a.
3. **Run context present, `event_log=None`** (`set_current_run(event_log=None, ...)` is legal, `telemetry_ctx.py:50-57`): a
   GREEN that stamps on `run_ctx is not None` writes an id that no event names, which breaks the §2.4 invariant. No test
   covers it.
4. **`data` that is not a dict, in a run:** a GREEN that turns `None` into `{"invocation_id": ...}` passes AC3 `data_not_dict`,
   which makes no assertion on `result.data`. Callers that test `result.data is None` would then change behavior.
5. **Pre-dispatch refusals in a run:** a wrapper-style GREEN that stamps every return of `_dispatch_backend` whenever a run is
   active is only inert today because those builders use `data=None` (e.g. :1148, :1624). No test pins "refused before
   dispatch ⇒ no `invocation_id`" (`[bd10:27]`).
6. **Sentinel replay:** a GH374 step-sentinel cache hit replays the stored `data`, including an `invocation_id` from an earlier
   process. The id names a real event in the run's log, but not "this dispatch" as the §2.4 invariant says. This is not
   declared in §5.
7. **Spec text placement:** `bd#206` may appear anywhere in `AUTHORSHIP_SPEC.md` and the AC10 test still passes. The §2.6
   matching rule is never asserted. The R3.2 row at `AUTHORSHIP_SPEC.md:371` still calls "class-M output attestation (#152)" a
   follow-up.

## VERDICT

VERDICT: REJECTED

1. **MAJOR-1: two sibling tests go red after a correct GREEN, and neither the RED nor the spec handles them.**
   - `engine_py/tests/test_bd167_cost_cache_billing.py:867` and `:883` (`assert res.data == data`) dispatch in a real run
     context. A correct GREEN adds `data["invocation_id"]`, so both fail, and the GREEN cannot amend tests. Spec §4:85-86
     foresees such sites, but §4:80 and §7:105 declare the bd10 `ATTEST_KEYS` edit "the only edit", and the RED report
     lists none.
   - **Fix (RED + spec):**
     - In both bd167 tests, assert `{k: v for k, v in res.data.items() if k != "invocation_id"} == data`.
     - In both, also assert that `res.data["invocation_id"]` matches `^[0-9a-f]{32}$`. In the :883 case it should also equal
       the logged attestation's id.
     - List both sites in spec §4 and §7 as RED amendments.
2. **MINOR-1: backend-dict non-mutation is checked only on the plain in-run path.**
   - `test_bd152_output_digest.py:280-307`: in both AC6 tests, keep a reference and a deepcopy of the backend dict. Assert it
     is unchanged after the call (it still holds `"invocation_id": "forged"`) and that `result.data is not` that dict.
   - Spec §2.4:38: state that the no-mutation rule applies on every path, including no-run.
3. **MINOR-2: the `event_log is None` branch of "no event ⇒ no key" is untested.**
   - Add an AC6c: `telemetry_ctx.set_current_run(event_log=None, run_id="R", step_name="s")` plus a forged backend id. Assert
     the key is absent and nothing raises.
   - Spec §2.4:37: replace "(no run context)" with "(no run context or no event log)".
4. **MINOR-3: no AC pins "data that is not a dict stays as it is" or "a pre-dispatch refusal carries no id".**
   - In AC3 `data_not_dict` (test:217/:225), assert `result.data is None`.
   - Add one hard-gate floor refusal in a run (e.g. `hard_gate=True, model="haiku"`). Assert there is no attestation and that
     `result.data` is None or holds no `invocation_id`.
   - Spec: add both to §3.
5. **MINOR-4: AC10 is looser than §2.6.**
   - `test_bd152_output_digest.py:427`: search for `bd#206` only inside the class-M paragraph, sliced from `"**Class M,"` to
     `"**Chunk rule.**"`. Also assert that slice contains `invocation:<step_name>:<invocation_id>`.
   - Spec §2.6 and §7: decide on and name the update to the R3.2 row at `AUTHORSHIP_SPEC.md:371`, which would otherwise keep
     calling #152 a follow-up.
6. **MINOR-5: sentinel replay is not a declared limit.** Spec §5: add that a cached step result replayed from a sentinel
   carries the id of the original dispatch's attestation, not of a new one.
7. **NIT-1:** `test_bd10_l3_authorship.py:87`, `:167` and `:397-400` say "nine". Update the comments in the RED.
8. **NIT-2:** Spec §1.1 should acknowledge the in-session `request_nonce` (`llm_subprocess.py:799`). Either declare it
   unlinked (§5) or note it for bd#206.
9. **NIT-3:** `test_bd152_output_digest.py:271`: `backend.last_data is original` is tautological. Drop it or keep it as a
   documented precondition.
