## Step 1.5: Rule-overlap simulation

**Classifier.** First match wins, Dockerfile before IaC.
- `k8s/Dockerfile.yaml` → Dockerfile. Tested.
- `Dockerfile.dockerignore` / `x.dockerignore` → none. Tested.
- `Containerfile*` → Dockerfile. Tested.
- `compose.y*ml` → IaC. Tested.
- `*.tf.json` → none. Not in the classifier and not listed out of scope. MINOR, carried over from r1-18.

**Verdict dispatcher**, each branch simulated in order:
1. argparse / usage error → F5 JSON, exit 2. Tested with 4 shapes.
2. `--root` missing or not a dir → F5. The not-a-dir case (`--root` pointing at a regular file) is untested. MINOR.
3. `--fail-on` → F8. The spec does not say F8 is checked before enumeration or scanning. The test asserts `not v["nongating"]`, which pins "before scanning". The spec should say so (MINOR 11). The order of F8 vs F4 (bad `--fail-on` on a nothing-to-scan tree) is also unspecified. MINOR 11.
4. Enumeration. Without `--files`: `git ls-files -z`, then G1. With `--files`: relative entries kept, while missing and outside-root entries are dropped silently. **An absolute path inside root is unspecified.** The spec says only "paths relative to root". A GREEN that drops every absolute path passes all tests (`test_ac7_files_outside_root_and_missing_ignored_no_crash` has only an absolute path *outside* root). A caller passing `$(git diff --name-only | xargs realpath)` then gets `nothing_to_scan`, exit 0, on every run. That is fail-open. **MAJOR 6.**
5. F4 → exit 0.
6. F1/F2 binary missing.
7. Scanner runs. Rule F6 applies to hadolint; rule F3 applies to trivy for rc. Then parse, then F7 shape. **Empty stdout with rc 0**: hadolint rc 0 and trivy rc 0 have no branch. The idiom `json.loads(out or "[]")` / `if not out.strip(): return []` gives `clean`, and that passes every test. **MAJOR 3.**
8. Per finding: severity (F10), gating vs nongating, then waiver. With **missing `ID`/`code`**, there is no branch. A `continue`-on-missing-key implementation drops the finding and returns clean. **MAJOR 4.**
9. Aggregate (F9): unavailable > blocked > clean. **Run granularity for hadolint is unspecified.** The F9 hadolint test requires one hadolint invocation per Dockerfile (the shim fails when `zzbadzz` is anywhere in argv). A batched `hadolint --format json a/Dockerfile b/Dockerfile` is a valid reading of §1, and it fails `test_ac10_f9_two_dockerfiles_one_run_fails_exit2_other_gating_listed`. The same test asserts `"zzgoodzz" in gating[0]["file"]`, while the shim's hadolint item says `"file": "Dockerfile"`. So GREEN must attribute `file` from the *input path*, not from hadolint's own `file` field, and the spec says neither. **MAJOR 5** (spec/test contradiction: a spec-conformant GREEN fails RED).

## Adversarial edges (not covered by the §3/§4 AC set)

1. **Env-var suppression.** `HADOLINT_IGNORE=DL3006`, `HADOLINT_OVERRIDE_INFO=DL3006` (downgrades error → info → LOW, nongating), `HADOLINT_FAILURE_THRESHOLD`, `XDG_CONFIG_HOME/hadolint.yaml` (hadolint's config lookup checks XDG before HOME), `TRIVY_SEVERITY=LOW` (trivy drops CRITICAL/HIGH before output), `TRIVY_SKIP_DIRS`, `TRIVY_SKIP_FILES`, `TRIVY_IGNORE_POLICY`, `TRIVY_CHECK_NAMESPACES`/`TRIVY_MISCONFIG_SCANNERS`. Each of these removes findings before the script sees them. A CI workflow file in the repo is agent-writable and can set them. (MAJOR 1)
2. **Inline trivy/tfsec ignores** (`#trivy:ignore:AVD-…`, legacy `#tfsec:ignore:`, `# trivy:ignore:*[exp:…]`) in `.tf` and YAML. No CLI flag disables them. (MAJOR 2)
3. **Scanner exits 0 with empty stdout** (killed by OOM before flush, broken wrapper script, `HADOLINT_FORMAT` overridden to an output that goes elsewhere). (MAJOR 3)
4. **Misconfiguration without `ID`, hadolint item without `code`, `Results: ["x"]` / `[null]`.** (MAJOR 4)
5. **Batched hadolint invocation** and attribution from hadolint's own `file` field. (MAJOR 5)
6. **`--files` with absolute paths inside root**, or with paths relative to the git toplevel while `--root` is a subdirectory. Every entry is dropped, giving `nothing_to_scan`, exit 0. The verdict does not show that inputs were dropped (r1 MINOR 10 still open). (MAJOR 6)
7. **Fresh HOME vs trivy's checks bundle.** `trivy config` caches the misconfig checks bundle under the user cache dir (`$HOME/Library/Caches/trivy` on macOS, `$XDG_CACHE_HOME` or `$HOME/.cache/trivy` on Linux). A fresh HOME forces a registry download on every run. If that is slow, it hits the 60 s default timeout, which is a false `unavailable`. Air-gapped, it depends on the trivy version's embedded-checks fallback. The run never fails open, but the gate can be permanently red in CI. (MINOR 6)
8. **`--fail-on CRITICAL` with an unknown or missing severity.** F10 maps it to HIGH, so it becomes nongating and exits 0. That is "fail-closed" only under the default set. Also, a lowercase `critical` from a trivy fork or plugin maps to HIGH, which is a downgrade. Real trivy `UNKNOWN` is "known", so under the default set it is nongating while a garbage string is gating. (MINOR 8)
9. **Relative trivy `Target`** (`main.tf` from `trivy config /abs/repo/infra`). "Relative to root when under root" has no join base. Joined against the script's cwd (a temp dir), it is "not under root" and reported as `main.tf`. Then an allowlist pattern `infra/main.tf` never matches. (MINOR 7)
10. **Nested IaC dirs** (`infra/main.tf` plus `infra/mod/x.tf`). `trivy config infra/` is recursive, so the `infra/mod` run duplicates findings. A waiver then shows up once under `waived` and once under `gating` if the `file` strings differ. (MINOR 7)
11. **`git` absent from PATH.** The spec says exit 2, but no test covers it. `except OSError: return []` is fail-open and passes RED. (MINOR 13)
12. **Uncaught exception after parse**, for example `OverflowError` from `--timeout inf`. Python exits 1, which is read as `blocked`, with a Traceback. Not fail-open, but the status is wrong. The spec should require a top-level handler that returns `unavailable` with exit 2 (r1 MINOR 13 second half). (MINOR 12)
13. **`--root` pointing at a regular file.** (MINOR 12)

## Findings

**MAJOR (any one blocks GREEN)**

1. **Scanner env passthrough defeats "only the allowlist can waive"** (r1 M7 residual). The spec isolates cwd and HOME but inherits the caller env, including `HADOLINT_*`, `TRIVY_*`, `XDG_CONFIG_HOME`, and `XDG_CACHE_HOME`.
   - Required in the spec: scanners run with a **constructed env**, not `os.environ`: `PATH`, `HOME=<fresh>`, `TMPDIR`, `LANG`, plus a named cache var if needed (see MINOR 6). Every `HADOLINT_*`, `TRIVY_*`, and `XDG_*` var is dropped. Also pass `trivy --severity UNKNOWN,LOW,MEDIUM,HIGH,CRITICAL` explicitly, so that no config can narrow the reported set.
   - Required in RED: the M7 test sets `HADOLINT_IGNORE=DL3006`, `TRIVY_SEVERITY=LOW`, and `XDG_CONFIG_HOME=<dir with hadolint.yaml>` in the script's env. The shim logs `env | grep -E '^(HADOLINT_|TRIVY_|XDG_)'`. The test asserts that none of them reach the scanner, and that trivy argv contains `--severity` with all five levels.
2. **Inline `#trivy:ignore:` / `#tfsec:ignore:` cannot be disabled, and the test is vacuous on it** (r1 M7 residual; r1 explicitly required declaring it).
   - Required in the spec, one of the following:
     - (a) **Recommended.** The script itself scans every IaC candidate (and every file under each trivy scan dir) for `trivy:ignore` / `tfsec:ignore` comments. It emits each hit as a gating finding `{scanner:"devops_scan", id:"inline_ignore_pragma", severity:"HIGH", file, description:<the line>}`. That finding can be waived only through the allowlist, which keeps governance intact.
     - (b) A declared known limit, with the "only the `--allowlist` can waive" sentence corrected.
   - Required in RED: for (a), a test where trivy returns clean (`{}`) and `main.tf` contains `#trivy:ignore:AVD-X-1` → exit 1 with gating `inline_ignore_pragma`, plus a waiver test. For (b), remove the misleading inline line from the M7 test, or comment it as not covered.
3. **Empty stdout with rc 0 is unspecified for both scanners** (r1 M3 residual).
   - Required in the spec: "empty or whitespace stdout is never `[]`/clean, whatever the rc". For hadolint rc 0 and trivy rc 0 that means exit 2 (`json_decode_error` or `subprocess_error`, named).
   - Required in RED: parametrize `""` and `"  \n"` for hadolint rc 0 and for trivy rc 0, each alone, each expecting exit 2 / `unavailable`.
4. **Finding identity fields and Result entries are not shape-checked** (r1 M2 residual; r1's required fix named both).
   - Required in the spec, F7 extension: a trivy misconfiguration without a non-empty string `ID`, a hadolint item without a non-empty string `code`, and a `Results` entry that is not an object are all `json_shape_error`. The alternative, explicitly stated, is to keep the finding as gating HIGH with `id:"<missing>"`. Never skip it.
   - Required in RED: `_tv_raw({"Severity":"CRITICAL"})`, `_hl_raw({"level":"error"})`, `{"Results":["x"]}`, `{"Results":[null]}`. Each runs alone and expects a non-zero exit with no `clean` verdict.
5. **Hadolint run granularity and `file` attribution are pinned by RED but absent from the spec.** Spec/test contradiction: a batched hadolint invocation is spec-conformant and fails the F9 hadolint test. The test also requires `file` to come from the input path, not from hadolint's `file` field.
   - Required in the spec (§1): "hadolint is invoked once per Dockerfile; trivy once per distinct directory". Also: "hadolint finding `file` = path relative to root of the Dockerfile passed to that run (hadolint's own `file` field is ignored)".
   - Alternatively, change the test to be granularity-agnostic. Then F9 coverage for hadolint has to come from a per-file failure signal that a batch run can still attribute. The spec route is simpler.
6. **An absolute `--files` entry inside root is silently dropped → exit 0** (fail-open at the integration point; r1 MINOR 10 escalated now that the wiring step is next).
   - Required in the spec: an absolute path that resolves under `--root` is accepted, normalised to root-relative. The `reason` of a `nothing_to_scan` verdict carries the count of dropped `--files` entries (e.g. `"ignored 2 of 2 --files entries"`).
   - Required in RED: `--files <abs path of root/Dockerfile>` → exit 1 `blocked`. Also, the existing outside-root test asserts that the reason mentions the dropped count.

**MINOR (advisory)**

6. Trivy cache under a fresh HOME. Specify `--cache-dir <persistent dir outside root>` (or `--skip-check-update` with embedded checks) and a minimum trivy version. Otherwise expect per-run registry downloads and false `unavailable` on timeout or offline.
7. Specify `file` for a relative trivy `Target` as `relpath(join(scan_dir, Target), root)`. Add a test that a `_tv(target="main.tf")` result from scanning `infra/` reports `file == "infra/main.tf"`. The current unlisted-target test only checks a substring. Also say whether nested scan dirs are deduplicated (scan only the topmost dir, or dedupe on `(scanner, file, id)`).
8. F10 under a non-default `--fail-on`: an unknown or missing severity is "HIGH", so it becomes nongating under `--fail-on CRITICAL`. Consider making unknown always gating (or mapping it to CRITICAL). Uppercase trivy severities before the known-set check. State that real trivy `UNKNOWN` follows `--fail-on`.
9. Define "today" (local date) in §3. In RED, compute dates per test rather than at import, or tolerate a midnight crossing.
10. Spec hygiene:
    - F3's reason list contradicts F7 (`json_decode_error` vs `json_shape_error`). Make F3 say "not valid JSON → `json_decode_error`; wrong shape → see F7".
    - Remove the blank line that splits the §2 table.
    - Give G1 an F-row.
11. State that F8 is validated before enumeration and scanning, and that it takes precedence over F4.
12. Add to F5: a top-level exception handler emits `unavailable` with exit 2, never a traceback with rc 1. `--root` pointing at a non-directory → F5. Add a test for each.
13. Add a G1 test with `git` absent from PATH. Build a minimal bin dir with symlinks to `sh`, `dirname`, `cat`, `wc`, `tr`, and `sleep`, and set PATH to only that dir.
14. `*.tf.json` is neither classified nor listed out of scope (r1 MINOR 18 remainder).

VERDICT: REJECTED

(In the caller's terms: **REJECT**.)

Required fixes before GREEN (MAJOR):
1. Run the scanners with a constructed env. Drop `HADOLINT_*`, `TRIVY_*`, and `XDG_*`, and pass an explicit full `trivy --severity`. Add a RED test that sets these vars and asserts that none reach the shim.
2. Detect inline `trivy:ignore` / `tfsec:ignore` pragmas in the script as gating `inline_ignore_pragma` findings that only the allowlist can waive, with tests. The alternative is to declare a known limit and fix the false "only the allowlist can waive" claim along with the vacuous test line.
3. Spec: empty or whitespace stdout is never clean, whatever the rc. RED: hadolint rc 0 and trivy rc 0 with empty stdout, each alone → exit 2.
4. F7: a missing or empty `ID`/`code` and a non-object `Results` entry are `json_shape_error`, or are explicitly kept as HIGH, never skipped. Add RED cases for each.
5. Spec §1: one hadolint run per Dockerfile, and the hadolint finding `file` comes from the input path (root-relative), not from hadolint's `file` field. This resolves the spec/test contradiction in the F9 hadolint test.
6. Accept absolute `--files` entries that resolve under root, and report the dropped-entry count in `reason`. RED: absolute in-root Dockerfile → exit 1.
