## 4-step audit

### Step 1: spec-internal consistency
- Helper and token names are consistent across spec, RED and the bd#116 source: `ROLE_CORE_ID`, `role_template_digest`, `E_ROLE_TEMPLATE_INVALID`, the 13 new reason tokens (same order in spec section "Reason tokens", AC20 and the RED `NEW_REASONS`).
- Drift 1 (MINOR): Item 1 says "Section scanning ... come from `skill_companion._Doc` ... `lib/frontmatter`" while Principle 5 says `skill_companion.py` is "imported only". That is consistent, but it conflicts with the existing bd#119 module-contract guard (see finding 2).
- Drift 2 (MINOR): AC1 says `content` is "the body text stripped plus `\n\n`". The code keeps the whole file (heading line included) stripped plus `\n\n`, and the RED AC7 asserts `"## b\nbody\n\n"`. The wording "body" is misleading; the intent is "whole text".
- Drift 3 (MINOR): the "H empty" rule prepends `## <slug>` for the checks only; `content` stays the original text. This is not stated in an AC.

### Step 1.5: rule-overlap simulation (reason order)
The order is core_unavailable, frontmatter, section_required, text_outside_section, section_not_overridable, forbidden_markup, unclosed_fence, heading_level_invalid, setext, invalid_section_title, duplicate, empty. I simulated each RED input against it:
- AC5 frontmatter, `<!--`, unclosed fence, H1 after H2, setext, duplicate and empty: each input trips exactly one rule, so the first match is the intended one. PASS.
- AC4 (preamble before the first H2): reaches `text_outside_section` first. PASS.
- Overlap NOT covered by any test: a plain-text template (H empty) that contains an H1 gets `## slug` prepended, so `_Doc.h1_after_h2` is true and the reason is `heading_level_invalid`. The same holds for a horizontal rule `---` or `===` under a text line (`setext_heading`), and for an unclosed fence or a `<!--` comment. Plain text is therefore not a safe subset, which contradicts the spec's Rollback claim "plain-text templates keep working". Two existing tests break because of this (finding 1).
- Multi-error ordering (`; +N more`) is specified but no input in RED has more than one error, so the first-wins order is never exercised (finding 3).

The AC17 "template alone gives a hash" path is covered. Inversely, AC9 and AC10 are in section 3 but the RED does not enforce them (Step 3).

## Adversarial edges (not already AC-covered)
1. Plain-text decoration regression shield: an operator plain-text template containing an H1, `---` / `===` rule lines, a fenced block left open, or an HTML comment is now rejected even though "plain text" is documented as safe. Add an AC and Rollback wording. Two in-repo tests already hit this.
2. TOCTOU in the pin: `check pin -> content check -> record pin` is not atomic. Two threads of the same run (parallel reviewers) can both pass the check with the file changing between reads and the second record overwrites the first. The lock must cover check-and-record, and the recorded digest must be compared, not overwritten.
3. Pin-map eviction (64 runs): an evicted but still-live run silently loses its pin, so drift goes undetected (fail-open). Also unspecified: whether a read refreshes the "oldest" order.
4. Deployment without the repo core: `default_plugin_root()` falls back to the engine's grandparent. A packaged install, a site-packages copy or an unset `CLAUDE_PLUGIN_ROOT` with no `skills/bytedigger/SKILL.md` makes every operator with `role_template_path` fail closed with `core_unavailable`. Needs a documented note or an AC for the packaged case.
5. Symlink and path-alias: the pin key is the expanded path string. A symlink whose target flips between steps keeps the same key but different bytes, so it is caught (good); two different strings naming one file get two pins. No test covers the symlink-retarget case.
6. Digest and hash coupling: `role_template_digest` runs on every `compute_ctx_hash` call and a template that is `empty` or `over_cap` gives `"!empty"` / `"!over_cap"`. A file going missing then reappearing with identical bytes changes the hash twice (a resume re-executes twice). Not tested; arguably acceptable but unstated.
7. BOM-prefixed template with a leading `## project-conventions` and the H-empty prepend with a BOM: the BOM sits mid-text after the prepended heading. `_Doc._split` strips a BOM only at the start. The bd#119 guard pins BOM bytes (`"﻿BOM ROLE"`). Add a BOM case for both H-empty and H-non-empty.
8. Frontmatter probe on a plain text starting with `---` (a horizontal rule on line 1): `parse_frontmatter` may raise or accept; the reason becomes `frontmatter_not_allowed`, which hides the real intent. Unspecified.

## Findings
1. MAJOR: the spec breaks two existing tests that are not in `sibling_tests` or `paths`: `test_phase_45_spec.py::test_role_template_prepended_to_both_prompts` and `test_phase_5_integrity.py::test_role_template_prepended` (H1 fixtures, `heading_level_invalid`). Preflight ran only two siblings, so this is invisible to it. Fix: either rewrite those two fixtures (migrate to plain text or a `## project-conventions` body) and list the files in `paths`/`sibling_tests`, or allow a leading H1 title in the H-empty case. Update the Rollback claim that plain text keeps working.
2. MAJOR: `role_template.py` must import `skill_companion`, `lib.frontmatter` and `telemetry_ctx`, which the existing `test_role_template_module_contract` (stdlib and `contracts` only, AST over all nested imports) forbids. Spec and RED are silent. Fix: state the contract change explicitly (amend that test and the allowlist in the spec's `sibling_tests` handling, with a rationale for the core-boundary lint and `core_manifest.json`), or move the content check to a new module (not `role_template.py`) imported by `load_role_template` through an allowed path. Also state the cycle analysis (`skill_companion` → `verification_registry` → none of the new importers).
3. MAJOR: the "several errors: first in order, `; +N more`" contract has no AC and no RED case, so any implementation order passes. Add an AC and a RED test with two violations (for example `output-schema` plus `<!--`) that asserts the reason is `section_not_overridable` and the detail ends `; +1 more`.
4. MAJOR: AC9 (own pin per run) and AC10 (no run, no pin) are not enforced by RED or by any existing test; the Note's claim of verification "by the existing suite" is wrong for both. A path-only global pin, or a pin that raises without a run, passes all of RED. Fix: fold them into failing tests (the r2 acceptance after the r1 drift assertion; the no-run rewrite acceptance in the same body as an assertion that fails today), then drop the Note's false claim.
5. MINOR: also add ACs/RED for `invalid_section_title`, the TypeError-degrade hash branch, `core_unavailable` for an unusable or empty set, and the 64-char slug cap.
6. MINOR: the pin check-and-record atomicity and the pin eviction policy (adversarial edges 2 and 3) are unspecified; define them in the spec.
7. MINOR: update the bd#119 sibling (`REASONS` at line 69/463) in the same GREEN; list it under `sibling_tests` as "to be amended".
8. MINOR: fix the AC1 wording ("body text" means the whole stripped text).

VERDICT: REJECTED
