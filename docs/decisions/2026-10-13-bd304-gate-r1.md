## Adversarial edges (not covered by the section 3 AC table)

1. **Driver crash is read as a violation.** An uncaught exception in a driver exits 1, and `run_plan` reports any rc 1 as BD66-REFUSE-VIOLATION. An undecodable spec (UnicodeDecodeError) or `--spec <directory>` (IsADirectoryError) is only tested as "missing path → 2". A driver that catches only FileNotFoundError would print a traceback and be reported as a lint finding. Suggested AC6 sub-case: a non-UTF-8 file and a directory both exit 2, with stderr naming the path.
2. **Non-ASCII in finding text.** scope-inverse's `reason` contains `§1v`, and the text line prints it. Under a non-UTF-8 stdout encoding, `print` raises, which gives exit 1 (see edge 1). AC1 exercises this only under the test runner's locale.
3. **Empty spec file (0 bytes).** All six leaving drivers should exit 0. spec-coverage exits 2 (no AC table), which is harmless while it is dormant but becomes BD66-REFUSE-DRIVER-ERROR for every empty `*_spec.md` once #305 flips it.
4. **Multi-finding output.** AC6 pins exactly one finding. The order and the one-line-per-finding text for two or more findings are untested (e.g. helper-extraction with two `$((` lines).
5. **AC9 corpus is the working tree, not the index.** `os.walk` skips only `.git`, so an untracked `.venv`, `node_modules` or build artifact holding a `*_spec.md` can make the measurement pin flaky. The spec says "tracked-or-present", so this is advisory.
