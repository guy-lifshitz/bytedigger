## Step 1.5: Rule-overlap simulation

**Dispatcher** (first match wins), simulated for the r3 additions:
1. argparse/usage: F5 JSON, exit 2.
2. `--root` missing: F5.
3. `--fail-on`: F8, before any scanner run. F8 vs F4 precedence is still unstated, but no test depends on it.
4. `--allowlist` unreadable: F5.
5. Enumeration. With `--files`: relative or absolute-in-root kept; outside or missing dropped and counted. Without: `git ls-files -z`, G1 on any failure, including git absent from PATH. In `test_ac11_g1_git_missing_from_path_without_files_exit2`, PATH holds neither git nor hadolint. G1 has to fire before F1, and it does by construction: F1 needs candidates. **OK.**
6. Classify, then F4.
7. F1/F2 binary presence.
8. Pragma grep over the candidates. Unreadable candidate: falls through to the top-level handler, `internal_error`, exit 2 (only the RED pins this; MINOR 1).
9. Per-run: rc check (F3/F6), then empty stdout (`json_decode_error`), then JSON parse, then shape (F7), then per-entry identity (`<missing>`) and severity (F10).
10. De-dup on `file|id|description`, then gating/nongating split, then waiver.
11. Aggregate (F9): unavailable > blocked > clean.
12. Any uncaught exception: `internal_error`, exit 2.

Ordering hazard found at step 10: the de-dup key omits severity and scanner. If two entries collide on `file|id|description` but differ in severity, a keep-first de-dup can drop the gating copy and keep a nongating one. This needs malformed output, e.g. two `<missing>`-ID misconfigurations with the same (empty) description. That is exactly the input class M4 hardens against. **MINOR 3** (cheap fix).

**Classifier:** the r3 tests add `*.tf.json` and `infra/net.tf.json`, and the existing Dockerfile-wins and `.dockerignore` cases still hold. Pragma fixtures do not create new candidates: `.hadolint.yaml` and `trivy.yaml` at root are not IaC by the classifier. **OK.**

## Adversarial edges (not covered by the §4 AC set)

1. **Relative trivy `Target` against the scan dir.** Real `trivy config /abs/root/infra` reports `Target: "main.tf"`, relative to the scanned dir. The spec still gives no join base ("relative to root when under root, else as reported"). The nested de-dup test makes both runs emit `infra/main.tf`. Joining with the scan dir is the realistic choice, and it *fails* that test (`infra/infra/main.tf` vs `infra/mod/infra/main.tf`). As-reported and join-with-root pass it, but with real trivy they produce `file: "main.tf"` for `infra/main.tf`. Then:
   - File-scoped allowlist patterns mis-scope: a waiver written for root `main.tf` also covers `infra/main.tf`.
   - The nested duplicates de-dup claims to remove (`mod/x.tf` vs `x.tf`) are not removed with real trivy.

   Gating is not fail-open, because unlisted targets are kept. (MINOR 2)
2. **De-dup severity collision.** Two findings that agree on `file|id|description` and differ in severity (malformed `<missing>`-ID output, or a description-less check) collapse. A keep-first can keep the nongating copy. (MINOR 3)
3. **Pragma in a non-candidate file inside a trivy scan dir.** For example, `infra/cfn.yaml` next to `infra/main.tf`, or an untracked `.tf`, or a module dir not listed in `--files`. Trivy scans the whole dir recursively and honours the pragma there, but the script greps only candidates. A pragma can only suppress findings in its own file, and those files are outside the declared scan scope, so this is not a contract hole. r2's recommended fix included "every file under each trivy scan dir". (MINOR 7)
4. **Helm templates in `--files` mode.** A changed `charts/app/templates/dep.yaml` without `Chart.yaml` in `--files` makes trivy scan only `templates/`, which is unrendered Go-template YAML. Trivy may skip it silently and return `{}`, so the verdict is clean. In full (git) mode `Chart.yaml` is a candidate and the chart root is scanned. (MINOR 7)
5. **Root-level IaC file.** The containing dir is `--root`, so trivy recursively scans the whole repo, including untracked files. That means slow runs (false `unavailable` on timeout) and extra gating from local junk. Fail-closed. (advisory)
6. **`LANG=C` for hadolint (GHC runtime).** Older hadolint builds decode files with the locale encoding. A UTF-8 byte in a Dockerfile can make them exit 1 with empty stdout, which reads as `subprocess_error`, a permanent false `unavailable`. Fail-closed. (MINOR 5)
7. **Non-UTF-8 candidate in the pragma grep.** Strict decoding raises `UnicodeDecodeError`, giving `internal_error`, which is also a permanent false `unavailable`. Grep bytes or decode with `errors="replace"`. (MINOR 5)
8. **Shared persistent `--cache-dir`.**
   - Concurrent runs contend on trivy's cache DB lock. This ends in a timeout and `unavailable`, which is fail-closed.
   - The cache holds the checks bundle. A process that can write to the user cache can swap it for an empty bundle and get a clean result. That is outside the repo-writer threat model. (advisory)
9. **Inherited `TMPDIR` inside `--root`.** Trivy's temp writes would then land under root and break AC9's property. (advisory)
10. **All `--files` entries dropped still gives exit 0** (count in `reason`). This covers paths relative to the git toplevel while `--root` is a subdir. Required r2 fix 6 asked only for the count, so the spec meets it. Before wiring, consider exit 2 when every *outside-root* entry is dropped, as opposed to missing entries, which are legitimate deletions. (advisory, for the wiring follow-up)

## Findings

**MAJOR:** none.

**MINOR (advisory, non-blocking)**

1. **`internal_error` trigger is unspecified but pinned by RED.** The test makes a candidate unreadable and requires `internal_error`. A GREEN that catches `OSError` in the pragma grep and reports `unavailable`/`read_error` (exit 2, fail-closed) is spec-conformant and fails the test. Add one line to §2: "an unreadable candidate (pragma grep or scanner input) → exit 2 `internal_error`; never skipped as missing".
2. **Relative trivy `Target` join base** (r2 MINOR 7 remainder). Specify `file = relpath(join(scan_dir, Target), root)` for a relative Target. Rewrite `test_ac11_dedup_nested_scan_dirs_report_once` with an argv-switching shim that emits realistic scan-dir-relative targets: `main.tf` + `mod/x.tf` for `infra`, and `x.tf` for `infra/mod`. Assert `infra/mod/x.tf` is reported once. As written, the test steers GREEN toward attribution that is wrong under real trivy.
3. **De-dup key.** Use `scanner|file|id|severity|description`, or keep the highest-severity copy on collision, so de-dup can never demote a gating finding.
4. **Cache-dir wording.** "Invoking user's real trivy cache dir" can be read as the passwd home, and then the RED (which requires it under `$HOME`) fails. Say: "`$TRIVY_CACHE_DIR` if set in the invoking env, else the trivy default derived from the invoking `$HOME`/`$XDG_CACHE_HOME`".
5. **Encoding robustness.** Consider `LANG=C.UTF-8` (or adding `LC_ALL`) for the scanners, and byte-level or `errors="replace"` reading in the pragma grep. Both current failure modes are fail-closed but can wedge the gate permanently red. Changing LANG requires updating the `LANG == "C"` assertion.
6. **`ID`/`code` present but empty or non-string.** The spec says "without". Extend it to "missing, empty, or non-string → `<missing>`", plus one parametrized case each.
7. **Pragma and coverage scope.** Either grep every regular file under each trivy scan dir, or declare in §5 that pragmas in non-candidate files under a scan dir are out of scope. Note the Helm `--files` gap (edge 4) for the wiring follow-up.
8. **Hygiene.**
   - Remove the blank line that splits the §2 table (line 27).
   - State F8 vs F4 precedence.
   - Add the `--root`-is-a-regular-file F5 test.
   - r2 MINOR 8 (unknown/missing severity is nongating under `--fail-on CRITICAL`) is still unaddressed.
