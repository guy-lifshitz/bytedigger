## Adversarial edges (not covered by the §4 AC table)

1. **Disk file present but blank, stdout non-blank (decoy).** `_resolve_review_content` returns `raw` when `on_disk.strip()` is empty (L2025-2027). The diagnosis runs on the stdout bytes and `bytes` counts the stdout. But §1 says "if the reviewer already wrote `doc_path` on disk, that file's bytes" -> `os.replace` moves the blank file, so the rejected file does not hold the bytes that were diagnosed and the stdout evidence is lost. (MINOR-2)
2. **Same-run re-entry destroys the evidence.** The first failure moves the reviewer's real disk review into `build-review.rejected.md`. A restart replays the cached `invoke_review_llm` sentinel (`raw_response` is the stdout summary, e.g. `"done"`). `doc_path` is now absent, so the content is `"done"`, it is findingless again, and `write_text("done")` **overwrites** the rejected file that held the real review. (MINOR-3)
3. **Normalisation-event ordering (regression shield).** If GREEN places the check before `_normalize_to_aggregated_findings` (tempting, because `body_empty` is defined on the pre-normalisation text), `review_stdout_normalized_deterministic` stops firing on findingless input. That breaks `test_F7830037_insession_review_normalize.py::test_ac8_normalize_event_emitted` (L439-466) and `test_GH1399_advisory_format_terminal.py::test_ac4_normalization_is_counted_event_for_agent_sdk` (L649-689). Both use the findingless default `"summary only, no header\nVERDICT: PASS"`, and neither is in §5. The spec does not pin the order. (MINOR-5)
4. **Severity blocks under a second `##` heading.** Example: non-conformant `"# Review\n## Findings\n### SEVERITY: HIGH - x\n> a.py:1: y"`. After normalisation, `_doc_section_body` stops at `## Findings`, so (b) = 0, and the review is terminated as `E_REVIEW_EMPTY_FALLBACK` / `no_findings_parsed` even though it contains a HIGH finding. Today it is silently SUSPECT with an empty fix feed, so failing closed is arguably an improvement. But the code name "EMPTY" and the reason will mislead the operator. The rejected file preserves the bytes. (MINOR-6)
5. **Fallback with forwarded `verified_findings`/`suspect_findings` in `prev.data`.** `_persist_fix_feed` prefers these lists over the parse (L2050, L2222-2223). Definition (b) ignores them. No current producer sets them on the fallback path, so the edge is latent. (MINOR-7)
6. **`os.replace`/`write_text`/`unlink` raises `OSError`** on the evidence move. Which code wins is unspecified: `E_REVIEW_WRITE_FAILED` or `E_REVIEW_EMPTY_FALLBACK`. Does the event still fire? Is `doc_path` left in place (and then read as PRESENT by phase 7)? (MINOR-4)

### MAJOR

**MAJOR-1: the definition contradicts AC4b for non-object structured entries. A RED cell cannot be satisfied by a spec-conformant GREEN.**
`extract_structured_findings` (phase_6_review.py:285-303) runs on `_extract_structured_findings_raw`, which drops non-dict entries (findings_extractor.py:91). So `_structured(["CRITICAL: sql injection"])` yields `[]`, and `_derive_fallback_verdict` returns `PASS`. §2 explicitly keeps that ("Empty list `[]` stays `PASS`"). Then §1 (c) (`verdict is SUSPECT`) is false, the content is **not** findingless, and the result is `ok PASS`. §1 "Accepted gap (named)" also says these entries "count as zero", which reads as *not fixed*. Yet §4 AC4b and RED `_AC4B_CELLS[0]` (test L288) require `status=error`, `no_findings_parsed`. GREEN has to invent an unspecified mechanism (a second JSON parse to count raw list entries, or a change to the shared `findings_extractor` that `phase_45_spec` also uses) or fail the cell.
Required (pick one, one-line spec edit):
- (a) In §2, specify "a structured fence whose JSON list is non-empty but contains zero object entries -> `SUSPECT`", and name the mechanism. For example, a phase_6-local raw-length check on the same fence that adds no disk read, with `[]` (literally empty) still `PASS`. Then delete the "count as zero" clause from the accepted gap.
- (b) Keep it as an accepted gap and change the AC4b `non_object_entries` cell to expect `ok PASS` (gap pinned).

### MINOR (advisory)

- **MINOR-1:** In §1 (b), "the SAME bytes" should say **the normalised content** (the argument `_persist_fix_feed` receives).
