# bd#141 item 7 — close gate: "done" claimed while the spec has gone untouched

**Status: r3 (gate r2 APPROVED; r3 adds gate r2 non-blockers G19b/G23)** (r1 gate REJECTED: G19–G22 added, G9/G10/G13/G15/G17/G18 tightened) · **Tier:** 3 (one new engine prod `.py` module, Option D) · **Class:** SYSTEMATIC ·
**Chokepoint:** `close_gate.evaluate` — the one function that turns (transcript entries, spec path,
threshold) into a close-gate verdict; the CLI and every host adapter call it and add nothing but I/O
and the optional latch.
**Side of the seam (decision 2026-07-26 §7.1 / §7.4):** engine. The host keeps what the engine cannot
own: hook registration on Stop (the same seam as `claim_evidence`), resolving which spec belongs to
the live work (active run or manual lot), the off switch, the recovery exemption, the block/log-only
policy and the journal. HAL's adapter and its host-controls registry entry are hal-v2 work (pairs
with hal-v2#2277), not this PR.
**Source:** bd#141 item 7; LifeOS 7.40.4 `ISACloseGate` (harvest `2026-09-30_lifeos-7.40.4-harvest.md`
row "ISACloseGate"); hal-v2#1774 (designed, never shipped — there is no HAL code to port).

## §1 Problem (measured on `618e63c`)

1. BD has no check for a "done" claim made while the spec the work is bound to was not edited for a
   long stretch of tool calls. The class: the agent finishes against its memory of the plan, not the
   plan; the spec's progress/decision record goes stale exactly when the work closes.
2. HAL has none either: hal-v2#1774 is OPEN; its design carried 8 known pitfalls, most of them in the
   host-side run resolver (two live event logs, stale-run window, lock collisions in the Stop
   registry). Putting the resolver in the host and only the decision in the engine removes that
   machinery from the engine entirely.
3. `claim_evidence` (bd#141 item 1) already owns claim detection on the Stop seam (vocabulary,
   clause-scoped negation, downgrade, quoted-text stripping). A second claim detector would drift.

## §2 Design

`engine_py/bytedigger_engine/close_gate.py`, stdlib-only, listed in `core_manifest.json`
`core_modules` and in `mypy-strict-modules.txt`, no Cyrillic, no `HAL_*` env, with a
`if __name__ == "__main__":` CLI. It imports the claim pipeline from
`bytedigger_engine.claim_evidence` (`Vocabulary`, `DEFAULT_VOCABULARY`, `load_vocabulary`,
`slice_current_turn`, `final_assistant_text`, `strip_quoted_text`, `claim_phrase`) and does not
re-implement it.

### op1 — `evaluate(entries, spec_path, threshold=10, vocab=DEFAULT_VOCABULARY, cwd=None) -> Verdict`
`Verdict = {"outcome", "phrase", "calls", "threshold"}`. Steps, first match wins:

1. `spec_path` does not name an existing regular file → `no-spec` (fail-open; the host passes a
   spec only when work is bound to one).
2. `slice_current_turn(entries)` is empty → `no-turn`.
3. `phrase = claim_phrase(strip_quoted_text(final_assistant_text(slice)), vocab)`; `None` →
   `no-claim`.
4. Honest mention: the spec file's basename occurs, case-insensitively, in the **raw** final text
   (backticks included — a spec name is usually written as inline code) → `mentioned`.
5. `calls` = number of main-chain `tool_use` blocks after the last successful spec touch in the
   **whole** transcript (not the turn slice); when the spec was never touched, all main-chain
   `tool_use` blocks. `calls >= threshold` → `fire`, else `clear`.

`phrase` is set from step 3 on, `calls` only in `clear`/`fire`/`latched`; otherwise `None`.
`threshold` is always echoed.

**Main chain:** entries with `isSidechain is True` are dropped before counting (a delegating session
must not reach the threshold through its subagents' calls). Tool-use blocks are the
`{"type": "tool_use"}` items of `assistant` entries' `message.content` lists, in transcript order.

**Spec touch:** a `tool_use` whose `name` is `Edit`, `Write`, `MultiEdit` (path in
`input.file_path`) or `NotebookEdit` (path in `input.notebook_path`), whose path resolves to the
spec, and whose paired `tool_result` (matched by `tool_use_id`) does not carry `is_error: true`. A
touch with no paired result counts as a touch. `Read`, `Grep`, `Bash` never count (a shell edit of
the spec is a declared blind spot, §2 divergences).
**Path resolution:** a relative tool path is joined to `cwd` (default `os.getcwd()`); both sides go
through `os.path.realpath` (macOS `/tmp` → `/private/tmp`, symlinked worktrees).

### op2 — latch (once per run)
`latch(state_dir, run_id) -> bool`: creates `state_dir` (parents included) and the file
`close-gate-<sha256(run_id.encode("utf-8")).hexdigest()[:16]>.latch` with `O_CREAT | O_EXCL`; returns True when this
call created it, False only when the latch **file** open raised `FileExistsError`. The run id never reaches the path verbatim. No lock
is held across the hook (lesson R3-04/R3-06 of hal-v2#1747: a held lock silences the gate forever on
a timeout kill); the exclusive create is the whole mechanism. Any other `OSError` — including a
`FileExistsError` from creating `state_dir` itself (a regular file sits at that path) — → returns True
(fail toward reporting: the verdict stays `fire`, the host decides).
Only a `fire` verdict consults the latch; a False return turns it into `latched`.

### op3 — CLI
`python -m bytedigger_engine.close_gate --transcript P --spec S [--threshold N] [--vocab V]
[--cwd D] [--state-dir D --run-id R]` prints one JSON line (`sort_keys=True`) with exactly the keys
`calls, outcome, phrase, threshold`, exits 0. Exit 2 with a message on stderr and nothing on stdout
for: a missing `--transcript` or `--spec`; `--threshold` not an integer ≥ 1; exactly one of
`--state-dir` / `--run-id`; a bad `--vocab` (`ValueError` from `load_vocabulary`). An unreadable
transcript is `no-turn` with exit 0; non-JSON lines are skipped (same reader rules as
`claim_evidence.evaluate_transcript`).

### Declared divergences from LifeOS ISACloseGate / hal-v2#1774
Stateless: the call count is derived from the transcript at Stop, not kept by a PostToolUse
counter (no per-session state file, nothing to drift or lose on a crashed hook). The spec path is an
input; resolving the active run / manual lot spec is host work. No env vars in the engine
(`CLOSEGATE_OFF`, `CLOSEGATE_THRESHOLD` become host adapter policy mapped onto `--threshold` / not
calling the CLI). No recovery exemption in the engine (the host knows recovery). Default threshold
10 (LifeOS value). A spec edited through `Bash` (`sed -i`, heredoc) is not seen as a touch.
A spec edited by a subagent (sidechain) is not a touch either: the sidechain filter drops those
entries whole; the main chain's own count still decides. An empty final assistant text is
`no-claim` here (a real user entry exists, nothing was claimed), where `claim_evidence` reports
`no-turn`. Touch matching is `os.path.realpath` equality, so a path that differs from the spec only
in letter case on a case-insensitive volume is not a touch (fail toward reporting). The mention
exemption is a case-insensitive substring match of the spec basename in the raw final text.

## §5 Acceptance criteria

Fixtures are JSONL transcripts written under `tmp_path`; the spec is a real file under `tmp_path`.
"N calls" = N main-chain `tool_use` blocks (e.g. `Bash`) each paired with a non-error result.
Every CLI AC runs `python -m bytedigger_engine.close_gate` as a real subprocess.

| AC | Check |
|---|---|
| G1 | spec never touched, 10 calls, final text "Done." → `fire`, `calls == 10`, `phrase == "Done"`, `threshold == 10` |
| G2 | same with 9 calls → `clear`, `calls == 9` (boundary: `>=`) |
| G3 | 12 calls where call 5 is a successful `Edit` of the spec → `clear`, `calls == 7`; same with the `Edit` at call 2 → `fire`, `calls == 10` (the touch itself is not counted) |
| G4 | each of `Write`, `MultiEdit` (`file_path`) and `NotebookEdit` (`notebook_path`) at call 2 of 12 resets the count like G3 (`calls == 10`); a `Read` of the spec at call 11 does not (`calls` stays 10) |
| G5 | path resolution: a relative `file_path` resolved against `cwd=` matches; a spec reached through a symlinked directory matches the real path the tool used (and vice versa) |
| G6 | an `Edit` of the spec whose paired `tool_result` has `is_error: true` is not a touch (count continues through it); an `Edit` of another file is not a touch |
| G7 | 6 main-chain calls + 6 `isSidechain: true` calls → `clear`, `calls == 6` |
| G8 | whole transcript: 6 calls before the last real user entry, 4 after → `fire`, `calls == 10` |
| G9 | no claim ("Still working on it.") → `no-claim`, `calls is None`; negated claim ("Not done yet.") → `no-claim`; downgrade ("Done, except 1 failing test.") → `no-claim`; claim only inside a fenced block → `no-claim` |
| G10 | final text "Done — updated `spec.md` progress." (spec basename `spec.md`) with 10 untouched calls → `mentioned`; "Done — see SPEC.MD" → `mentioned`; "Still working on spec.md." with 10 untouched calls → `no-claim` (claim check runs before the mention check) |
| G11 | missing transcript file / empty file / no real user entry → `no-turn` |
| G12 | `spec_path` that does not exist, or names a directory → `no-spec`, before the transcript is read (a missing transcript with a missing spec is `no-spec`) |
| G13 | `vocab` extended with claim `shipped` (via `--vocab` JSON file) → "Shipped." fires with `phrase == "Shipped"` (matched text as written); without it → `no-claim` |
