## Findings

1. **[MAJOR] F1: `test_ac27_driver_is_executable_in_git_and_has_shebang` fails deterministically in the clean-room `git archive` lane.**
   - Location: `test_bd166_one_sided_predicate.py:775-782`.
   - It runs `git ls-files -s one-sided-predicate-lint.py` in `_REPO_ROOT` without checking that `.git` exists. In the archive tree, git either errors out (stdout empty) or walks up to an unrelated enclosing repo. Either way `listed.stdout.startswith("100755 ")` is False, so the test is red in that lane whatever GREEN does.
   - Both sibling precedents guard this exact case: bd66 AC15 uses `_corpus_is_archive_tree()` at L374/L1562, and bd79 AC10 uses `if not (_REPO_ROOT / ".git").exists(): pytest.skip(...)` at L294.
   - This is a RED that GREEN cannot satisfy in one of the lanes the suite ships to, so it blocks.
   - Fix: run the shebang assertion and a working-tree exec-bit assertion (`os.stat(_DRIVER).st_mode & 0o111`) unconditionally. `git archive` preserves the mode in the tar, so these are meaningful in both lanes. Then, before the ls-files call, add `if not (_REPO_ROOT / ".git").exists(): pytest.skip("no .git (clean-room ships via git archive); index mode has no corpus here")`. Also assert `listed.returncode == 0` so a git error is not reported as a mode mismatch. Add the archive-lane skip to §3 AC27 in the spec.

2. **[MINOR] F2: the AC27 control is one-sided.**
   - Location: `test_bd166_one_sided_predicate.py:764-772`.
   - It asserts only `lines == []`. A driver that crashes or exits 2 on the controlled file produces a DRIVER-ERROR line and rc 1, and the control still passes. The dirty side and bd66 cover crashes in general, but not a crash that depends on the input.
   - Fix: also assert `proc.returncode == 0`. The text lane exits 0 on ASCII content, so this is satisfiable. Alternatively, assert that no line contains `lint=one-sided-predicate-lint`.

3. **[MINOR] F3: stale docstring in the bd66 AC7 edit.**
   - The sentence "Pre-GREEN: FAIL — precommit_lints has no DECLARED_ABSENT attribute..." no longer describes why the test fails.
   - Fix: reword it to say that pre-GREEN, `one-sided-predicate-lint` is declared absent and has no driver, so `on_disk == []` fails the pin.

r1's planned concern about the VIOLATION-line `lint=` format is withdrawn: prod emits `lint={name}` (`precommit_enforce.py:192`).

M2 decision: I accept the parity pin `==` in B3 as a declared, test-enforced compromise. It is not ideal: there are still two literals, but drift fails B3 at once.
