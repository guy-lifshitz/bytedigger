## Adversarial edges (not covered by any §3 AC)

- **E1 relative explicit source:** `git_cwd: "repo"` (relative) resolves to `cfg_git_cwd_relative`, which is ambient (git_cwd.py:59, :42). By spec:29 it must yield `ambient-skip`. AC14 drives only the `cwd` source.
- **E2 git_cwd is a subdirectory of the repo:** op2 passes the resolved git cwd as `toplevel`, but `compute_state_hash` uses pathspec `.` (preflight.py:209). From a subdir it hashes only that subtree, so a receipt written at the toplevel reads as `stale` even when the tree is unchanged. Normalise with `rev-parse --show-toplevel` inside `receipt_rung`, or state the limit. The bias is toward "no evidence", not false evidence.
- **E3 ladder_table red_step type:** a dict with string `status` but `red_step` of `5` or `["cite"]` is not specified as kept, coerced or skipped. A non-hashable `red_step` would break grouping, which contradicts "never raises".
- **E4 phase-mismatch receipt that was red:** a `green` receipt with `ok:false`, read for `red`, gives status `missing`. spec:24 says `red_step` is `None` for missing, but also says it is "read from the receipt". AC2 only covers an ok green receipt.
- **E5 below-cap reject row:** AC9b and AC12 drive only the terminal `cycle == cap` arm. The below-cap arm (phase_5_implement.py:7529-7531) goes through the same helper, so the risk is low. Still, no row assertion exists for cycle 1 of 2.

## Findings

1. **MAJOR-A**: AC10 / the L16 edit contradict op2's ambient rule and AC14.
   - Where: spec:71 vs spec:29 and :68; test_bd141_check_ladder.py:544-545 vs test_bd218_s1_preflight_rung.py:619, :625.
   - L16's harness (test_bd141_check_ladder.py:454-471) has no `git_cwd`, `current_worktree_path` or `scratchpad_dir`, so the source resolves to `"cwd"` (git_cwd.py:93-95), which is ambient. op2 then emits `ambient-skip` and adds **no** `extra_data["preflight"]`.
   - So the edited L16 key set fails for all 7 params, while AC14 asserts the key is absent on the same harness shape. No GREEN satisfies both. r1 MAJOR-4 is therefore not closed.
   - **Fix:** revert the L16 edit (the unedited L16 already passes under ambient-skip, since both baseline and drive lack the key). Restate AC10 as "`test_bd141_check_ladder.py` passes unchanged (its harness is ambient → ambient-skip, no record)". Remove the one-key edit from §4 (spec:76).
2. **MINOR-1**: op2b's premise is wrong for `_verify_validation_citations`.
   - Where: spec:38, spec:76.
   - It delegates to `helper.verify_validation_doc`, which already forwards `dict(prev.data)` on every return path (helper.py:479, :491-620). Only `_write_validation_doc` (phase_5_implement.py:7206-7223) needs the added key.
   - Reword so GREEN does not add a redundant wrapper. `helper.py` is not in §4 scope, so it must not be edited.
3. **MINOR-2**: AC4/AC5 depend on how phase 5 binds `receipt_rung` (test:290-291, :312-313, :323). Add a line to spec op2 saying phase 5 calls it as `preflight.receipt_rung(...)` (module attribute), or as a module-level name `receipt_rung`.
4. **MINOR-3**: Spec post-conditions without an assertion:
   - the `error` record `{"status":"error","red_step":None}` (spec:35; AC4 test:292-296)
   - no record on `config-error` (spec:33; AC6 test:336-340)
   - `cycle` in the `ambient-skip` event (test:621-622)
5. **MINOR-4**: Edges E1 (relative explicit source, which is ambient) and E2 (subdir git_cwd, which reads as false `stale`) are unspecified and untested.
6. **MINOR-5**: The tier/scope line (spec:3) understates the change. It touches four production files and four `phase_5_implement.py` functions (spec:75-76); classify accordingly.
7. **MINOR-6**: The MAJOR-5 reading rule (spec:43-44) is prose only (Principle C). `ladder_table` returns `stale`/`missing`/`none` groups with the same weight as `fresh`/`red`. Consider an `informative: bool` field per group, or state the enforcement layer (the review of the gate-replacement PR).
8. **MINOR-7**: The RED docstring uses stale labels: "ACs AC1-AC9c" and "AC9 (bd141 / bd164 siblings...)" (test:3, :14). They should read AC1-AC16 and AC10.
9. **MINOR-8**: `findings_heads` has no defined source (spec:42): the first element of each row's `detail.findings_head`, or all heads flattened, which order, and whether to dedup. The RED accepts any 3-subset (test:510-511, :650).
