- E4 (timeout): ls-files hits rc 124 (bounded_run timeout). This falls under rc≠0 → event + False. It is covered by AC4c's logic, but no test uses the 124 value.

## Findings
1. MINOR: AC3's test does not assert that rc 1 emits no event. §2.1 says rc 1 → False with no event, so a GREEN that logs on every "differs" (noise on every dirty cycle) would pass. Suggest adding `captured == []` to AC3.
2. MINOR: AC5(c) is close to a tautology. `delta_verdict(x, 0)` never blocks for x in {None, 0}, so only `baseline in (None, 0)` has any force. It is not tied to `_verify_green_typecheck`. The spec allows this ("whichever the test fixture reaches"), so it is advisory only.
3. MINOR: The AC5(a) docstring says mypy is canned "for the live tree". The helper returns 0 at L4862 before any mypy call, so the canned output is never used. The assertion is still valid; only the comment overclaims.
4. MINOR: The AC6 guard only catches calls made through `llm_subprocess.invoke_llm_subprocess` as a module attribute. A direct-import alias would get past it. That is acceptable, because the design constraint is structural (plain git, no model step).
5. MINOR: No test for an exception raised from the ls-files read (§2.3). The diff-raise test (AC4a) covers the common `except`. Optional AC4(d).

No MAJOR findings. The spec matches the code. The RED forces the fix through the one real chokepoint, and the issue's AC2 cases (block, ok, identical, git failure) each have a test. On the design constraints: the check is deterministic, makes no provider call, and degrades to False/worktree instead of crashing.
