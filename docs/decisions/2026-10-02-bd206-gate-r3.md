### MINOR

**m-1. AC7 `passed` cases require `violations == ()`, but the spec does not require the payloads to be clean on R3.1, R3.3, R3.5 and R3.6.**
- **Evidence:** `_r31` returns a violation when `prompt_sha256` is missing (`bd_l3.py:110-111`), and `check_bd_l3` collects violations across all requirements (`:274-279`). A bare payload of `{invocation_id, output_sha256: null, injections:[role]}` therefore gives `violations == ("R3.1: ...",)`. That RED could never go green, and GREEN must not edit tests (§1s).
- **Fix (RED):** build every AC7 payload, including the attestation a `passed` case names, from the `test_bd28` `_event` shape (`test_bd28_bd_l3_checker.py:50-73`), which already has a valid `prompt_sha256`. Alternatively, narrow the assertion to "no `R3.2:` violation".

**m-2. The AC7 no-run case can be vacuous, and it contradicts "every AC7 fixture sets `run_id` explicitly".**
- **Evidence:** if the named attestation carries a run (for example `"A"`) and only the naming event lacks one, a GREEN that lets `None` match `None` still fails the lookup. The case then passes for the wrong reason, and the §2.6 "never resolves" rule is never exercised.
- **Fix (RED):** in this one case, both the attestation and the naming event lack `run_id` (key absent, harness shape), and the block names that attestation's real id and step. Expected: `failed`. Every other case sets `run_id`.

**m-3. The §2.2 clause "forwarded only when every group with fixes has a valid id" has no AC.**
- **Evidence:** this is the Step 2 inverse gap. A GREEN that forwards an id-less group as `invocation:invoke_satisfaction_llm:None` produces blocks whose join equals the inlined string. The chokepoint attests them, and the checker would report R3.2 `failed` on a real log. No AC1-AC3 case catches this.
- **Fix (RED):** add an AC2 sub-case, adversarial edge 1. Expected: no `findings_blocks` key, no class-M block, dispatch ok.
