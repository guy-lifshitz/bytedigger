## Findings

### MAJOR

**F-1. AC7's two new `passed` cases cannot be R3.2 `passed` under §2.6 and the current `_r32`. Making them pass as written requires an inverted oracle.**
- **The cases.** AC7 asserts "R3.2 `passed` **and** `violations == ()`" for `{"invocation_id": <valid>, "output_sha256": null}` and for "a pre-#152 payload without both keys".
- **Why they get `not-checked`.** `_r32` returns `(False, None)`, which means not observed, when `injections` is missing or empty (`bd_l3.py:142-148`). `test_bd28_bd_l3_checker.py:57` pins exactly this: "R3.2 with no injections gives not-checked". §2.6 makes a payload R3.2-observed only on a form violation ("else an `R3.2:` violation, and the payload counts as R3.2-observed"). Neither case says it carries an injection block. As literally specified, both get R3.2 `not-checked` (`bd_l3.py:288-289`).
- **The danger.** A RED that writes the bare payloads leaves GREEN one way to go green: count form-valid `invocation_id`/`output_sha256` as an R3.2 observation. Every real post-#152 attestation carries `invocation_id`, so that GREEN reports R3.2 `passed` on logs with zero injections. That converts absence of evidence into conformance, which is what `bd_l3.py:9-22` forbids. No sibling catches it, because `test_bd28`'s fixtures carry no `invocation_id`.
- **Fix, two sentences:**
  - **AC7:** "Every `passed`-case payload also carries one attributed non-`invocation:` block (the `test_bd28` `_event` shape: `{"source_id": "role-template", "sha256": "sha256:" + "0"*64}`)."
  - **§2.6:** "Form-valid `invocation_id`/`output_sha256` do not by themselves make R3.2 observed; only a block or a form violation does."
  - Add adversarial edge 1 to AC7 as a case that expects `not-checked`.

### MINOR

**F-2. §2.6 says `event["run_id"]` (a KeyError form) and leaves the `None` run key unspecified.** Harness-shape events have no `run_id` key (`test_bd28_bd_l3_checker.py:73` returns `{"type", "payload"}`). A literal `event["run_id"]` crashes every sibling that builds them. With `.get`, two run-less events share the key `None`, and so count as "same run". **Fix:** write `event.get("run_id")` and state the rule for `None`. Recommended: a block in an event whose `run_id` is `None` never resolves (`R3.2` failed), which stays consistent with "same run" in AUTHORSHIP_SPEC `:514-515`. Have AC7's fixtures set `run_id` explicitly on every event.

**F-3. §2.1's "With no current run nothing is written" can be read as suppressing the sidecar.** C834481A requires `last_findings.json` to be written on every satisfaction FAIL (`phase_6_review.py:3635-3683`). **Fix:** "With no current run no provenance file is written; the sidecar is still written, with `run_id: null` and `source_id: null`; nothing is declared."

**F-4. AC5 does not separate `ctx.session_id` from the telemetry run id.** A GREEN that uses `ctx.session_id` both when it writes the sidecar `run_id` and when it compares in `_build_review_prompt` passes AC5 whenever the fixture makes the two equal. AC4 and AC6 cover only the writer and the verifier. **Fix:** add AC5: "the fixture sets `ctx.session_id` ≠ the telemetry run id, and the sidecar's `run_id` equals the telemetry run id".
