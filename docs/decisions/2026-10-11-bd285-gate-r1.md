## Adversarial edges (not covered by the AC table)

1. Run the script with `cwd` != repo root (CI cwd is `engine_py`; script is `../scripts/...`; default workflow `.github/workflows/ci.yml` is then not found -> permanent "could not run" warning, feature silently inert).
2. Fixture workflow with its own `pytest` job at a different ceiling (e.g. 10 min) plus a decoy earlier job with another `timeout-minutes` and a step-level `timeout-minutes` inside the pytest job: ceiling must be job-level of the named job only.
3. Ceiling values: `timeout-minutes: "30"`, `30 # comment`, `${{ vars.X }}`, `0`, negative, `30.5`: must warn "could not run", exit 0. `0` risks `ZeroDivisionError` (exit 1) and breaks the "exit 0 in every case" claim.
4. `--duration-sec abc` / missing flag / negative: spec says exit 0; an `argparse type=int` exits 2.
5. `--workflow` pointing to a nonexistent file or a directory (OSError path).
6. Switch `1`, empty string, `" 0 "`, `NO`, `off`: only `0` and `False` are tested; "any set value disables" passes AC3.
7. `PYTEST_JOB_T0` unset in the step: bash arithmetic treats unset as 0, so duration = epoch (~1.7e9 s) and a bogus 100000% warning fires instead of "could not run".
8. Warning percentage correctness: RED only checks that `%` appears; `70.1` vs `0.7` vs `7006` pass.
9. Boundary one second below (1259) and integer-ceiling variants (25 min = 1500 -> 1050): float equality only exercised at 1800.
10. Both conditions at once: switch `0` with missing workflow (order of a vs b).

## Findings

1. **F1 MAJOR** - Default `--workflow` is cwd-relative, but the job runs under `working-directory: engine_py`. Spec does not say how the script finds `ci.yml` from there (script-relative resolution, `GITHUB_WORKSPACE`, or an explicit `--workflow ../.github/...` in the step). All RED runs use `cwd=ROOT`, so the feature can ship permanently inert and every test stays green. Fix: spec pins script-relative default resolution (`Path(__file__).resolve().parent.parent / ".github/workflows/ci.yml"`) and RED adds a test with `cwd=tmp_path` that expects the real ceiling in the warning.
2. **F2 MAJOR** - AC5 wiring pin is too weak for a "reachability" AC: no check that the T0 step exists/writes `PYTEST_JOB_T0` to `GITHUB_ENV` before the suite, that the headroom step is after the suite, that it passes `--duration-sec` derived from `PYTEST_JOB_T0`, or that the script path resolves from `engine_py` (`../scripts/ci_pytest_headroom.py`). A headroom step placed before the suite, with a literal duration, passes. Fix: parse with `yaml.safe_load`, assert step indices T0 < suite < headroom, `PYTEST_JOB_T0` in both run texts, `continue-on-error is True`, script path string.
3. **F3 MAJOR** - Principle 2 (no second copy of the ceiling) is unpinned: a script that hardcodes 1800 passes all 7 tests. Fix: add a RED using a tmp workflow with a `pytest` job at a different `timeout-minutes` (and a decoy job/step-level value) and assert that its ceiling seconds appear in the warning at 70%+1 s of that ceiling.
4. **F4 MAJOR** - The spec claims "exit 0 in every case" for missing file, missing job, non-integer ceiling and non-numeric duration, but only missing-job is tested. `argparse(type=int)` (exit 2) and a `timeout-minutes: 0` division are likely first-implementation failures that would make the step fail (masked only by `continue-on-error`, which turns the "never red" guarantee into a hidden red annotation). Fix: parametrized RED over edges 3, 4, 5 above asserting exit 0 and a `::warning::`.
5. **F5 MINOR** - Step-level `timeout-minutes` and quoted/commented values: define the line-scan contract (job-level key at job indentation only, trailing `# comment` stripped or rejected) in the spec, since a line scan without yaml cannot tell them apart implicitly. Note pyyaml IS installed in the job before the headroom step, so the "no yaml import" rationale is about the script's stock-python promise only; acceptable but state the contract.
6. **F6 MINOR** - Use integer arithmetic for the boundary (`N * 10 > C * 7`) rather than float ratio; today it works for 1800 but the spec's "strictly greater than 0.70" is brittle against percent-rounding in the message (`70%` printed for 70.4%).
7. **F7 MINOR** - State precedence when switch is off and the ceiling is unreadable (suggest: switch wins, per "prints nothing starting with ::warning::"), and pin it.
8. **F8 MINOR** - RED's `_ceiling_sec` regex fails on a trailing comment on the `timeout-minutes` line; either note in spec ("no trailing comment on that line") or loosen the regex, otherwise GREEN may trip RED by a natural edit.
9. **F9 MINOR** - Unset `PYTEST_JOB_T0` yields a false ~1.7e9 s warning (bash arithmetic); spec should require `${PYTEST_JOB_T0:?}` or an explicit guard, and the script should treat a duration larger than the ceiling x 100 / negative as "could not run". Also switch values `1`/empty/`NO`/`off` untested.
