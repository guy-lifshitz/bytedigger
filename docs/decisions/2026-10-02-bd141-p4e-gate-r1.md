## Focus answers

1. **Observation choice.** Last root `assistant.message.model`, falling back to `system/init.model`, skipping values that start with `<`.
   This is the right *source* given the stream-json vocabulary the engine already parses. `message.model` is the API's answer and
   init is the harness's selection. `result.modelUsage` would be wrong, because it lists the haiku that the CLI uses internally.
   `<synthetic>` is the CLI's placeholder on API-error and no-response turns, and skipping it is correct. The engine never passes
   `--fallback-model` (I grepped `engine_py/bytedigger_engine`: 0 hits), so a CLI fallback swap is not a flow the engine triggers.
   However, the spec freezes these shapes from memory, not from a captured transcript. See F1.
2. **Blast radius.**
   - Aliases with no recognised family (`default`, `opusplan`, `opus[1m]`, ARN inference profiles, non-Claude proxies) give
     a family of None. That means not-checked, which is safe.
   - The tier rebind happens before `_dispatch_backend` (:1734-1749), and the argv is built from that same `model`, so the pin
     equals the dispatched value. Safe.
   - **The risk that has not been measured is `fable`.** `decorrelated_verifier` is `["fable", "opus"]` (`model_config.py:39`). Nobody
     has shown what `message.model` a `--model fable` run reports. If it is an id that `_is_fable_model` does not anchor,
     the result is merely not-checked. If it is an opus-family id, every verifier run becomes a non-recoverable failure. See F1.
   - Operator remaps (`ANTHROPIC_DEFAULT_OPUS_MODEL` set to a sonnet id) would now hard-fail. That is the intended R3.3 detection, but §7 should say so.
   - **Provider placement.** `ProviderSpec` has no observed-model slot. `_pin_mismatch_refusal` already uses `_claude_model_family`
     directly, not `get_provider().model_family`. All transcript extractors (`_observed_tools_from_events`, `_written_paths_from_events`,
     `_mcp_losses_from_events`) live in `llm_subprocess`. Putting the new one beside them is consistent. A provider slot would be the right
     long-term home but would widen the frozen `ProviderSpec` dataclass, so it should not be part of this lot. Advisory F8.
3. **Seam.** Satisfies §1l (see Step 3). AC3 is the one AC whose named teeth fail (F2).
4. **§1a siblings.**
   - I grepped `engine_py/tests` for stream-json fixtures that carry `"model"` on an assistant/init event (single-line and dict forms,
     plus `*.jsonl`/`*.ndjson`/`*.sh`). The only hits are in the new RED file.
   - `test_bd82_role_backend_effort.py:462/606` is an anthropic-api HTTP body. `test_25e75663...:576` is an in-session artifact.
   - `test_bd141_check_ladder.py:522` asserts exact `data` but uses a fake gate, not `_invoke_subprocess`.
   - `test_bd71::test_ac7` scans `reference_backends/` only, so it is unaffected.
   - No existing test should flip to `E_MODEL_PIN_MISMATCH`. The RED report must still list this grep, per §5.
5. **AC7, key present with None.** This is the right contract. It matches `observed_tools` (always written on success) and the in-session
   producer (`result_obj.get("dispatched_model")`, which may be None). Every consumer reads through `_observed` / `.get`. I grepped prod for
   `"observed_model" in`: 0 hits. So present-None and absent are observably identical to the chokepoint and the attestation, and
   "always written" gives a stronger test. Keep it.

## Adversarial edges (not covered by §3)

- **E1, straggler-ok shadow.** On the straggler branch (:2046-2053), `extra_data={"observed_model": "haiku"}` with `status="ok"`
  reaches `_pin_mismatch_refusal` as a reported value, so a caller key is adjudicated as an observation. No current
  caller passes this key. The siblings have the same gap. Not tested.
- **E2, depth-1 subagent with a real spawn.** A root `Agent`/`Task` tool_use with id X, followed by a haiku assistant event with
  `parent_tool_use_id == X` as the final event. A root-only extractor gives the root value. A `_manifest_eligible_events` walk gives haiku and
  a false `E_MODEL_PIN_MISMATCH`. The current AC3 fixtures cannot see the difference (F2).
- **E3, `parent_tool_use_id: ""`.** `_is_root_stream_event` treats an empty string as root. Not tested. Low risk.
- **E4, multiple / subagent init events.** If two root inits carry different models and there is no assistant event, the spec does not
  define which wins. A non-root init (parent set) should be excluded under "root only", but no test covers it.
- **E5, cross-backend divergence.** On the same step, the agent-sdk producer (`agent_sdk.py:116-118`) takes the last `model` of *any*
  message: no root filter and no `<` skip. A trailing `<synthetic>` there gives not-checked, and a trailing subagent haiku gives a refusal.
  After a GH1169 fallback, the claude-subprocess verdict for the same work can differ. This lot does not cause it, but "R3.3 observable on
  both paths" now means two different semantics.

## VERDICT: REJECTED

1. **F1 (MAJOR): no live baseline for a behaviour-changing, non-recoverable AC (§1b / "verify the instrument").**
   - **Problem:** §2.1 freezes the event shapes (`system/init.model`, `assistant.message.model`, `parent_tool_use_id`, `<synthetic>`)
     without a captured real `claude -p --output-format stream-json --verbose` transcript. §7 also does not enumerate what the production
     model strings report.
   - **Required before freeze:** one real transcript per configured alias (`opus`, `sonnet`, `haiku`, `fable`, and the in-repo
     `models.json` values). Record a table in §1: dispatched alias, init.model, last root message.model,
     `_claude_model_family` of each, and the verdict. Include at least one real `<synthetic>` occurrence, or a cited CLI source for it, and
     one `--forward-subagent-text` run that shows that subagent events carry a non-empty `parent_tool_use_id`.
   - **Why it blocks:** `fable` (`decorrelated_verifier`) is the concrete case where a wrong guess turns every verifier dispatch into
     `E_MODEL_PIN_MISMATCH` with `recoverable=False`.
2. **F2 (MAJOR): AC3's stated teeth are false.**
   - **Problem:** §4 says "AC3 goes red if the extractor walks `_manifest_eligible_events`". In every AC3 fixture,
     `parent="toolu_agent1"` is never spawned by a root `Agent`/`Task` tool_use. `_manifest_eligible_events` (:3005-3013) therefore drops
     those events as well (fail-closed), and both traversals return the same value. The named mutation stays green.
   - **Why it matters:** copying the sibling `_observed_tools_from_events` traversal is the most likely GREEN mistake.
   - **Fix:** add a root assistant event carrying `{"type":"tool_use","name":"Agent","id":"toolu_agent1"}` (with no `message.model`, or with
     the root model) before the subagent event in `test_ac3_subagent_events_are_excluded` and
     `test_ac3_root_after_subagent_still_wins...`. Then root-only gives A / ROOT and depth-1 gives SUB.
3. **F3 (MINOR):** the RED file has 13 tests, not 12 (the RED report count). `HAIKU_MODEL` is unused.
4. **F4 (MINOR):** correct "default headless path" in the header and §1.3. The default is agent-sdk (:83). claude-subprocess is the
   explicit, default-fallback and GH1169 path.
5. **F5 (MINOR):** state in §2.2 or §6 that the straggler synthetic-ok branch is out of scope (E1), or reserve the name there too.
6. **F6 (MINOR):** specify which init wins when there are several, and that init must also be root (E4). One extractor test would pin this.
7. **F7 (MINOR):** §4 should name the reddening change for AC4 and AC6 (Step 3 lists candidates).
8. **F8 (MINOR, advisory):** keep the extractor in `llm_subprocess` beside its siblings for this lot. Open a follow-up for a
   `ProviderSpec.observed_model` slot, and for aligning the agent-sdk accumulator with root-only and `<`-skip (E5).
