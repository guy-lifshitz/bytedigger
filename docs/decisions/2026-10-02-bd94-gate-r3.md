## Adversarial edges

Edges not covered by any §3 AC:

1. **Collapsed untracked dir hiding nested state.** Without `--untracked-files=all`, porcelain reports `?? newpkg/` when `newpkg/` holds user files plus `newpkg/.bytedigger/`.
   - R1 does not match `newpkg/`, so the self-heal `git add -- newpkg/` stages `newpkg/.bytedigger/*`.
   - If `newpkg/` holds only `.bytedigger/`, the guard counts it as dirty but the tail has nothing user-owned to commit. The result is E_FIX_UNCOMMITTED_CHANGES or a failed commit.
   - The checkpoint is immune because it uses pathspecs.
2. **All-state manifest through `_filter_gitignored_paths`.** After the R1 drop the list is empty, so `git check-ignore --` with no paths returns rc 128. The degrade branch then returns `list(paths)`, the ORIGINAL list, and the state leaks back.
3. **Rename with a state source in the tail.** `ln[3:]` yields `.bytedigger/x -> src/y.py`, and R1 drops the whole entry, including the user's destination file. This is no regression versus today (the arrow form was already mis-parsed). Declare it as a follow-up.
4. **Lint blind spot.** A future git add or status through `_git(repo, [list])` (readiness, git_blob) or `_git_text` escapes the inventory.
5. **Leaked `GIT_DIR` / `GIT_WORK_TREE` / `GIT_INDEX_FILE` from an outer process**, e.g. pytest run from a git hook.
   - The githooks/pre-commit shim runs python under git, which exports GIT_INDEX_FILE and can export GIT_DIR.
   - The real-git tests would then read or commit against the outer repo.
