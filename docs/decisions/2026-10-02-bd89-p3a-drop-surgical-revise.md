## §2 Design: delete, don't flag

Row 3 says drop. A kept-behind-a-flag surgical path would be a new default-off flag, which row 7 forbids. Both existing kill-switches are deleted with their branches. Nothing is kept.

What cycle 2 does afterwards:

- **Writer:** the delta retry. `_build_spec_prompt` at cycle>=2 with structured findings builds `build_delta_retry_prompt` (compact header, restricted-writer body, per-finding checklist) plus the high-binding block. `_invoke_spec_llm` always unlinks the stale spec file and grants `["Read", "Write", "Glob"]`; the writer writes the FULL revised body to `specs/build-spec.md`; `_write_spec_doc` takes the body from the file (`_resolve_spec_source`), writes the canonical and the versioned cycle-2 copy. This is the lane that already ran whenever the patches failed. Without structured findings the scaffold lane (c)/(d) still applies; all remaining lanes write a full body.
- **Reviewer:** the cycle-1 reviewer prompt, unchanged, for every cycle. The reviewer reads the spec by path, may raise new findings, and emits the usual `## Verdict` and `## Scores`. The score downgrade now applies to cycle 2 (GAP-3).
- **Verdict parsing** is untouched. `_write_review_doc_cycle2_result` tries the per-finding parser first and returns `None` (UNPARSED) on a free-form review, which then takes the classic cycle-1 verdict path. A full-prompt cycle-2 review always takes that fall-through (AC9 pins it). Deleting the now-producerless per-finding consumer is open question 1.

Ops:

- **op1 (plugin):** delete `surgical_revise.py`, `delta_reviewer_prompt.py`, `restricted_reviewer_prompt.py`; remove their exports from `checklist_convergence/__init__.py` (keep `Finding`, the four `extract_*`, `build_writer_prompt`, `ReviewerVerdict`, `parse_per_finding_verdicts`).
- **op2 (phase_45_spec):** remove the imports (`_restricted_reviewer_prompt`, the surgical trio, `build_delta_reviewer_prompt`, `extract_affected_sections`); in `_build_spec_prompt` delete the surgical branch and the `surgical_fallback_flag` / `surgical_enabled` reads, keep the delta branch (its `spec_prompt_high_binding` event now only carries `path` in `{"delta", "scaffold"}`); in `_invoke_spec_llm` delete `is_surgical` and always unlink plus `["Read", "Write", "Glob"]`; in `_write_spec_doc` delete the surgical block; delete `_load_surgical_delta`; in `_build_review_prompt` delete the cycle>=2 restricted/delta block so cycle>=2 falls through to the full prompt; reword every comment that names the dropped lanes.
- **op3 (flags):** delete `HAL_SURGICAL_REVISE` and `HAL_DELTA_REREVIEW` from `flags_catalog.FLAGS`. An operator who still exports either gets no effect (the env var is simply never read).
- **op4 (lint list):** delete `mypy-strict-modules.txt:36`.
- **op5 (md/docs):** `phases/phase-45-spec.md:178` is replaced by "The cycle-2 review is the full reviewer prompt, the same as cycle 1; the score downgrade applies to it." `docs/configuration.md:271-273` becomes "Delta-retry prompts and the restricted spec writer carry no template and do not read the file." (the cycle-2 reviewer now reads it, GAP-6). `CHANGELOG.md` gets one entry (doc dance).
- **op6 (tests):** retire, edit or re-point per §5.

Provider principles. P3a adds no LLM call and no provider dependency; it removes a path that depended on the model returning machine-parseable JSON. Cycle 2 on a subscription CLI or on an API key now behaves identically to cycle 1 and to the former fallback. Degrade, don't fail: the writer lane no longer has a parse-or-retry step that costs an extra paid call. Deterministic-first: nothing changes in the deterministic gates that follow the writer. All new tests are deterministic and run with no `claude` on PATH and no API key (AC14).

### GAP list: behavior that exists only in the dropped code (not ported; file as follow-ups)

- **GAP-1: output economics.** The cycle-2 writer now emits the full body instead of a patch array. Input size is unchanged (the surgical prompt embedded the full spec too). Cost: output tokens on an API key, latency on a subscription CLI. The delta lane was already the fallback of every failed patch, and the surgical lane's own failure retry paid for both calls.
- **GAP-2: byte-stability of untouched sections.** `apply_surgical_patches` guaranteed everything outside the patched fragments was byte-identical (`test_gh592` ac2). A full rewrite can drift unrelated sections. Backstop that stays: the deterministic spec gates re-run on every cycle (cite lint, coverage, scope inverse, AC DSL, reality), and the reviewer reads the whole spec. No equivalent byte check is ported.
- **GAP-3: reviewer scope and cycle-2 score downgrade.** The restricted reviewer could not raise new findings and its verdict was exempt from the score downgrade (`phases/phase-45-spec.md:178`). Now a cycle-2 reviewer may raise new findings and a SHIP with a low axis becomes REVISE. `MAX_REVIEW_CYCLES = 2` (`:341`), so a cycle-2 REVISE goes to the existing cap path instead of a pass. This is the same behavior a free-form cycle 2 already had when cycle 1 produced no structured findings, so no new path exists; the frequency changes. See open question 3.
- **GAP-4: suppression-token guard on patches (0b95d45a P7).** `apply_surgical_patches` refused a patch whose `new` introduced `gitleaks:allow` or a security-lint pragma-allow line (self-authorization loop). Lost with the path, three tests retired. A spec is markdown, not code; the code-side guards (`_verify_security_lint`, `_commit_green_code`) are in phase 5 and are untouched.
- **GAP-5: diff-only re-review (GH605/GH638).** The cycle-2 reviewer no longer votes on a diff. The full prompt makes it read the spec by path. Cycle-2 review latency can rise; the complexity-aware timeouts (80CC602D, `:262`) apply to every cycle and are not changed.
- **GAP-6: role template now reaches the cycle-2 reviewer.** Behavior addition, not loss: a configured `role_template_path` is injected at cycle 2 as at cycle 1, and a bad template now also aborts cycle 2 (it would already have aborted cycle 1). Docs fixed in op5, pinned in AC8.
- **GAP-7: telemetry.** The four events and the `path: "surgical"` value go quiet. No consumer exists in this repo; external dashboards are unknown.
