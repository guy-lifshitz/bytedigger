## Adversarial edges (not covered by the §3 AC table)

1. **A str value the OS layer rejects.** Example: `scope: ["sp\u0000ecs"]`, or a bare-str or dict member `"sp\u0000ecs/a.md"` with `scope` absent.
   §2.2 accepts it, because it is a list of str. `compute_scope_digest` (oracle.py:186-188) then calls `iterdir()`, which raises `ValueError: embedded null byte`.
   Only `FileNotFoundError`, `NotADirectoryError` and `OSError` are caught there. The error escapes to `run.py:410` and becomes `E_BAD_CTX`.
   The CLI meanwhile says rc 2 `malformed` through its backstop, so engine and CLI disagree after GREEN. A path component longer than NAME_MAX has the same
   problem: on py 3.9-3.12, `Path.exists` (oracle.py:381) re-raises `ENAMETOOLONG` as `OSError`, which ends in `E_RUNNER` (run.py:416).
2. **Malformed `oracle_amended` row.** No RED shape uses `event_type="oracle_amended"`. The filter tuple (oracle.py:324) treats it the same as `oracle_frozen`, so the risk is low.
3. **Malformed but still a dict, as the previous row on re-entry amendment.** Example: `digest: 1`. The amendment proceeds and records a non-str `previous_digest`. Neither the spec nor the RED decides this.
4. **Pre-existing, outside the freeze-row shape.** A deeply nested JSON row makes `json.loads` raise `RecursionError` (oracle.py:300 catches only `ValueError`), which escapes as `E_RUNNER`.
   Absolute or `..` member paths are accepted and hash files outside the scratchpad. This is not an escape, but it is a fail-open surface.

## Findings

1. **MAJOR — the shape check is type-only, so a str value still escapes (edge 1).** After a spec-conformant GREEN, a freeze row whose `scope` or member path
   holds `\u0000` still raises `ValueError` past `run.py`'s `except OracleRefusal` (oracle.py:186-188, run.py:410 gives `E_BAD_CTX`). On py < 3.13, an
   overlong path component raises `OSError` from `Path.exists` (oracle.py:381, run.py:416 gives `E_RUNNER`).
   This is the exact defect class bd#158 closes, and its title promises "never escapes". It also breaks AC6 parity, because the CLI backstop answers rc 2.
   Remedy: either extend §2.2 so that path/scope str values must not contain `"\x00"`, or have §2.4 convert path-layer `ValueError`/`OSError` raised inside
   `verify_against` into `E_ORACLE_INDETERMINATE`. Add the matching AC1/AC4/AC6 rows (`scope_nul`, `member_path_nul`), or declare it out of scope in §1v with a reason.
2. **MINOR — the placement in §2.4 is not pinned.** No test calls `oracle.verify_against(malformed, D)` directly. A GREEN that instead put
   the full `check_freeze_payload` inside `find_last_freeze` would pass every AC, but it would change the amendment path: a previous row that is a dict but malformed further down
   would then refuse. Add a direct unit assertion on `verify_against`, and one AC that pins amendment over such a previous row (edge 3), whichever outcome is intended.
3. **MINOR — the RED has no malformed `oracle_amended` row (edge 2).** The title covers it. Add one AC1 parametrize with `event_type="oracle_amended"`.
4. **MINOR — §1x legacy input is not stated.** An absent `scope_digest` moves from `E_ORACLE_MUTATED mutated:added` to `INDETERMINATE`. Both refuse, so nothing
   fails open. The spec should still say that no shipped writer ever emitted a payload without `scope_digest` (oracle.py:246, always set).
5. **MINOR — out-of-scope escapes (edge 4).** `RecursionError` from a deeply nested row in `read_log_events`, and absolute or `..` member paths.
   Record a follow-up issue, or list them in §1v.

Re-gate after the spec (r2) and the RED address F1. F2-F5 are advisory.
