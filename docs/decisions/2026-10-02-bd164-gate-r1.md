## Adversarial edges (not covered by any §3 AC)

1. **Relative engine path + cwd ≠ toplevel:** spec `paths: [SYSTEM/cli/build/engine_py/x.py]` with `run_preflight(cwd=<repo>)` called from another process cwd. `tier_gate.resolves_to_existing` resolves against the process cwd or the engine's own `_REPO_ROOT` (`tier_gate.py:91-98`), not toplevel. The tier step silently passes (fail-open). The RED dodges this by using an absolute `{repo}` path (test:284).
2. **Tree edited while the steps run (TOCTOU):** `state_hash` is computed *after* the steps (line 115). An edit made during the scoped pytest run is folded into the hash, so the receipt is `fresh` for a tree the tests never saw.
3. **`red_tests` entry that does not exist on disk:** syntax and stub filter "existing", but scoped behaviour is not pinned down (pytest exit 4 with or without a JUnit file).
4. **Empty `paths`:** exit-2 branch, untested.
5. **`--classifier-cmd '[]'`:** passes "JSON list of strings", but `check_ladder._validate` raises on an empty list (`check_ladder.py:77-80,152-153`). This becomes a prescreen `error` instead of exit 2 USAGE.
6. **Repeated `run_preflight` in one long-lived host process after edits:** `spec_cite._REPO_INDEX_CACHE` is per-process (`spec_cite.py:487`). The second run's wrong_file/unresolved decisions use a stale index.
7. **Concurrent git op during `verify_receipt`:** `git status` can take `index.lock`. If the compute fails, the outcome is unspecified ("never raises" but which word?).
8. **Suite run from a git hook:** inherited `GIT_DIR`/`GIT_INDEX_FILE`/`GIT_WORK_TREE` redirect both the fixture `_git` and the UUT's git calls to the outer repo.
9. **Stale `facts.md` after an exit-2 run:** step 2 deletes the receipt but not `facts.md`, so a host can still find and cite the old facts file.
10. **CRLF front-matter (`---\r\n`)** and a **non-UTF-8 spec:** not pinned down. "Never raises" covers `parse_spec_fields`, but the "unreadable" decision for the spec read is unspecified.

## Findings

1. **MAJOR-1: A6 asserts a cleanup post-condition with no producing §2 path.**
   - Spec lines 63-66: bad phase returns at step 1, and a merge-base failure returns inside step 2, both before "delete any existing receipt".
   - A6 (lines 167-168) claims no receipt afterwards, "including when a green receipt existed before", for bad phase and unknown `--base`.
   - RED test:579 and test:589 never create a prior receipt, so they cannot detect either outcome.
   - Fix (spec): split step 2 into
     - 2a: resolve toplevel + git dir (fail gives GIT, nothing to delete), then **delete receipt and facts.md**;
     - 2b: phase check (USAGE) and `HEAD` + `merge-base` (GIT).
   - Alternatively, narrow A6 to say the bad-phase and not-a-repo paths leave an existing receipt untouched. That is still sound, because verify re-hashes.
   - Fix (RED): in `test_A6_unknown_base_is_git_error`, and in `test_A6_bad_phase_usage` if the reorder is chosen, first `_run(fx,"red")` to exit 0 and assert the receipt exists, then assert it is gone after the exit-2 run.
2. **MAJOR-2: the fail-closed branches of op4 have no AC and no RED.**
   - (a) Line 71: an exception inside steps 1-7 must give `red` "internal error: ...".
   - (b) Line 91: no JUnit report / runner missing / `test_timeout_s` expiry must give `red` "<file>: no test report".
   - Branch (b) is the dangerous one. A GREEN that treats "no report" as 0 pass / 0 fail passes **green phase** as `ok` (fail==0), so a crashed or timed-out suite yields a fresh green receipt. Nothing in the RED catches that.
   - Fix (spec): add A3 bullets for both.
   - Fix (RED), test 1: `monkeypatch.setattr(spec_cite, "lint_spec", raiser)`, then assert exit 1, `error_code == E_PREFLIGHT_CITE`, `steps[2].detail.startswith("internal error")`, and later steps `skipped`.
   - Fix (RED), test 2 (pre-staged, green phase): the red test file does `time.sleep(30)` and the run uses `test_timeout_s=1`. Assert exit 1, `E_PREFLIGHT_SCOPED`, and `"no test report"` in the detail.
   - Optional third test: a sibling run under the same timeout gives `E_PREFLIGHT_SIBLINGS`.
3. **MINOR-1: path relativity is unspecified** (spec lines 67, 74-85, 95; test:284).
   - Fix: state that `red_tests`, `sibling_tests` and `paths` are toplevel-relative unless absolute, and are absolutized against toplevel before `lint_paths`, `lint_red_file`, `compile` and the pytest argv.
   - Add a test with a relative engine path and `monkeypatch.chdir(tmp_path)`. This covers edge 1.
4. **MINOR-2: test:736 asserts `"preflight"` in the usage output, which the spec does not state.**
   - Fix: either add "`argparse.ArgumentParser(prog="bytedigger-engine preflight")`" to op6, or drop the assertion.
5. **MINOR-3: TOCTOU** (edge 2, spec line 115).
   - Fix: compute `state_hash` before step 1 and again after step 8. On mismatch, either record it with a distinct status/code or document the limitation explicitly. Advisory.
6. **MINOR-4: `verify_receipt` behaviour when `compute_state_hash` fails is unspecified, and its "read-only" claim is not strictly true** (spec lines 122-125).
   - Fix: run git with `--no-optional-locks` (or `GIT_OPTIONAL_LOCKS=0`) in `compute_state_hash`.
   - Specify that a compute failure with a readable receipt gives `stale`.
7. **MINOR-5: test env hygiene.**
   - `known_reds_ledger.resolve_today()` reads `HAL_KNOWN_REDS_TODAY` (`known_reds_ledger.py:138`). The active/expired sibling tests (test:338-365) do not clear it.
   - The `GIT_*` env is not scrubbed for `_git` (test:80-86) or for the UUT (edge 8).
   - Fix: an autouse fixture that runs `monkeypatch.delenv` for `HAL_KNOWN_REDS_TODAY`, `GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE` and `GIT_OBJECT_DIRECTORY` (`raising=False`).
8. **MINOR-6: `--json` combined with an argparse usage error.**
   - Line 132 says exit 2 under `--json` prints the JSON error doc. Line 135 says argparse errors exit 2, and argparse writes usage text to stderr with an empty stdout.
   - Fix: say explicitly that argparse-level errors are exempt from the one-JSON-document rule, or route them through the JSON doc with `E_PREFLIGHT_USAGE`.
9. **MINOR-7: the empty-`paths` exit-2 branch (line 67) is untested.**
   - Fix: add an `_spec_text(paths=())` case to test:558.
10. **MINOR-8: `facts.md` is not deleted with the receipt** (edge 9).
    - Fix: delete both files in step 2. This folds into the MINOR-1 fix.
11. **MINOR-9: `--classifier-cmd '[]'`** (edge 5).
    - Fix: op6 requires a **non-empty** JSON list of strings, mirroring `check_ladder._valid_cmd`.
    - Add `"[]"` to the loop at test:728.
12. **MINOR-10: the spec_cite repo-index cache is per-process** (edge 6). Advisory.
    - Document it in the module docstring, or note it in §4 as a known limitation for in-process hosts.
