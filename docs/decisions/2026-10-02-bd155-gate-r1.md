## Adversarial edges (not covered by §3)

1. **AC7 indirection bypass.** A GREEN can bind `_event_type_of` (satisfying the identity check) and still
   read the key inline through `_K = "type"; event.get(_K)` or `dict.get(event, "type")`. The AST scan only
   matches a literal constant as the first argument. See F3.
2. **bd_l3 over-filter.** A GREEN with an inverted or over-broad skip (dropping every event) passes the whole
   new file, because AC6 bd_l3 only asserts `violations == ()`. Only `test_bd141_p4_bd_l3_cli` and
   `test_bd28_*` would catch it. Suggest a positive control in AC6 bd_l3: the same payload under
   `event_type == EVENT_TYPE` must yield an `R3.3:` violation. This also keeps AC6 non-vacuous if R3.3's
   predicate changes later.
3. **Heterogeneous log.** No AC mixes the two shapes in one list, for example a legacy `type` R2.1-violating
   event alongside an on-disk R2.1-passing event, which should yield failed. Low risk because resolution is
   per event. Advisory only.
4. **AC8 interpreter environment.** If `PYTHONSAFEPATH` is set in the parent env, `-c` drops the cwd entry
   and the import may resolve to an installed `bytedigger_engine`, or fail. See F4.

## Findings

1. **MAJOR: the chokepoint claim is false on the current tree; oracle.py is a third inline reader the spec
   never names (§1c / §1v).** The spec header (spec:4-6) calls `event_type_of` "the single place a
   conformance checker turns an event dict into its event-type name". `conformance/oracle.py:309,323,338`
   reads `e.get("event_type")` inline. That is the exact pattern §1.3 (spec:20-22) predicts a third checker
   will copy. §2.4 (spec:49-52) lists the out-of-scope `get("type")` readers but leaves out oracle.py, and
   AC7 scans only bd_l2/bd_l3.
   **Fix, either way:**
   - (a) Add oracle.py to §2.4 with the reason (it reads only on-disk logs through its own loader and never
     the harness shape; routing it is a follow-up issue), and narrow the chokepoint wording to "the BD-L2 and
     BD-L3 checkers".
   - (b) Bring oracle.py into scope: route its three reads through the resolver and add `oracle` to the AC7
     parametrization.

2. **MAJOR: §2.1 allows an import that AC8 rejects.** Spec:37 says "no imports beyond
   `typing.TYPE_CHECKING`". The AC8 test (`test_bd155…py:218-230`) snapshots `sys.modules` after
   `bytedigger_engine.conformance` and requires the delta to be exactly `{…_event_type}`.
   `bytedigger_engine/__init__.py` imports only `__future__` and `conformance/__init__.py` is empty, so
   `typing` is not loaded by then. A GREEN following the bd_l2 precedent
   (`from typing import TYPE_CHECKING as _TYPE_CHECKING`, `bd_l2.py:37`), which §2.1 allows, adds `typing`
   (and its dependencies) and turns AC8 red. That is a spec-conformant GREEN failing the RED.
   **Fix:** change §2.1 to "no imports at all; annotations are string literals". The spec's own signature
   already uses string annotations. Alternatively, have the test `import typing` before taking the
   `before` snapshot. Prefer the spec change, since it is what AC-C1 actually means.

3. **MINOR: AC7 proves the resolver is bound, not that it is used.** `test_bd155…py:178-203`: the AST scan
   only matches a constant first argument of `.get`, and the identity test only checks the binding.
   **Fix:** in `test_ac7_both_checkers_bind…`, also assert that the body of `check_bd_l2` / `check_bd_l3`
   contains an `ast.Call` whose func is `Name(id="_event_type_of")`. Optionally also flag any `.get(...)`
   call on the loop variable `event` whose argument is not the literal `"payload"`.

4. **MINOR: the AC8 subprocess depends on the parent's environment.** `test_bd155…py:226` relies on
   cwd = `ENGINE_PY` being `sys.path[0]` for `-c`. `PYTHONSAFEPATH=1` (3.11+) or `-P` in the environment
   removes it, and an installed non-editable `bytedigger_engine` would then be measured instead of the
   worktree. `sys.executable` and the cwd are otherwise correct: the cwd entry precedes `PYTHONPATH`.
   **Fix:** pass `env={**os.environ, "PYTHONPATH": str(ENGINE_PY)}` with `PYTHONSAFEPATH` removed, or put
   `sys.path.insert(0, <ENGINE_PY>)` at the top of the `-c` code.

5. **MINOR: AC6 bd_l3 has no positive control.** `test_bd155…py:136-153`. See Adversarial edge 2.
   **Fix:** add the same payload under `{"event_type": attest.EVENT_TYPE}` and assert that some violation
   starts with `"R3.3:"`.

**Test vs spec alignment:** no test asserts anything the spec does not state.
- AC8 pre-imports `conformance` before the snapshot, which is equivalent to the spec's "other than itself

- The AC6 bd_l3 payload matches `test_bd141_p4_bd_l3_cli._payload("sonnet","haiku")` field for field.
