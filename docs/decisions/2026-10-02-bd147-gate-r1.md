    (`test…:229-232`, `:382`) check this.

  - No ref or an empty ref gives `""`.

  - Each surviving file is either at most 20 000 chars and inlined whole, or longer and truncated with a marker.
  - The AC3 fixture covers both inline arms. It also covers both filter arms: `tests/helper_not_a_test.py` fails `test_*.py`,
    and the `state_dir_prefix()` file is excluded.

## Findings

**F1 MAJOR: the I/M boundary leaves model output that is round-tripped through the scratchpad undecided. By §2.1's own test it is class I, yet it is
not surveyed, not migrated and not deferred.** §2.1 classifies by "where its bytes are read from when the prompt is built", and
explicitly not by who wrote them. Class M is defined as output "passed along in memory in `prev.data`". Several prompts, some inside the
very function this lot edits, read earlier model output back from disk and inline it verbatim:
- `phase_45_spec.py:1064` reads `spec.md`. That text is inlined by `build_surgical_revise_prompt` (`:1082`,
  `surgical_revise.py:85-86` `CURRENT SPEC…{spec}`), by `build_delta_retry_prompt` (`:1113`) and by `_restricted_writer_prompt` (`:1250-1257`).
- `phase_45_spec.py:1051` takes S7's structured findings from a file, `load_findings_thread` (`findings_sidecar.py:36-37`). That
  contradicts the §1.2 S7 row ("held in memory").
- `phase_45_spec_lite.py:388/397-402` inlines the previous review doc and the spec read from disk, and `:570-573` does the same.

AUTHORSHIP_SPEC §4 `[bd147]` says class I "MUST be declared". It lists closed membership, and the R3.2 note (:371) says the lot
"migrated" the class. The recorded boundary therefore reads as complete while known class-I-by-definition segments remain
undeclared. **Fix:** decide the class of scratchpad-round-tripped model output and record it in §2.1 and in AUTHORSHIP_SPEC. My
recommendation is to widen class M to "model output, carried in memory or round-tripped through the run's own scratchpad",
with the same declared limit and re-open criterion. Then add the survey rows (spec text, review doc, findings sidecar), and state the survey's scope and method
(for example "every `read_text` under `workflows/` and `lib/plugins/` that reaches a prompt") together with the gap statement for
anything outside it.

**F2 MAJOR: the class E criterion is contradicted by two of its own named members.** §2.1 says class E is text "where no run of source bytes reaches the
prompt unmodified", and the S5 row says "nothing verbatim from any one file".
- The facts pack renders KNOWN REDS ledger cells verbatim, joined with `" | "` (`facts_pack.py:326-327`, cells from `:229-233`).
  It can also be served from a cache file (`:356-359`).
- S9 interpolates `evidence` verbatim (`directed_repair.py:241-243`). A gate's evidence normally quotes the artifact.

Taken literally, the criterion would also make every interpolated path class I. **Fix:** replace the criterion with a structural one. For example:
- **Class E:** the engine extracts named fields or tokens and re-renders them under its own schema, with bounded per-field length.
- **Class I:** a file body, or a contiguous slice of one, is inlined.

Then correct the S5 row and mirror the new wording at AUTHORSHIP_SPEC :471-474.

**F3 MAJOR: the S1 binding over the final prompt (§3.2, "after the standards block is prepended at `:1292`") has no test, and when it is wrong it fails silently.**
None of the RED fixtures sets `artifact_type`, so `get_standards_context` returns `""` (`_standards_context.py:50-52`). A GREEN that
computes `_injected_blocks_record` before `:1293-1294` passes all 17 tests. In production with `artifact_type` set,
`prompt_sha256` would then never match. The new guard would drop S1 without a refusal and without any signal, so the lot's main
deliverable would be off for every run that uses standards. **Fix:** add an AC1 or AC6 case that monkeypatches
`phase_45_spec.get_standards_context`. That is a dependency of the builder, not the unit under test. Make it return a non-empty block, then assert
that the S1 block is declared and attested and that the dispatch is `ok`.

**F4 MINOR: ignoring a stale record silently is acceptable for forwarded records, but it hides mis-binding.** The hazard is real:
`_build_decorr_prompt` spreads prev.data (`:5509`), and after GREEN the fix invoke's extra_data carries the record downstream.
For a forwarded record, ignoring is the correct behaviour. But the same branch also absorbs a producer bug (F3) or a future
prompt-rewriting step (edge 4) as silent under-declaration. **Fix:** state in §3.1/§8 that the positive per-producer tests are the
only defence against that. Optionally, emit a debug-level `_emit_safe` event when a record is present, its hash does not match,
and every block's content still occurs in the prompt. That combination is the signature of mis-binding rather than forwarding.

**F5 MINOR: "none of them raises" covers only the containers.**
- A non-str `data["prompt"]` makes `hash_text` call `.encode` on it and raise (`attest.py:45`).
- A `blocks` element that is not a mapping with `source_id`/`content` raises on indexing.
- AC8 (`test…:613-624`) covers only container-level shapes.

**Fix:** either state in §3.1 that elements are trusted, because the engine produces them, or add `isinstance` guards plus two AC8 cases.

**F6 MINOR: the §2.2 empty-chunk rule has no AC.** The two cases are in edge 2. A `""` block passes the chokepoint, so only a test
can enforce the rule. **Fix:** add a BOM-only decision-doc case and an empty-test-file case that assert no block is declared.

**F7 MINOR: §8 understates the size cost.** The record holds full content: up to 75 000 chars for S1 and N×20 000 for S2. It is
stored in step data, forwarded through the fix extra_data into the downstream `{**prev.data}` chain, and kept ("ignored, never
deleted"). Persisted step outputs therefore roughly double their prompt-sized payload. **Fix:** say so in §8, or bound it, for example by
storing `(start, end)` offsets into `prompt` instead of content.

**F8 NIT.**

  prompt. Reword AC6.
- §1.2 S1 cites dispatch `:1357`; the actual call is `:1361-1369`.
- `AUTHORSHIP_SPEC.md:461-462` ("tracked in bd#147; the label value is unchanged") is now stale next to the `[bd147]` block.
