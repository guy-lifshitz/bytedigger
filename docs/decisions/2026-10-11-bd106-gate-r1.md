## Step 1.5 - rule-overlap simulation (`_call_can_write`)

Branch order: (a) None/[]/non-list -> True; (b) any base name in the 5-name set -> True; (c) else False. Simulated: None -> a; [] -> a; ["Read","Grep","Glob"] -> c; ["Read","Bash(git:*)"] -> b via `available_tools` base name; ["Edit"] -> b; ["Read","Write"] -> b. First matching branch yields the spec outcome in every row. `_snapshot_enabled`: absent/missing/unreadable -> enabled; `false` -> disabled; other value -> disabled. The `null` value sits in "any other value" (disabled), which an implementation using `.get(key)` could conflate with absent (see edge E2).

## Adversarial edges (not in the AC table)

- E1: a read-only list that includes `Task`/`Agent` (sub-agent delegation) or an MCP write tool: a delegated sub-agent may write under the parent's allow list; spec's Known limits cover MCP only, not `Task`/`Agent`. Decide: treat as can-write, or document.
- E2: `skip_read_only_snapshot: null`, `0`, `"false"` (string), `"False"`: spec says "any other value: disabled", but a `dict.get` + falsy check implementation would conflate `null`/`0` with absent. Only `"yes"` is pinned.
- E3: `restricted_roles` present but not a dict (string, list, null) or models file valid JSON but top level a list: must resolve to the same fail-safe as the absent key; not pinned.
- E4: `allowed_tools` as a tuple or a list with a non-str entry / blank entry / lower-case `"bash"`: spec says non-list -> True; a list with a non-str entry may raise inside `available_tools` before the decision, turning a would-be-snapshot call into a crash.
- E5: concurrent writer in the same worktree during a skipped read-only call: previously the read-only call's manifest would list the other worker's paths (and `engine.py` unioned them into `_written`); now `[]`. Behaviour change in the right direction, unpinned.
- E6: skipped call where `.git` vanishes mid-call: previously `E_MANIFEST_NO_GIT` error, now ok. Acceptable, unpinned.

VERDICT: APPROVED

## Findings

1. MINOR - Principle 2 contradicts the kill-switch read semantics. Principle 2 says malformed input keeps the snapshot, yet Design and AC3b make an unreadable or malformed models file skip (new behaviour). An operator who set `false` loses the kill switch silently if the file is unreadable. Either reword Principle 2 to "malformed `allowed_tools` or switch value" or change the unreadable-file default; RED pins skip-on-malformed, so rewording is the cheap fix. Not a gate blocker (behaviour is explicit and tested), but GREEN must follow AC3b, not Principle 2.
2. MINOR - `MultiEdit`/`NotebookEdit`/bare `Bash` are in the predicate but have no test. A regression dropping them would pass RED and guards. Add a parametrized guard (cheap, passes today).
3. MINOR - Edges E1-E4 are unpinned (`Task`/`Agent`, `null`/`0`/`"false"` switch values, non-dict `restricted_roles`, non-str tool entries). Recommend GREEN implement `_snapshot_enabled` as: skip only when the key is present-and-absent-sentinel or the file/key path is unreadable; anything present and not literally `False` disables skipping; and `_call_can_write` wrapped fail-toward-True on any exception.
4. MINOR - `timeout_data` assertions in AC1b do not check `manifest_source == "git_diff"` on the timeout result, though the spec states it for both paths.
