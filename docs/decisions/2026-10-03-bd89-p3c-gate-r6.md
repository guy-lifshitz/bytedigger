## Adversarial edges (not covered by any section 3/10/11/12 AC)

1. **Cross-build event leakage into persisted learnings.**
   - op9 reads `query_run_events(event_type=...)` with no run or build scope, over the whole default log. If that log keeps an earlier build's `fix_watchdog_no_progress`, `post_fix_pytest_infra_error` or `review_findings_audit` events, this build's `learnings-raw.md` re-derives them, and `learning-store.sh extract` stores them again.
   - Section 11 F7 accepted the same scope as the completed-phases section. The impact differs, though: the report is ephemeral, while learnings are persisted cumulatively.
   - Advisory follow-up: scope op9 to the current build's run IDs.
2. **A title containing ` --- `.**
   - For example `### SEVERITY: LOW — use a --- b`. The lesson becomes `- [review-finding] --- LOW finding: use a --- b`.
   - Whether `learnings_parse` splits on the first ` --- ` is not pinned, so the stored lesson could be truncated or mis-categorised. No test covers it.
3. **The satisfaction read raises inside op9** (section 12 fallback, `:404-407`). Untested (F3).
4. **The first separator is `--` but the title starts with `-`.**
   - For example `HIGH --- x`. The alternation matches `--`, then `\s+` fails, and the regex backtracks to `-`.
   - The header is then silently skipped instead of accepted as `- x`. This is benign (only the lesson is lost) but unpinned.
