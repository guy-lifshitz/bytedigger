# bd#93 gate r1: run-scoped event log (spec + RED audit)

- Spec: `docs/decisions/2026-10-02-bd93-run-scoped-event-log.md`
- RED: `engine_py/tests/test_bd93_run_scoped_event_log.py` (34 tests; orchestrator reported 33 failed and 1 passed. The pass is AC4a, the explicit `--event-log` regression guard, which is expected. The count matches: 1+1+1+2+5+3+20+1.)
- Code read: `run.py`, `event_log.py`, `config_provider.py`, `lib/restart_governor.py`, `lib/phase_sentinel.py`, `lib/dbos_setup.py`, `lib/observability/emit_resolver.py`, `telemetry_ctx.py`, `conformance/oracle.py`, `workflows/phase_8_post_deploy.py`, `lib/plugins/anti_hallucination/semantic_verifier.py`, `tests/conftest.py`, `tests/test_bd8_l1_oracle.py`, `tests/test_gh603_governor_auto_resume.py`, and the HAL host `hal_config_provider.py`.

## Q1. Does the spec fix the root cause at the chokepoint?

Mostly, yes, for the `run.py` driver path. `main()` is the first place where the run id is known, and assigning to `args.event_log` before `execute_durable_workflow` reaches `phase_sentinel.execute_engine`. That function builds a `WorkflowEngine(event_log=…)`, which emits `workflow_started` on its first event. So the log exists from the first event, outside cwd, keyed by run id.

The fix is incomplete in two ways:
- **Residual writers still default to cwd.** `semantic_verifier.py:375` and `:566` call `EventLog()`, which goes through `default_log_path()` to `<cwd>/.bytedigger/events.jsonl`. They also key by `session_id`, not run id. A logless run's phase-6 events still land in the shared cwd log (m4).
- **Turning on `args.event_log` for every logless run turns on every consumer gated on it.** The spec lists only some of them (M1, M2).

## 4-step audit

### Step 1: spec-internal consistency (literal-token drift)
These tokens are used consistently: `HAL_RUN_LOG_ROOT`, `BD_`/`BYTEDIGGER_` aliases, `run_log_root`, `run_scoped_log_path`, `event_log_path_override()`, `event log disabled:`, `org_config["events_log_path"]`, `_resolved_run_id`. No drift.

Ambiguities that are not drift:
- (m7) The order of `expanduser()` relative to the absolute-root check, and whether `expanduser()` also applies to an explicit `root`. The RED asserts that it does.
- (m7) Whether the minimal-Protocol fallback honours `HAL_RUN_LOG_ROOT`.

### Step 1.5: rule-overlap simulation
The resolution dispatcher is a/b/c plus an invocation filter. I traced each branch in order against `run.py:288-320`:
- `--task-begin`/`--task-reset` return at L288. `--derive-state`, `--list-runs` and `--status` return at L302-318. Each returns before the resolution point ("before the engine is built", L320). `--list` with `--workflow` is excluded by the spec's filter. All correct.
- (a) Explicit wins and (c) creates no dir: AC4a. (b) Host override beats (c): AC4b. (c) Default path: AC1/2/3/6. Bad id falls to degrade: AC5. A bad id with (b) set means (b) wins and no validation runs. That is correct, but untested.
- **Overlap hole:** `--event-log ""`. Today `args.event_log == ""` is falsy and means no log. The spec says "explicit, unchanged" but does not say whether `""` counts as explicit (a) or falls to (b)/(c) (m3).
- **Overlap hole:** a ctx where `events_log_path` is present but `null`/`""`. "Already sets that key" keeps the falsy value, so phase 8 falls back to the cwd-relative file (m1).

### Step 2: §2-vs-§3 cross-check
- §2.3 degrade path → AC5. But the producing §2 path catches only `ValueError`/`OSError`. The (b) and (c) lookups can raise `AttributeError` and `RuntimeError`, and no AC covers that (M3).
- §2.4 says governor and oracle "active, on purpose" and has **no AC**. Its consequences for the oracle contradict frozen `[bd8:6b]` (M2). The phase-sentinel cache, a third consumer turned on by the same switch, is missing from §2.4 entirely (M1).
- §2.5 test isolation → AC8. The scope is wrong: session-wide instead of per-test (M5).
- §2.1 `flags_catalog`, §2.6 docs/CHANGELOG: no AC (m8).
- The issue's crash-survival acceptance is AC1, but AC1 does not produce a crash (M4).

### Step 3: RED adequacy
- Every AC has at least one failing assertion. Production symbols are imported inside test bodies, so the tests fail at call time, not at collection. On `main`, AC1/2/3/4b/5/6/8 fail at an `assert`, and AC3 (unit part) and AC7 fail with an `ImportError`/`AttributeError` inside the body. Both are acceptable.
- No test mocks its own UUT. AC4b's provider subclass and the `register_all` wrapper are seams, not the UUT.
- **Gameable:** in AC1 the step raises, and the engine contains the exception, so `main()` returns normally. A GREEN that writes the run-scoped log only at the end of the run (for example, materialising it in a `finally`) passes AC1 and AC2 and still loses the log on a real crash (M4).
- AC8 passes on `main` if the developer's shell already exports a non-home `HAL_RUN_LOG_ROOT` (m11).

### Step 4: reachability (Point → Host → Test-path)
- AC1/AC6: Point is the new resolution block plus the `org_config` injection in `run.main()` before `asdict(ctx)` (around L366). Host is `run.main`. Test-path is in-process `run.main()`. It reaches `execute_durable_workflow` → `execute_native_workflow` → `execute_engine` → `workflows.register_all`, which is patched at module attribute level and resolved at call time (`phase_sentinel.py:166-170`). Reachable.
- AC2/3/5: the subprocess `RUN_PY` `__main__` → `hard_exit(main())`. Env is inherited through `engine_env`, and `HAL_DBOS_DB_PATH` comes from the autouse fixture. Reachable.
- AC4b: `get_config()` inside `main` uses the swapped factory. Reachable.
- AC7: direct. AC8: conftest `pytest_configure`. Reachable.

## Q2. Behavioural risks
- Governor active for logless runs: with a random run id, state never accumulates (harmless). With a repeated caller `--run-id`, the run is now denied after the caps. `--restart-reason` without `--event-log` stops being "ignored (governor inactive)" and becomes a real reset (m9). The spec declares this in general terms; no AC covers it.
- Oracle active: see M2.
- Phase-sentinel cache active: see M1. This one changes **results**, not just bookkeeping.
- `events_log_path` injection for `--event-log` callers: phase 8 now archives the `--event-log` file. Before, it archived `<working_dir>/<dirname>/events.jsonl`. If that file is shared across runs, the archive now holds other runs' events (m2). A relative `--event-log` is injected relative and resolved against the process cwd, not `working_dir` (m1). Injection also changes `_ctx_cfg_sha8` (org_config is hashed), so every `--event-log` caller's `phase_key` shifts once after upgrade, causing a one-time sentinel/DBOS cache miss (m12).
- HOME pollution: the default is `Path.home()/.bytedigger/runs`. On the HAL host it is `~/.claude/.hal-build/runs`, which is gitignored in HAL, so the tree stays clean. There is no retention, so every logless random-id run leaves a directory forever (m6).
- HAL host-override precedence: (b) is correct and preserves GH1309. But a relative `HAL_EVENT_LOG_PATH` is not validated, which brings cwd dependence back (m10).
- Existing tests that run `run.py` without `--event-log`: `test_bd8_l1_oracle` AC-15 legs and `test_gh603` AC12 still pass by value. However, AC-15 control leg 2's premise ("a logless ORACLE phase freezes nothing") becomes false (M2), and every such test now shares one session-wide root (M5).

## Adversarial edges (not covered by §3 ACs)
1. **Real process death** (`os._exit`/SIGKILL) after `workflow_started`. The current AC1 has only a contained exception. → M4
2. **Minimal-Protocol provider with no `--event-log`**: `config_provider.event_log_path_override()` (L276-278) raises `AttributeError`, so the run crashes instead of degrading. **Unresolvable HOME**: `Path.home()` raises `RuntimeError`. → M3
3. **Logless `phase_45_spec` without `scratchpad_dir`**: today it is untouched (`run.py:181-182`, `[bd8:6b]`). After GREEN it is refused with `E_ORACLE_INDETERMINATE` (`run.py:190`). → M2
4. **Same `--run-id` and same ctx run twice, logless**: the second run is served from `phase-sentinels/` instead of executing. → M1
5. **Cross-test state leakage** through a single session root (governor caps and sentinel cache keyed by literal run ids). → M5
6. **Case-insensitive APFS**: run ids `R1` and `r1` map to the same directory, so two different run ids cross-contaminate. This breaks the issue's acceptance on darwin. → m5
7. `--event-log ""`, and `events_log_path: null` in ctx. → m3, m1
8. Bad run id while host override (b) is set: (b) should win with no `event log disabled:` line. This is untested (advisory, part of m3).

## Findings

**MAJOR**

1. **M1: an undeclared result-changing switch (phase-sentinel cache).** `phase_sentinel.load_cached_success`/`store_success` (`_sentinel_path` L215-221) are gated on `event_log_path`. After GREEN, every logless run caches successes under `<root>/<run_id>/phase-sentinels/`, and a rerun with the same `--run-id` and ctx is served from the cache. §4 does not mention this.
   - Fix: in §4, list every consumer gated on `args.event_log`/`event_log_path`, and accept or gate each one explicitly: governor gate/record/pause/reset_full, `--restart-reason`, oracle entry/freeze/exit plus `phase_refused` rows, `phase_sentinel` SERVE/STORE, `emit_resolver` durable rows, and `stuck_report`.
   - Add a regression AC that pins the chosen cache behaviour for a logless rerun with the same run id and ctx.

2. **M2: `[bd8:6b]` contract break.** A logless oracle phase (`phase_45_spec`) without `scratchpad_dir` turns from untouched into a refusal (`E_ORACLE_INDETERMINATE`). `test_bd8_l1_oracle::test_ac15_control_logless_oracle_phase_is_untouched` still passes only because it supplies a scratchpad, so its premise is now false and nothing catches the change.
   - Fix: either (i) keep `[bd8:6b]` for implicit logs, for example by carrying an `explicit_log` flag and keeping the `if not args.event_log` freeze skip keyed on it, or (ii) amend `ORACLE_SPEC`/bd8 deliberately and add an AC for the new refusal.
   - In both cases, state which, and update the AC-15 control leg's docstring and premise.

3. **M3: "degrade, never fail" is incomplete.** §3 catches only `ValueError`/`OSError`. Resolution (b) calls an unguarded `get_config().event_log_path_override()`, which raises `AttributeError` on a minimal-Protocol provider. (c) calls `home_root()`/`Path.home()`, which can raise `RuntimeError`. Either would turn a working logless run into a traceback or `E_RUNNER`. That breaks the owner's provider-agnostic and degrade principles.
   - Fix: make the (b) lookup `getattr`-tolerant, like `foreign_state_dirname()` at L242-245, and catch `Exception` around the whole resolution block, emitting the `event log disabled:` line.
   - Add AC5c: a `_Minimal` provider with no `--event-log` gives exit code 0, unchanged stdout, and either a run-scoped log or `event log disabled:`.

4. **M4: AC1 does not test a crash.** `_boom` raises, the engine contains it, and `main()` returns. This is satisfiable by end-of-run materialisation, and the issue's acceptance is "emits ≥1 event then crashes".
   - Fix: add AC1b, a subprocess (`python -c` that wraps `workflows.register_all`, then calls `run.main()`) whose step calls `os._exit(9)` after `workflow_started`.
   - Assert the return code is not 0, `<root>/R1/events.jsonl` is readable, it contains `workflow_started`, and every event has `run_id == "R1"`.

5. **M5: §5 isolation is session-scoped and conditional.** One shared root for the whole session means governor state and the sentinel cache (both newly active, see M1) leak between tests that reuse literal run ids without `--event-log`. "Set when unset" also keeps a developer's real exported root.
   - Fix: keep the session-level set in `pytest_configure` but make it unconditional, with restore in `pytest_unconfigure`.
   - Add a function-scoped autouse fixture `monkeypatch.setenv("HAL_RUN_LOG_ROOT", str(tmp_path / "run-logs"))`, the same pattern as `_telemetry_log_isolation`.
   - Extend AC8 to assert the root is under the current test's `tmp_path`.

**MINOR**

6. **m1:** Inject an absolute path (`Path(p).absolute()`, not `resolve()`, so that AC6's equality against macOS `/var` tmp paths holds). Define "caller already sets" as a truthy value.
7. **m2:** Declare in CHANGELOG that phase 8 now archives the `--event-log`/host-override file. If that file is shared across runs, the archive holds other runs' events.
8. **m3:** Pin the `--event-log ""` semantics. Recommended: treat it as absent, preserving today's no-log behaviour by keeping `""` as "no log", and say so. Add the bad-id-with-(b)-set case to AC4b.
9. **m4:** List `semantic_verifier.py:375` and `:566` (`EventLog()` → cwd default, keyed by `session_id`) under Out of scope and file a follow-up. Alternatively, route them through `telemetry_ctx.emit_safe`.
10. **m5:** On case-insensitive filesystems, run ids that differ only in case collide. Document this, or detect it with a case-folded marker.
11. **m6:** No retention for `<root>/<uuid>/` directories. Document this in CHANGELOG and file a follow-up for pruning.
12. **m7:** State that `expanduser()` runs before the absolute check and applies to an explicit `root` (the RED asserts this). State whether the minimal-Protocol fallback consults `provider.path("HAL_RUN_LOG_ROOT", …)`.
13. **m8:** No AC for the `flags_catalog` entry or `docs/configuration.md`. Add a one-line assertion, or cite the existing catalog-parity test that enforces it.
14. **m9:** `--restart-reason` without `--event-log` silently changes from a warning to a real reset on the implicit log. Declare this. The HAL-side `run-phase-restart-reason-gh1335.test.ts` references the old message.
15. **m10:** Require (b) to be absolute, or degrade when it is not, so a relative `HAL_EVENT_LOG_PATH` cannot bring cwd dependence back.
16. **m11:** AC8 passes vacuously on `main` when the shell exports a root. Fixed by M5's per-test fixture plus a tmp_path assertion.
17. **m12:** Declare the one-time `phase_key`/`_ctx_cfg_sha8` shift for `--event-log` callers caused by `events_log_path` injection.
