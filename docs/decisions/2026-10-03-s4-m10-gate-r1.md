## Adversarial edges (not covered by the §4 AC table)

1. **Non-empty review aborted as "EMPTY" (decoy-fence).** Fallback content that carries canonical `### SEVERITY: HIGH — t` + `> path:line:` blocks (the PER_ROLE schema the prompt mandates, `canonical.py:18-35`) but omits the 194-byte JSON directive's block, and ends with `VERDICT: PASS` or has no marker. Today: SUSPECT, and `_persist_fix_feed` parses those blocks from the same bytes (L2050-2055) and feeds them to the fix worker. After the spec: terminal `E_REVIEW_EMPTY_FALLBACK` with `recoverable=False`. Real findings are dropped and the run is killed. (MAJOR-4)
2. **Persisted diagnosis doc reads as a review downstream.** The fail-closed path leaves `reviews/build-review.md` (normalised to `## Aggregated Findings\n\n(no findings)\n`). phase_7 reports `review: PRESENT` and lists no review gap (L458, L478). (MAJOR-1)
3. **Same-run resume / restart replay.** `invoke_review_llm` has `resume_sentinel=True`, and `phase_sentinel` caches ok results (L256). A same-run restart replays the cached empty `raw_response` and skips the stale-doc unlink (L1071-1077). Disk-first `_resolve_review_content` then reads the persisted normalised doc, so the step fails again. The reason drifts from `body_empty` to `no_structured_block`. A restart can never re-ask. (Context for MAJOR-3.)
4. **Aggregator error masked.** `_aggregate_and_write_review_artifact` routes aggregator errors (e.g. `E_MISSING_SCRATCHPAD`) into the fallback. The terminal code the run reports becomes `E_REVIEW_EMPTY_FALLBACK`. Only the side event `review_aggregation_error` keeps the real cause. (MINOR-7)
5. **Non-dict structured entries.** `["CRITICAL: sql injection"]` is filtered to `[]` by `extract_structured_findings_raw` (findings_extractor.py:91) and reads as PASS. This is the same family as §2 and it stays open. (MINOR-2)
6. **Bare `VERDICT: PARTIAL` / `VERDICT: FAIL`, zero findings anywhere.** It stays `ok` with a "(no findings)" fix feed. This is the same "no review evidence" class, and the spec keeps it as an unnamed residual. (MINOR-3)
7. **Unrecognised-severity block plus an explicit `VERDICT: FAIL` marker.** The block wins before the marker is read, so this becomes a terminal error, not FAIL. (MINOR-4)
8. **Stale fix doc.** `build-review-fix.md` from cycle N-1 is not removed on the cycle-N fail-closed path. The invoke step unlinks only the composite and the review doc. "No fix doc written" is not the same as "no fix doc present". (MINOR-8)
9. **Prompt-template echo (regression shield).** A reviewer that echoes `STRUCTURED_FINDINGS_JSON_TEMPLATE` (severity `"CRITICAL|HIGH|MEDIUM|LOW"`) is PASS today and becomes `unrecognised_severity` under §2. That is good, but no RED cell pins it. A cell is recommended.
10. **Malformed or dict-root JSON inside a real `## Findings (structured)` fence.** It goes to `no_structured_block`, and no RED cell covers it. (MINOR-11)

## Findings

### MAJOR

**MAJOR-1: phase_7 consumer missed. The fail-closed post-condition "review doc persisted" makes the report claim a review exists.**
`phase_7_synthesize.py:458` sets `"review": "PRESENT" if paths["review"].is_file()`, and the gap list (L478) excludes PRESENT. Phase 7 runs after phase-6 aborts (GH1626b). On the new terminal path, `reviews/build-review.md` holds the normalised "(no findings)" text, so the build report shows `review: PRESENT` for the exact case this lot exists to flag. AC1 currently pins `doc_path.is_file()`. Required: the spec decides how the diagnosis bytes are kept without impersonating the review artifact. Options: (a) persist under a distinct name (for example `reviews/build-review.empty-fallback.md`) and leave `REVIEW_DOC_RELPATH` absent; (b) write a recognised NOT_ASSESSED-style marker and classify it in phase_7, which grows the scope. Add an AC asserting the phase-7 artifact state is not PRESENT, or that `REVIEW_DOC_RELPATH` is absent, on this path.

**MAJOR-2: §5 conflict list is incomplete. GREEN will hit unlisted red tests.**

**MAJOR-3: the remedy class and recoverable semantics are not argued against GH1399's own doctrine.**
GH1399's §1n registry defines the vocabulary (test file L1103-1110): "normalize" means missing FORM; "re-ask" means missing SEMANTICS ("the only legitimate recovery is asking the model again, and exhaustion means refusal"); "terminal" means a real verdict or a wiring/IO fault. A review with no findings and no verdict evidence is missing semantics, so this doctrine puts it under re-ask (compare `E_INTEGRITY_NO_MARKER`). The spec picks terminal (`recoverable=False`), which short-circuits the step retry (`contracts.py:684`), emits the terminal stuck report (`engine.py:421-434`) and exempts nothing at the restart governor (`run.py:440-446`). It does not say why. Terminal may well be the right call: a same-run restart replays the cached `invoke_review_llm` sentinel and re-reads the persisted doc disk-first (adversarial edge 3), so it cannot re-ask without sentinel invalidation, and GH1399 removed paid inline retries. But the spec must (a) state the remedy class and the `_CLASS_REGISTRY` entry text (`missing`, `why`), (b) explain why a bounded re-ask is not used, or specify it, and (c) name the operator's recovery action (new run? sentinel purge?). §5's one-line policy note does not do this.

**MAJOR-4: "SUSPECT" is not "empty". The spec aborts non-empty reviews and no AC pins the decision.**
§0's premise is that fallback SUSPECT means no findings. On the fallback path SUSPECT means "no JSON structured block and no PARTIAL/FAIL marker". That includes reviews whose body carries canonical `### SEVERITY:` finding blocks (the schema the prompt mandates). `_persist_fix_feed` parses those blocks from the same bytes and forwards them to the fix worker today (L2050-2055). Under §1 those reviews become terminal `E_REVIEW_EMPTY_FALLBACK` / `no_structured_block`: real findings are discarded, the run is killed, and the code name is false. Required: decide explicitly and add an AC. Either (a) fail closed only when SUSPECT **and** the fix-feed derivation from the same bytes (`_parse_finding_blocks` over `## Aggregated Findings` + the suspect section) yields zero blocks, with a guard AC for the SEVERITY-blocks-without-JSON shape that stays `ok`; or (b) keep the abort for this shape on purpose, with its own reason (not "empty") and an AC that pins it.
