## Adversarial edges (not covered by any §3 AC)

1. **Decoy control (D1 false negative).** Under D1, `expect(r.code).not.toBe(0)` and
   `expect(user.zipCode).toBe(90210)` in the same block count as controlled. HAL flags this case. The wider
   tokenizer widens the control side as well as the candidate side.
2. **Decoy candidate (D1 false positive).** Under D1, `expect(addr.countryCode).not.toBeNull()` and
   `expect(res.statusText).not.toBeNull()` become findings. HAL does not flag them.
3. **Mixed legacy batch.** One unreadable target and one dirty target in the same `red_test_paths` must
   terminate with `E_RED_LINT_TARGET_UNREADABLE`.
4. **Legacy kill switch.** With `HAL_ONE_SIDED_PREDICATE_GATE=0` and `HAL_RED_LINT_PREFLIGHT_BATCH=0`, the dirty
   file must reach the semgrep terminal and emit `gate_disabled`.
5. **Precommit lane end-to-end.** A staged one-sided `.test.ts`, under the real registry with `BD66_LINT_DIR`
   unset, must refuse with `BD66-REFUSE-VIOLATION`. Because `precommit_enforce` runs argv[0] directly, a driver
   without a shebang or exec bit fails with `BD66-REFUSE-DRIVER-ERROR` on every `.test.ts` commit in bd.
6. **Package-copy fixture.** `test_bd66_precommit_enforcement._materialize_package_copy` copies only
   `precommit_lints.py` and `precommit_enforce.py`. The B3-forced import of `one_sided_predicate` therefore
   fails in the clone (regression shield, M2).
7. **Registry baseline.** bd66 AC7 counts drivers on disk with `rglob` (regression shield, M1).

## Findings

**M1 (MAJOR): GREEN as specified reddens `test_bd66_precommit_enforcement.py::test_ac7_real_registry_twelve_declared_absent_returns_zero`. The spec says this file "stays green unmodified".**
The test asserts `on_disk == []` using `REPO_ROOT.rglob(f"{name}.py")` (lines 902-912). The spec puts
`one-sided-predicate-lint.py` at the repo root, so the scan finds it. The test also asserts
`len(declared) == 12 and set(declared) == set(names)` (915). The spec removes the name from `DECLARED_ABSENT`,
leaving 11. The test's own text says: "If a driver has landed, its name must leave DECLARED_ABSENT and this AC
must be re-baselined."
*Fix:* in §3 Regression, declare an authorized edit to bd66 AC7. Re-baseline to 11 declared plus 1 driver. A
better version asserts the invariant itself: for every registry name, exactly one of these holds:
`name in DECLARED_ABSENT`, or `os.path.isfile(driver_path(name, DEFAULT_LINT_DIR))`. Pin the driver set as
`{"one-sided-predicate-lint"}`. List the edited test in a Files section.

**M2 (MAJOR): the B3 alias forces `precommit_lints` to import `bytedigger_engine.one_sided_predicate`. That reddens bd66 AC11 and AC6c.**
`_materialize_package_copy` (bd66 :410-439) builds a clone package that contains only `__init__.py`,
`precommit_lints.py` and `precommit_enforce.py`. `scripts/precommit_enforce_cli.py:25-26` puts the clone's
`engine_py` at `sys.path[0]`, so `bytedigger_engine` resolves to the clone, and the import raises
`ModuleNotFoundError`.
- AC11 then fails `REFUSE_VIOLATION in output`. Python's rc=1 on an uncaught exception satisfies only the rc
  half.
- AC6c then fails `REFUSE_MISSING_DRIVER in output`.

The other design questions are fine. There is no import cycle, because `one_sided_predicate` imports nothing from
the package. A `try/except ImportError` fallback in `precommit_lints` would be a hidden second copy, which breaks
§1g.
*Fix:* declare an authorized edit to `_materialize_package_copy` that also copies `one_sided_predicate.py`. It
can be derived, for example from the `bytedigger_engine.*` imports of `precommit_lints` found via AST, so the next
dependency needs no fixture edit. Name AC11 and AC6c in §3 Regression.

**M3 (MAJOR): the precommit lane has no test path, and the spec mislabels portable HAL Rule P tests as not ported.**
The spec lists AC17-AC22 as "Rule M" and AC27 as "HAL pre-commit script". AC18, AC19 and AC20
(`is_ts_test_file`, `classify_staged` ts routing, `build_lint_commands` ts argv) and AC27 (a TS-only commit
reaches `one-sided-predicate-lint`) are Rule P precommit tests. They port directly to bd's
`precommit_lints`/`precommit_enforce`. Issue AC3 asks for "HAL's GH1373 tests pass against the port".

`precommit_enforce.py:175` runs `subprocess.call(argv)` with argv[0] set to the `.py` path, so it executes the
driver directly. §2.4 does not require a shebang or mode 100755. B3 checks only `is_file()`.
*Fix:*
- Port AC18-AC20.
- Port AC27 adapted to bd: a hermetic repo with `_hermetic_git_env`, a staged dirty `.test.ts`, the real
  registry, and `BD66_LINT_DIR` unset. `precommit_enforce.main([])` should then return 1 with
  `BD66-REFUSE-VIOLATION` naming `one-sided-predicate-lint`. Add the control side: the same file plus a control
  returns rc 0.
- In §2.4, state the `#!/usr/bin/env python3` shebang and that the file is versioned as 100755.
- Fix the "Not ported" list so that only Rule M items (AC1-6, 14, 17, 21, 22, 33) plus AC26 and AC32 remain,
  each with a correct reason.

**M4 (MAJOR): two §2.3 legacy-path terminal branches have no AC (Step 2 mismatch).**
(a) Legacy gate off emits `gate_disabled` and continues to semgrep. (b) When unreadable targets and findings are
mixed, `E_RED_LINT_TARGET_UNREADABLE` takes precedence over `E_RED_ONE_SIDED_PREDICATE`. Today a GREEN that
ignores the gate on the legacy path, or that picks the code from the first hit, passes every test.
*Fix:* add AC-L1. `HAL_RED_LINT_PREFLIGHT_BATCH=0`, `HAL_ONE_SIDED_PREDICATE_GATE=0`, dirty file, empty PATH,
expect `E_RED_LINT_SEMGREP_MISSING` and `gate_disabled{gate=HAL_ONE_SIDED_PREDICATE_GATE}`. Its control is AC30
dirty. Add AC-L2. `[dirty_rel, unreadable_rel]` in that order should give `E_RED_LINT_TARGET_UNREADABLE`. Add
both rows to the §4 mutation table.

**m1 (MINOR): the D1 superset claim is wrong, and its precision effects are not recorded.**
- "The token split is a strictly finer boundary" is false. The camel-hump split can cut a codey word in two.
  `rC`, `sTatus` and `exitcODE` are codey under HAL's case-insensitive regex and not codey under tokens.
  These cases are pathological and no fixture is affected.
- The real effect is two-sided. D1 adds candidates (adversarial edge 2: `zipCode`, `countryCode`, `statusText`
  under `.not.toBeNull()`). It also adds controls (edge 1: an unrelated codey `toBe(<int>)` silences a real
  one-sided predicate).

*Fix:* correct the sentence. Add a short paragraph naming both classes and the decision taken. Add a decoy-fence
test that pins the chosen behaviour for edge 1 and edge 2.

**m2 (MINOR): the AC36 adaptation is not declared.**
HAL's AC36 builds the observed corpus by content, and its docstring explicitly warns against "compar[ing] the
artifact with its own copy". The port pins a literal tuple. The literal pin is the right instrument for bd,
because Rule P scans the target project's TS files and not bd's own tree, and bd's tree is far below HAL's
`observed >= 200` floor. The spec should still say so.
*Fix:* add one line to §3 stating the adaptation and the reason.

**m3 (MINOR): §2.3 emits `red_one_sided_predicate_violation` and `red_one_sided_predicate_unreadable_target`, but no test asserts either event.**
*Fix:* capture `_emit_safe` in AC23 and AC34 and assert each event once.

**m4 (MINOR): the requirement that the CLI holds no copy of the rule (§2.4, §1g) is not pinned.**
A driver that reimplements the regex passes AC15/16.
*Fix:* add an AST check to B3 or B4. The driver must import `bytedigger_engine.one_sided_predicate` and must
contain no `re.compile`.

**m5 (MINOR): T-B and T-C are weak evidence for the backend and provider constraints.**
- **T-B** is non-vacuous only in that its baseline must contain 1 record. Nothing on the lint path reads
  `HAL_RUNNER_BACKEND`, so after GREEN the test is invariant by construction. It is a valid regression pin. It
  is not evidence that the lint "runs on" either backend in a live sense, and no lint could provide that.
- **T-C** patches only `p5.invoke_llm_subprocess`. A GREEN that routes through `check_ladder` or calls
  `bytedigger_engine.llm_subprocess.invoke_llm_subprocess` directly would not hit the patch.

The real evidence for "deterministic, provider-agnostic" is B4, and B4 covers only the module, not the phase-5
helper.
*Fix:* add an AST or `inspect.getsource` check that `_one_sided_predicate_hits` references no
`invoke_llm*`, `check_ladder` or `bounded_run`. In §2.6, state that the both-backends constraint holds by
construction, with T-B as its regression pin.

**m6 (MINOR): §2.5 and the AC25 message mislabel `error_codes.main(["--check"])` as an .md sync check.**
It is a harvest-vs-registry check. .md sync is held by the existing `render_markdown` tests.
*Fix:* correct the wording, and name the existing md-sync tests in §3 Regression.

**m7 (MINOR): the spec has no explicit Files section.**
The touched paths are: the new module, the repo-root driver, `empty_input_assert.py`, `precommit_lints.py`,
`phase_5_implement.py`, `error_codes.py`, two `ERROR_CODES.md` files, `flags_catalog.py`, `core_manifest.json`,
and, after M1 and M2, `test_bd66_precommit_enforcement.py`.
*Fix:* list them, and mark which test edits are authorized.

## Verdict summary

The design and the RED file are mostly sound:
- The scanner port is faithful.
- Every clean side is the dirty fixture plus a control.
- The mutation table holds.
- RED is collectable and fails at assert time.

But GREEN as specified cannot reach the spec's own regression bar. bd66 AC7, AC11 and AC6c turn red (M1, M2)
unless test edits are authorized, and the spec authorizes none. The precommit lane and two legacy terminal
branches also have no AC (M3, M4). Four MAJOR findings, so the verdict is REJECTED. For r2: add the authorized
bd66 fixture edits, port AC18-20 and AC27 for bd, add AC-L1 and AC-L2, and correct the D1 wording.
