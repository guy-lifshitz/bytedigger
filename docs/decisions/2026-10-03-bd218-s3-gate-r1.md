## Inventory-lint self-scan (preflight.py)

- `class_i_lint` only scans `workflows/` and `lib/` (`_SCAN_DIRS`). `preflight.py` is not in its scope.
- `tree_scan_lint` does scan `preflight.py`. It already holds three `preflight.py` keys, for `compute_state_hash` and `_Run._changed`.
- A plain `_git(top, "diff", "-U0", mb, "--", path)` is a control under the tree-scan rules: the `f_ctl_diff` form is not a site. So the design can be implemented with no inventory change.
- That only holds if GREEN adds no `ls-files`, `status`, `add` or `--name-only/--name-status/--numstat/--stat` call. See finding 3.

## Adversarial edges (not covered by §3)

1. A change that is already committed on the branch (merge_base..HEAD) and not in the worktree. Every RED edits the worktree only.
2. A diff header `+++ b/engine_py/bytedigger_engine/lib/util/subprocess.py`. The header line starts with `+` and matches `\bsubprocess\b`, so a parser that keeps every `+` line over-triggers.
3. An untracked `.py` file that is not valid UTF-8 or is binary. A strict `read_text` raises, and the siblings step goes `red: internal error`.
4. A call spelled `'git'` (single quotes), `_git_read(`, `read_bytes(`, `json.load(`, `os.walk(` or `.rglob(`. Each of these is a lint site that the trigger regex does not match. See finding 1.
5. Not triggered while `sibling_tests` is non-empty. The spec promises a byte-identical detail, but only the empty-list `no siblings` case is asserted.
6. A sibling listed as `./engine_py/tests/test_bd94_...py` or as an absolute path. Dedupe compares exact strings, so the file runs twice.
7. Renames, CRLF and huge diffs: harmless with `-U0` plus a pathspec. A `\r` does not break the regex, and a pure rename adds no `+` lines. No action needed.

VERDICT: REJECTED

## Findings

1. **MAJOR: the trigger is a hand-written token list that misses most of the call sites the four lints actually key (§1g one canonical source, Principle B).**
   - Callees keyed by `class_i_lint`:
     - `WRAPPER_CALLEES`: `bounded_run`, `run_test_command`, `_read_text_or_empty`, `_read_or_empty`, `_git_read`, `git_read`, `rev_parse`, `status_porcelain`, `ls_files_others`, `worktree_list_porcelain`, `_run_git`
     - `_STDLIB_CALLEES`: `json.load`, `subprocess.check_output`/`run`/`Popen`
     - `_READ_CALLEES`: `read_text`, `read_bytes`
   - `tree_scan_lint.KINDS` adds `os.walk`, `scandir`, `listdir`, `glob`, `iglob`, `rglob`, `iterdir`, the helper kinds, and git argv sites.
   - The spec regex `\b(read_text|subprocess|Popen|git_read|_git_text|_git)\b` + `"git"` misses:
     - `read_bytes`, `json.load`, `bounded_run` and every walker kind
     - `_git_read` and `_read_text_or_empty`, because `\b` fails after a leading `_`
     - `'git'` in single quotes
   - test_bd94 AC9 is one of the four listed lints and is driven by tree-scan kinds, and none of those are in the trigger.
   - The rung repeats the defect it was written to fix: a hand-written list that misses siblings.
   - Fix: build the token set from the lint modules' own constants. Either import them, or keep a literal tuple plus a parity AC asserting it is a superset of `class_i_lint.WRAPPER_CALLEES ∪ _READ_CALLEES ∪ stdlib tails ∪ tree_scan_lint` callee names.
   - Add RED cases for at least `read_bytes(`, `_git_read(` and `os.walk(`. The "Limit stated" line should only cover spellings outside these sets.

2. **MAJOR: the §1a sibling audit is incomplete.** A grep for `tree_scan_lint|class_i_lint|*_inventory` in `engine_py/tests` finds two real-tree lint guards that are not in §4:
   - `test_bd89_p3c_deterministic_synthesize_report.py::test_ac15_guard_tree_scan_lint_real_tree_clean`. It scans `preflight.py` directly.
   - `test_bd89_p3b1b_ii_aggregation_helper.py::test_ac12_guard_class_i_lint_and_inventory_key`.

   Add both to §4. Also decide, and record in §2, whether they belong in `INVENTORY_LINT_TESTS`. They are real-tree lint guards of the same class, and if left out the rung's set is again a partial hand list.

3. **MINOR: state the implementation constraint precisely.**
   - The new code MUST get untracked names from `self._changed()`, which is already keyed as `_changed::git-ls-files#0`.
   - Any new `_git(... "ls-files" | "status" | "add" ...)` call, or any `diff` with `--name-only/--name-status/--numstat/--stat`, inside the new function is an unkeyed tree-scan site, and `conformance/*` is out of scope.
   - "Reuse `_git`" alone is not enough, because `_git(r, "ls-files", ...)` is itself a site (form `f_varargs`).

4. **MINOR: parse only real `+` content lines.** Skip `+++ `/`--- ` headers (edge 2) and read untracked files with `errors="replace"` (edge 3).

5. **MINOR (§1n): state how a git failure inside the trigger fails.** Today it would surface as `siblings red: internal error: git diff failed`, which fails closed. Write that in §2, or catch the error and treat it as triggered.

6. **MINOR: pin the suffix.** Define N (appended vs run), the separator, and whether the suffix appears when N=0 because every lint file is already listed.

7. **MINOR: cover the remaining edges.**
   - Add a case for a committed branch change (edge 1).
   - Add a non-trigger case with a non-empty `sibling_tests`, asserting the detail is unchanged (edge 5).
   - Normalise the sibling paths before dedupe (edge 6).

8. **MINOR (§1b): the "10-second local run" claim in §1 is unmeasured.** The rung adds four whole test files (bd94 is about 1.2k lines), and finding 2 may add two more, to every engine-diff preflight. Measure the wall time before freeze and record it.
