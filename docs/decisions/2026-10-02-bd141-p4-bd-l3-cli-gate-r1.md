The only `"type":` event builders in the package are in `harness.py:94,175,200`. Other `"type"` hits (`llm_subprocess.py:3295`, `anthropic_api.py`, `phase_45_spec*.py`) are payload records, API blocks, or prompt text. None of them is an event-log event. So R3.x `failed` cannot be reached on a production log.
- The line citations hold: `bd_l3.py:249/263`, `check_ladder.py:228-287`.
- No token drift. `_main`, `event_type`/`type`, `events_read`, `run_id`, `bd_l3: `, and `EVENT_TYPE` are used the same way throughout the document.
- `conformance/__init__.py` executes no statements. Nothing in the import chain of `bd_l3` (`attest`, `tokens`, `report`, `lib.llm_provider`) imports `bd_l3` again. So `python -m` will not raise the runpy "found in sys.modules" RuntimeWarning. That warning would have prefixed stderr and broken AC8.

## Step 1.5: rule-overlap simulation

- **Filter (§2.1):** non-dict → skip; `event_type == ET` or `type == ET` → read; otherwise skip. AC2 (`event_type` only) → read. AC3 (`type` only) → read. AC4 (foreign `event_type`, no `type`) → skip. AC1 (real log) → read. Every expected outcome is reached by the first matching branch. Case not exercised: both keys present with different values (see Adversarial edges).
- **CLI dispatch (§2.2):** argv error → 2; OSError → 2; UTF-8 error → 2; bad JSON line → 2 with stdout empty, even when line 1 parsed; otherwise rc 0 for any report. AC8 and AC1 (rc 0 with `passed=false`) are consistent with this. One GREEN hazard: argparse's default `error()` prints `usage: ...` before `bd_l3: error:`, so a stock argparse fails AC8. GREEN has to override `error()` or catch `SystemExit`. This is correct test behaviour, not a defect.

## Adversarial edges (not covered by the §3 AC table)

1. **Both keys present and disagreeing:** `{"type": ET, "event_type": "other"}` and the reverse. §2.1 says read (OR). A GREEN that writes `event.get("event_type") or event.get("type")` skips the first case. No test covers it.
2. **Non-object JSON line combined with `--run-id`:** a line such as `[1]` or `null` plus `--run-id A`. A naive `e.get("run_id")` raises AttributeError, and the run ends in a traceback with rc 1. The spec does not say whether non-objects survive the run-id filter. Without the filter, AC-free: a non-object line must be counted in `events_read`.
3. **Missing parent directory:** `--event-log /tmp/nonexistent-dir/x.jsonl`. A GREEN that reuses `EventLog(path).read_all()` calls `mkdir(parents=True)` (`event_log.py:109`). That creates a directory, which breaks "never writes", while still returning `[]` and rc 0 instead of rc 2. AC8 missing_file does not catch this, because its parent directory exists.
4. **Invalid UTF-8 inside an otherwise valid JSON string**, e.g. `b'{"a":"\xff"}\n'`. This tells a strict decode apart from `errors="replace"` (see F8).
5. **UTF-8 BOM at byte 0:** `json.loads` rejects it, which yields rc 2. `EventLog` never writes a BOM, so rc 2 is acceptable, but the spec does not state it. Advisory.
6. **Non-string `run_id` in the log** (e.g. `7`): `--run-id 7` does not match `7 == "7"`. That is correct strict behaviour, but unspecified. Advisory.
7. **Huge logs:** the CLI holds every event in memory. Acceptable for `events.jsonl` sizes. Advisory: iterate line by line, and print nothing until the whole file has parsed (stdout must stay empty when the last line is malformed).
8. **Path is a directory:** `IsADirectoryError` is an `OSError` and must give rc 2. Not tested (see F6).

## Findings

1. **MAJOR: AC8 malformed_line, the line-number clause cannot fail.** The test writes `'{"a": 1}\n{not json\n'` and asserts `"2" in proc.stderr`. `str(JSONDecodeError)` for `{not json` is `Expecting property name enclosed in double quotes: line 1 column 2 (char 1)`, which already contains "2". The pytest `tmp_path` in the message will usually contain a "2" as well. A GREEN that never reports the 1-based line number still passes. Fix: pin a message form in §2.2 (e.g. `line N`), put the bad line at line 3 or later after valid lines, and assert `re.search(r"\bline 3\b", stderr)`. The decoder's own text says `line 1`, so it cannot satisfy that assertion.
2. **MAJOR: AC8 unknown_flag is vacuous.** It passes `--event-log <tmp>/x.jsonl --bogus`, and `x.jsonl` does not exist. A CLI that silently ignores unknown flags (`parse_known_args`) still exits 2 with `bd_l3: ` through the missing-file path. No code change turns this case red on its own. Fix: create a valid log for this case. Also add a positional-argument case, which §2.2 lists.
3. **MAJOR: the same defect in a sibling class is neither fixed nor declared.** `conformance/bd_l2.py:261` (`event_type = event.get("type")` in `check_bd_l2`) has the same `type`-only read. R2.x `failed` is therefore just as unreachable on a production log. The spec declares Class SYSTEMATIC and treats `check_bd_l3` as the chokepoint. The defect class is "conformance checkers read only the harness shape", and it spans both checkers. `bd_l3`'s own docstring calls this pattern the way "the same class survived three lots in a row". Fix (cheap): add a §5 entry naming `bd_l2.py:261` with a filed follow-up issue, and say in §1 that the class covers both checkers. Bringing `bd_l2` into scope is optional.
4. **MINOR: AC9 is weaker than the sibling test it claims to re-assert.** It excludes `types.ModuleType` values, so an unaliased `import json` in `bd_l3` passes AC9. `test_bd28::test_ac8` uses `{n for n in vars(bd_l3) if not n.startswith("_")}` with no exclusion and still catches it in-suite. Drop the exclusion so AC9 matches the claim.
5. **MINOR:** §2.2 says non-object lines are "passed through and counted in `events_read`", but no AC covers it. It also leaves the interaction with `--run-id` unspecified (edge 2), and that interaction can crash. Specify it and add one test.
6. **MINOR:** the §2.2 rc-2 cases "positional" and "not readable" (an existing but unreadable path, or a directory) have no AC8 case.
7. **MINOR:** "never imports `llm_subprocess`" is a §2.2 claim with no AC. A subprocess test asserting `"bytedigger_engine.llm_subprocess" not in sys.modules` after `_main` would enforce it. Otherwise, reword it as intent.
8. **MINOR:** the AC8 invalid_utf8 fixture (`\xff\xfe\x00`) cannot tell a strict decode from `errors="replace"`, because both reach rc 2. Use invalid bytes inside a valid JSON string (edge 4).
9. **MINOR:** AC5 `complaints == []` would also pass with a hard-coded `[]`. Advisory only: a checker-produced report always validates, so no CLI-level fixture can force a complaint.
10. **MINOR:** missing-parent-directory writes (edge 3). Add a case to AC10 or AC8 asserting that the parent directory is not created and rc is 2.

Scope and siblings: the 8 sibling files in §1.3 all build `{"type": ...}` events, and the OR filter keeps those working. AC9 and `test_bd28::test_ac8` pin the surface (`_main` and aliased imports are allowed under B-2). No other sibling risk found apart from F3.

VERDICT: REJECTED
