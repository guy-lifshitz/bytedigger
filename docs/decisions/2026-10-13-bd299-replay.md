# bd#299 baseline-delta driver replay on real CI logs

## Method

Data: the last 20 merged PRs of this repo (gh pr list --state merged). For each merge commit on main, the ci.yml run, job "pytest", was fetched with gh run view --log, and the output of the step `python -m pytest tests/ -q -p no:cacheprovider --timeout=120` (through the final summary line) was saved with the GitHub timestamp and job/step prefixes stripped. 16 PRs yielded a green log; 4 were skipped (PR#298 CI still in progress at fetch time; PR#284, #280, #279 CI run conclusion cancelled). Every used run was green, so base_fails = [] for all real cases (base = parent on main, assumed no fails). Each log was fed to scripts/baseline_delta_replay.py, which runs baseline_delta_gate.py with --suite pytest --require-corpus-parity --base-ref HEAD (local ref, no network). Two seeded cases were derived from the PR#295 log: (a) a FAILED tests/x.py::seeded_regression line appended and summary changed to "1 failed, 9733 passed, ..."; (b) the summary line removed (the incoherent/no-summary case). Driver and script were not modified.

Limits: -q logs contain no collected-file lines, so corpus_scope is "no_file_oracle" on every row (corpus scope not verifiable from the log); in this data that did not produce a BLOCKED on the real green logs. All real cases are green, so this measures false blocks only, not detection of real regressions; detection is covered only by the 2 seeded cases. Base-ref HEAD is the worktree HEAD (lot-299), not each PR's actual parent. One CI run per PR; no flaky/red history sampled.
