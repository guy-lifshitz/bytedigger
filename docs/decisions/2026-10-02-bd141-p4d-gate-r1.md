## Adversarial edges (not covered by any §3 AC)

1. **Stale record carried by a `{**prev.data}` spread.** Once GREEN puts `role_template` into the `extra_data` of the GREEN and fix dispatches
   (AC8 forces this), invoke results carry the record downstream. `phase_5_implement` has 46 spreads and `phase_6_review` has 9. If a later
   prompt-carrying dict on a role-less branch inherits the record, `_declared_injections` declares content that is not in the prompt. The
   result is `E_INJECT_UNATTRIBUTED`, `recoverable=False`, a hard build stop. `phase_45_spec` is safe because `_fwd_frozen` threads a whitelist
   (:5128). No test covers this (F4).
2. **Double read in the string-returning builders.** If GREEN records phase_1/phase_4/the rewrite by calling `_role_template(ctx)` a second
   time in the dict-building caller, a template edited between the two reads gives record ≠ prompt bytes. The result is a fail-closed refusal on
   an otherwise healthy run. Nothing in the spec requires the record and the prompt to come from one `RoleTemplate` (folded into F1).
3. **A `role_template_path` change between build and dispatch, or on retry.** This is safe as designed: the dispatch and the retry read the stored
   record and prompt, never the file. AC8 pins it for the retry. No finding.
4. **Engine re-entry into `_write_green_artifact` with a plain dict** (GH1626 part D, `phase_5_implement.py:7616-7621`). If the reconstructed
   dict lacks `role_template`, the retry declares `()` while the prompt still contains the role, so R3.2 is silently `not-checked` there. It is not
   a refusal (F6, advisory).
5. **Skipped/passthrough steps** (`passthrough_if_skipped`, frozen `status="skip"` at `phase_45_spec_lite.py:461-467`,
   `phase_45_spec.py:1323-1329`). They never dispatch, so they declare nothing. No finding.
6. **phase_45_spec repoll** (:4150 via `invoke_kwargs`). If `injections` goes into the `dict(...)` at :4186, both the first call and every repoll
   carry it, and `_param_declares` follows the parameter correctly. No finding.

Taken on its own, §6 is an honest increment. Each deferred segment has a real, separate design question (truncation for a per-chunk rule, an
undefined source id for the bun standards context, a synthetic id for facts). Declaring only the role template is truthful under the existing

(a) `AUTHORSHIP_SPEC.md:371` ("one of eight role-template inlining sites is migrated") and the re-open criterion at :457-461 become stale

is exactly AUTHORSHIP_SPEC's re-open criterion, so the issue has to exist before R3.2 starts reporting `passed` on those steps.

## Findings

**F1 MAJOR: the 17th role-template producer is missing, and §2.2 is wrong for the string-returning builders.**
`phase_45_spec_lite.py:421-449` (`_maybe_rewrite_simple_spec_prompt`) embeds phase_1's role-bearing prompt and returns its own data dict to the
:481 dispatch. The spec's ":481 takes them from the phase_1 builder result" (§1.4, §2.3) is false. No AC3 driver exists for it. A GREEN that follows
§2.2 literally passes every RED test while :481 declares `()`. `phase_1_discovery.py:349/400` and `phase_4_architect.py:214/256`
return `str`, so §2.2's "adds the key to the data dict it returns" does not apply there. **Fix:** list `_maybe_rewrite_simple_spec_prompt` as producer 17
(free-rewrite branch carries the record; restricted-writer branch at :400-418 carries `None`). Specify that the role-placing function
receives or returns the single `RoleTemplate`, so the record and the prompt bytes come from one read (no second `_role_template(ctx)` in the
caller). Add an AC3 driver for the rewrite step (cycle ≥ 2, unstructured prior review).

**F2 MAJOR: two sibling tests go red, and §2.1's "the four patches still pass" is false.**
`test_34AEB235_green_typecheck_gate.py:674,717` (`monkeypatch.setattr(..., "_maybe_role_template", ...)` without `raising=False`) and
`test_261_PH56SPLIT_stage0_common.py:110-123` (re-export identity of `_maybe_role_template` in phase_5_implement and phase_6_review) cannot both
pass alongside the RED's AC2, which bans the import (`test_bd141_p4d...py:244-245`). **Fix:** add both files to §5 with the exact edit:
drop `_maybe_role_template` from `_HELPER_NAMES` in test_261, or carve it out of the re-export check with a comment citing this lot; add
`raising=False` to (or delete) the two test_34AEB235 patches. Correct §2.1's claim. Forbid workarounds that hide the name from the AST
(`globals()`, star imports).

**F3 MAJOR: AC5 is structural only and passes when nothing is declared; the pool path has no teeth.**
`_declaring_value` (`test_bd141_p4d...py:443-450`) accepts any Name/Attribute and any argument to a declare helper. So
`injections=_declared_injections(prev)` (a StepResult, which returns `()`, an easy slip because phase_2's helper does take `prev`) and a
defaulted, unwired `injections=injections` at `phase_6_review.py:3044` both pass, and nothing drives COMPLEX satisfaction. 16 of the 22
dispatches have no behavioural check. **Fix:** add a parametrized behavioural matrix that reuses the AC3 drivers. For each dispatch, feed the builder's
real output into its invoke step, with a module-attribute spy on `invoke_llm_subprocess` (the AC8 pattern), and assert
`injections == (InjectedBlock(source_id, ROLE_CONTENT),)`. Include `_invoke_satisfaction_llm` with `complexity="COMPLEX"` (all 3 pool calls),
:4201 plus a repoll, and :481. In §2.3, specify the pool plumbing: a new parameter on `_run_satisfaction_evaluators_parallel`, passed from :3261.

**F4 MINOR: stale-record leak through `{**prev.data}` (adversarial edge 1).** **Fix:** in §2.2, require every prompt-carrying dict in the 17
producers to set `role_template` explicitly (`None` on role-less branches). Add one RED that runs a role-less branch (for example `phase_45_spec_lite._build_review_prompt`
at cycle 2 with structured findings) with a `prev.data` that carries a record, and asserts the output record is `None`.

**F5 MINOR: doc and issue debt on the scope boundary.** `conformance/AUTHORSHIP_SPEC.md:371,457-461` go stale. §6's follow-up issue is unnamed.
**Fix:** add the AUTHORSHIP_SPEC update to §5 and name the issue number in §6.

**F6 MINOR: re-entry into `_write_green_artifact` from a reconstructed dict declares `()`** (`phase_5_implement.py:7616-7621`). **Fix:** state it in
§7 as a known not-checked path, or carry `role_template` in the re-entry dict.

**F7 NIT:** `_injection_refusal` is at `llm_subprocess.py:1014` (spec §1.1 says :1012). The AC5 docstring in the RED still calls the pool path a "spec
gap", but r1.1 already absorbed it, so the docstring is outdated.
