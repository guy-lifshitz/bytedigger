## Adversarial edges (not covered by any §3 AC)

1. **Steps that write deterministic artifacts into the work tree.** Example: a RED test or `bun test` that creates a non-ignored file. With the pre-step hash, the first receipt is always stale. A second run is fresh only if the artifact's content is byte-identical. An artifact containing timestamps makes the receipt stale forever. This is intended behaviour, but the module docstring should document it so hosts do not loop.
2. **`compute_state_hash` failing inside `run_preflight` at point 5.** The spec does not say whether this raises or exits 2 (GIT). By then the receipt is already deleted, so this is fail-safe, but it is unspecified. A HAL-style port that turns git failures into `""` (`lot-gate-policy.ts:100-102` uses `?? ""`) could hash degraded output both at receipt time and at verify time, and so report `fresh` while git is persistently broken.
3. **CLI-level USAGE (`--classifier-cmd` bad) does not reach `run_preflight`,** so an older green receipt survives. This is sound because verify re-hashes, but it is an asymmetry with "every later exit starts from no receipt".
4. **Same-process re-run after an edit that turns a `wrong_file` citation into `unresolved_symbol`.** This is the scenario the memo pop exists for (MINOR-A).

## Findings

1. **MINOR-A: the cite memo pop (spec:88-90) has no AC or RED.**
   - A GREEN that omits the pop passes all 54 tests.
   - Fix (RED rev3, optional): in one process, run with a body citing `calc.py` `helper_zz` where `helper_zz` is defined only in an untracked `other.py`. The status is `wrong_file`, which is advisory, so exit 0.
   - Then remove `other.py` and re-run. Expect `E_PREFLIGHT_CITE`.
2. **MINOR-B: verify "hash computation fails, stale" (spec:135) has no RED.**
   - Fix: write garbage to `<git-dir>/index` after a fresh receipt; `git status` then fails while `rev-parse` still works. Expect `"stale"` and no exception.
   - Also specify that `compute_state_hash` raises on any git failure, never degrades to `""` (edge 2). In `run_preflight`, that failure gives exit 2 `E_PREFLIGHT_GIT`.
3. **MINOR-C: "neither `--spec` nor `--verify`" is not declared an argparse error.**
   - test:791/794 depend on argparse handling it. A GREEN that answers with `E_PREFLIGHT_SPEC_FIELDS` and a JSON doc fails test:796.
   - The bad-`--classifier-cmd` path, by contrast, must emit a JSON doc (test:789). The spec's sentence "the one-JSON-document rule covers runs that reach `run_preflight`" could be read to exclude that path.
   - Fix (spec): "`--spec` and `--verify` form a required mutually-exclusive argparse group. `--classifier-cmd` validation happens after parsing and emits the exit-2 JSON doc under `--json`."
4. **MINOR-D: token drift at spec:78.**
   - "An exception inside steps 1–7" now collides with op4's numbered points 1-7.
   - Fix: "inside any of the first seven `STEPS` (syntax … facts)".

   - The RED docstring (test:3) says r1.
