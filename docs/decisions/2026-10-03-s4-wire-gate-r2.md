## New-defect review (feasibility)

- **Budget in pure bash 3.2 under `set -euo pipefail` (macOS and Linux): feasible.** The shape is:
  1. `python3 "$script" --root "$CWD" --timeout 3 >"$tmp" 2>/dev/null &` then `pid=$!`. A simple background command is exec'd by the forked child, so `$!` is the python PID, which AC9 checks.
  2. Poll with `kill -0 "$pid"` and fractional `sleep`, which both BSD and GNU support, against `$SECONDS`.
  3. On overrun, `kill "$pid"` (python has no SIGTERM handler: `devops_scan.py` imports `signal` only for `SIGKILL` at `:199`) and then `wait "$pid" || rc=$?`.

  GREEN must guard `wait`, `kill -0` and any `(( ))` against `set -e`. That is an implementation detail and not a spec defect.
- **Killing the child process tree.** Scanner subprocesses (hadolint, trivy) are started with `start_new_session=True` and `stdout/stderr=PIPE` to python (`devops_scan.py:184-191`). When the gate kills python, an in-flight scanner is orphaned in its own session. It keeps running until it finishes on its own, because its `--timeout 3` is enforced by the dead python. It does **not** hold the hook's stdout/stderr pipes, so it cannot stall the dispatcher's `$( )` capture (`gate-dispatcher.sh:152`) or the harness. The result is a resource leak, not a hang and not a fail-open (minor 4).
- **printf-based JSON event and sanitising: feasible.** All fields are either constants, digits, a validated ISO date, or scanner-derived text that has backslash, `"` and C0 controls stripped (for example `tr -d '\000-\037'`, plus sed). The result is valid JSON for any input with ASCII-safe constants. The spec restricts sanitising to "scanner-derived text". If GREEN puts the script path or `$CWD` into a reason (for example "script_missing: <path>"), a `"` in the path breaks the hard_block JSON (minor 5). Existing `hard_block` (`:483-486`) does not escape at all, so sanitising must happen at the call site or move into `hard_block`.
- **Hook output.**
  - SHADOW stdout stays empty, which AC1, AC6, AC9 and AC10(b) fence.
  - The soft block JSON is unchanged (AC10(a)).
  - ENFORCE emits exactly one JSON object (AC10(d) `json.loads` on the whole stdout).
  - Under `shadow` backend the SHADOW WARN lands in `dispatcher-stderr.log`, and on exit 0 the harness shows stderr only in verbose/transcript. The event file is therefore the real channel of record. This is advisory for the flip decision.

## Adversarial edges (not covered by the section 2 AC list)

1. **Orphaned grandchild on budget kill:** a fake that spawns a `sleep 60` child with `start_new_session=True` and then sleeps itself. After the gate returns, the grandchild is still alive. No pipe stall occurs, but it leaks.
2. **AC9 with stdout as a pipe** (`bash gate | cat`, modelling the dispatcher's `$( )`): a GREEN that leaves the background scan attached to the gate's stdout would stall here. AC9 catches this indirectly through `assert_fake_dead`.
3. **Gate killed externally mid-scan** (harness SIGTERM, Ctrl-C): there is no EXIT/TERM trap that kills the background scan or removes the temp file.
4. **rc 1 with non-JSON stdout:** row ambiguity (blocked with count 0 vs unavailable).
5. **Path-derived reason text** with `"` in `$CWD` or in the override path inside an ENFORCE unavailable message.
6. **Concurrent 5.5 SubagentStops:** two parallel 8 s scans, each appending one printf line to the same jsonl.
7. **Budget boundary:** a scan that completes at about 8 s, racing with the kill. The verdict must come from `wait`'s rc, and a kill-then-wait must report `budget_exceeded`, not a signal rc such as 143 mapped to "other rc".

## Findings

### MAJOR

### minor (advisory)

1. State in section 1 that the event field types are JSON number for `rc`/`gating` and JSON boolean for `flag.expired`. RED already requires the boolean (`True`/`False` repr).
2. The ENFORCE precondition (TS port plus parity) lives only in the PR body and an OFI. Also put a comment next to `DEVOPS_SCAN_ENFORCE` in `build-gate.sh`. Optionally, have the dispatcher emit a stderr WARN when the backend is `ts` and `DEVOPS_SCAN_ENFORCE=1`.
3. Define rc 1 with non-JSON or no-`gating` stdout. The suggested text is `devops_scan blocked: unknown gating finding(s)`, or route it to unavailable. Exit codes are unaffected.
4. Record the orphaned-scanner leak as an accepted limit. Alternatively, file a follow-up so `devops_scan.py` installs a SIGTERM handler that killpg's its in-flight scanner. Changing `devops_scan.py` is out of scope here.
5. Extend sanitising to every text placed into `hard_block` and the event, including paths. Simpler still: make `hard_block` reuse `block`'s escaping sed.
6. Add an EXIT trap in `run_devops_scan` that kills the background PID and removes the temp file (edge 3).
7. Under SIGTERM, `wait` returns 143. Map a gate-initiated kill to `budget_exceeded` explicitly, not through the "other rc" path (edge 7). AC9 already asserts the `budget_exceeded` text, so a wrong mapping fails RED.
8. With real repos, hadolint/trivy runs are sequential at 3 s each, so a repo with three or more Dockerfiles or IaC dirs routinely exceeds 8 s. That means SHADOW unavailable on every 5.5 stop, and a permanent hard block under ENFORCE. Record this as an owner input for the flip, together with r1 minor 9 (full-tree scan).
9. Each AC9 cell takes about 8 s of wall time because the budget has no test seam. This is acceptable, but CI time grows by about 16 s.
