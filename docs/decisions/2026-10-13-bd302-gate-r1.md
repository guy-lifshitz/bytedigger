## Findings

F1 (MAJOR) engine_py/tests/test_bd66_precommit_enforcement.py:1219-1225 (AC11), with its docstring :1175-1202 and assertion message :1240-1246. AC11 is the "plan branch on the canonical DEFAULT_LINT_DIR path with `BD66_LINT_DIR` deleted" pin. Before the edit the violating driver sat inside the package directory (DEFAULT_LINT_DIR) with the name unmapped; the only way for rc 1 was `resolve_lint_dir()` falling back to DEFAULT_LINT_DIR and executing it. After the edit the driver sits at the clone root, which is where `LINT_DRIVER_DIRS` resolves the name (precommit_lints.py:45-46), so the lint dir is never consulted: a `resolve_lint_dir` that returns `""`, cwd or a nonexistent path when the override is unset still yields rc 1 and passes. No other test pins it: AC12 (:1270-1281) asserts only the attribute `DEFAULT_LINT_DIR`; AC6c (:1432-1493) is a pre-pass refusal that a wrong default dir also produces; bd81 AC3 and bd166 go through the mapping; AC5/AC7/AC10 use the override. This is an assertion that kept its name and lost its discriminating power. Fix: keep a driver in DEFAULT_LINT_DIR with an UNMAPPED name, e.g. append `phantom-canon-lint` to the copied TEST_LINTS as AC6c does, write the exit-1 stand-in at `pkg/phantom-canon-lint.py`, leave it undeclared, and keep rc 1 + VIOLATION. The real-driver refusal is already covered by bd302 AC1/AC2, so AC11 does not need the SP name at all. Also restore the docstring sentence mangled at :1182-1184 ("the copied registry drops `stub-passability-lint` is given a driver ...").
