# bd#141 item 4 (c/d/e): `bd_l3` host CLI, and the checker reads the on-disk event shape

**Status:** r1 (draft, pre-gate) · **Tier:** 2 (one engine prod `.py` + one new test file, Option D) ·
**Class:** SYSTEMATIC · **Chokepoint:** `conformance/bd_l3.check_bd_l3`, the single adjudicator of
R3.1/R3.2/R3.3/R3.5/R3.6, and its event filter.
**Source:** bd#141 item 4 (§7.4 portable set); hal-v2 host-adapter request (MGR, 2026-10-02). Pairs with
hal-v2 `SYSTEM/cli/jev/bd-l3-verdict` (a later PR, not in scope here).

## §1 Problem (measured on `af2542a`)

1. **No host surface.** The (c) effective-prompt hash, (d) injected-content attribution and (e)
   model-identity controls are adjudicated by `check_bd_l3(events) -> L0Report` (`bd_l3.py:249`).
   The module has no `__main__`; the only callers are tests and `conformance/harness.py`. A host that
   wants the engine's verdict must import private wiring or re-implement the checks. `check_ladder`
   (`check_ladder.py:228-287`) is the only control with a host CLI today.
2. **The checker cannot see a real log.** `EventLog.append` (`event_log.py:123-128`) writes
   `{"ts","run_id","event_type","payload"}`. `llm_subprocess._emit_safe` (`:3603-3608`) writes
   `model_invocation_attested` through it. `check_bd_l3` keeps only events where
   `event.get("type") == attest.EVENT_TYPE` (`bd_l3.py:263`). The key `type` is the harness/test
   shape (`harness.py:94,175,200`); no production writer emits it. Fed a real `events.jsonl`, every
   requirement comes back `not-checked` and `violations == ()`: R3.x `failed` is unreachable on
   production input. Every existing test builds `{"type": ...}` events, which is why it never showed.
3. §1a sibling audit (tests importing `bd_l3`): `test_bd28_bd_l3_checker.py`,
   `test_bd10_l3_authorship.py`, `test_bd58_adversary_harness.py`, `test_bd63_r35_enforcement_falsifiable.py`,
   `test_bd68_l3_observation_producers.py`, `test_bd71_agent_sdk_observations.py`,
   `test_bd73_r31_r32_verdicts.py`, `test_bd141_p4e_subprocess_observed_model.py`. All use the
   `type` key, which stays accepted, so none should change. `test_bd28::test_ac8` pins
   `set(__all__)` and the public surface; this change adds no public name.

## §2 Design

**2.1 Filter (the class fix).** In `check_bd_l3`, an event is read when it is a `dict` whose
`event_type` **or** `type` equals `attest.EVENT_TYPE`. Nothing else about the checks changes.
Fixing it in the checker, not in the CLI, closes it for every consumer (harness, CLI, future hosts).

**2.2 CLI.** `python -m bytedigger_engine.conformance.bd_l3 --event-log PATH [--run-id ID]`.

- `--event-log` is required. `PATH` is read as UTF-8 JSONL; blank (whitespace-only) lines are skipped.
- `--run-id ID`: only events whose top-level `run_id == ID` are passed to the checker. Without it,
  every parsed event is passed.
- Success: exactly one line on stdout, a JSON object with exactly these keys:
  - `passed` (bool), `requirements` (list[str]), `violations` (list[str]), `labels` (object) — the
    `L0Report` fields, unchanged;
  - `complaints` (list[str]) — `validate_report(report)`;
  - `events_read` (int) — number of events passed to `check_bd_l3` (after the `--run-id` filter);
  - `run_id` (str or null) — the `--run-id` value echoed.

  Exit code **0 for any report**, including `passed: false` (same contract as `check_ladder`: the
  verdict is in the JSON, the exit code means "a report was produced").
- Usage/input errors: exit **2**, nothing on stdout, one message on stderr starting `bd_l3: `.
  Cases: `--event-log` missing; unknown flag or positional; file missing or not readable
  (`OSError`); a non-blank line that is not valid JSON (message names the 1-based line number);
  invalid UTF-8. Lines that parse to a non-object JSON value are passed through (the checker
  already ignores them) and counted in `events_read`.
- Mode: read-only. The CLI never writes, never appends to the log, never imports `llm_subprocess`.
- Surface: `__all__` and the set of public names are unchanged. New names are underscore-prefixed
  (`_main`, and stdlib imports aliased `import json as _json` etc.), per the module's B-2 rule.
  Guard: `if __name__ == "__main__": _sys.exit(_main())`. `_main(argv=None)` returns the exit code.

## §3 Acceptance criteria

- **AC1 (side-effect, §1l):** a log written by the real `EventLog.append` (no hand-built line) with one
  `model_invocation_attested` event whose payload violates R3.3 (`model_requested` and `observed_model` resolve to different families, e.g. a sonnet id vs a haiku id, the pair test_bd28 AC1 already uses)
  → subprocess `python -m bytedigger_engine.conformance.bd_l3 --event-log P` exits 0, stdout parses,
  `labels["verdict:R3.3"] == "failed"`, `passed is False`, a violation starts with `R3.3:`.
  Turns red on `af2542a` (filter reads only `type`).
- **AC2:** `check_bd_l3([{"event_type": EVENT_TYPE, "payload": <R3.3-violating>}])` → R3.3 `failed`
  (in-process, the filter alone).
- **AC3:** legacy `{"type": EVENT_TYPE, ...}` events give the same verdicts as before (one passing
  and one failing case), so harness callers are unaffected.
- **AC4:** a log holding only an R3.3-violating payload under a different `event_type`
  (e.g. `model_pin_mismatch`) and no `type` key → `events_read == 1`, R3.3 `not-checked`,
  `violations == []` (the filter still filters).
- **AC5:** output key set is exactly `{passed, requirements, violations, labels, complaints,
  events_read, run_id}`; `complaints == []` for a checker-produced report; `run_id` is `null`
  without `--run-id`.
- **AC6:** `--run-id A` on a log with a failing event under run `B` and a passing one under `A` →
  R3.3 not `failed`, `events_read == 1`, `run_id == "A"`; `--run-id B` → R3.3 `failed`.
- **AC7:** empty file → rc 0, `events_read == 0`, `passed is False`, every `verdict:R3.x` is
  `not-checked` (the inverted-oracle guard from the module docstring holds through the CLI).
- **AC8:** rc 2, empty stdout, stderr starts `bd_l3: ` for each of: no `--event-log`; unknown flag;
  missing file; a malformed JSON line (stderr contains the line number); invalid UTF-8 bytes.
- **AC9:** `set(bd_l3.__all__)` unchanged and no new public (non-underscore) module attribute
  (re-asserts `test_bd28::test_ac8` from this lot's side).
- **AC10:** the CLI leaves the log byte-identical (read-only), checked by hashing before/after.
