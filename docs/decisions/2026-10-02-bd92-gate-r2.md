## Focus questions

**(a) Cycle-1 unlink of `.findings-thread.json`: can a legitimate flow lose a needed thread?**
- **Engine retries (gate retry, frozen fallback, REVISE retry, D3 retry):** never cycle 1. `next_cycle = cycle_count + 1` (`engine.py:705`), and the forwarded `initial_data` already carries `structured_findings` (`revise_fwd`, :4879). Safe.
- **Reroute:** cycle-1 entry is exactly the intended attempt boundary. Safe.
- **Driver crash-resume:** `execute()` restarts at cycle 1, so the unlink fires. The chain re-derives the thread, though. `invoke_review_llm` is sentinel-cached per cycle (:5008), and `gate_on_review` re-executes on the cached raw review and re-persists the same `(run_id, cycle)` thread. If the sentinels were invalidated (terminal `invalidate_cycle_sentinels_on_fail`, :4856), the reviewer re-runs and produces a fresh thread. Safe.
- **DBOS recovery:** a recorded `build_spec_prompt` row is replayed, not executed, so there is no unlink. Safe.
- **The only casualty is test-level:** gh636 `test_ac8` (M-r2-1).

**(b) Unlink after the SHIP return.**
- One non-SHIP path is reachable before the unlink: the D3-hit REVISE-equivalent inside the SHIP branch (:4592-4594). It is unjustified in the spec (m-r2-3).
- No SHIP path needs the sidecar absent: `_finalize_ship_verdict` writes it.
- Every other non-SHIP branch sits after the unlink. ✓
- The unlink needs `prev.data["spec_path"]`. It is present on the `write_review_doc` output (:4357), but the spec should say `.get()` plus a swallowed KeyError/TypeError ("fail-safe" covers it, advisory).

**(c) `resume_sentinel_glob` through placeholder substitution.**
- Workable. `resume_key_lint` R1 fires only on a string node that fullmatches `[\w{}.]*_done_c[\w{}.]*\.json` (`resume_key_lint.py:28,105`). A builder that calls `resume_sentinel_name(step, <placeholder>, run_id, <placeholder-hash>|None, wf)` and then `str.replace`s the placeholders adds no such literal.
- Unpinned details (m-r2-2):
  - The placeholder must not be a substring of step/run/workflow names (use a NUL-bearing token, or an int cycle such as `-1` that never occurs).
  - The hash placeholder must survive the `[:12]` truncation (`resume_keying.py:32`).
  - `cycle: int` in `resume_sentinel_name` is mypy-strict. Passing `"*"` through it needs a widened annotation or an int placeholder.
- Glob metacharacters in run_ids: `run_id` is still interpolated raw, which is pre-existing behaviour, documented out of contract (`step_sentinel.py:179-181`) and not widened by r2. Advisory: `glob.escape` the non-wildcard segments.
- Overmatch: simulated `c*` against `_r{rid}.json` / `_r{rid}_h*.json`. Matching needs the literal `_r{rid}` immediately before `.json`/`_h`. An unprefixed glob is anchored at `step_done_c`, so `s` cannot match `s_x`. The only theoretical overmatch is a run_id that is itself `…_r<other>`. uuid hex cannot produce it.

**(d) AC1/AC2 cannot tell `doc_path` from `REVIEW_DOC_RELPATH`.**
- Acceptable. The only producer builds `doc_path` from `scratchpad / REVIEW_DOC_RELPATH` (`phase_6_review.py:762, :1000`), so the two are equal by construction.
- An AC with divergent paths would test a configuration that cannot occur.
- Advisory: phase 7 (`phase_7_synthesize.py:433`) and `phase_6_review.py:5365` read `REVIEW_DOC_RELPATH` directly. The spec's "one unlink covers both readers" holds only while that equality holds. It also does not cover the phase-6-skipped case, which r1 m7 asked to declare out of scope.

**(e) Vacuous or unreachable ACs.**

- AC15c :308 is a vacuous line inside an otherwise valid positive control (advisory).
- AC5 is meaningful: same run, stored cycle 2, for_cycle 3, so only the `gate_retry` exclusion keeps the thread out.
