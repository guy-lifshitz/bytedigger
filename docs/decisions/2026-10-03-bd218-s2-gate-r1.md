1. **Empty-scope.** `prev.data["red_test_paths"]` is `[]`: `_build_validation_prompt` L6634 writes `.get(..., [])`. It can also be absent (the A3398552-style prev) or `None` (L1583). ## Findings

1. **MAJOR: the §1a sibling audit is factually wrong.** §4 says "every other sibling is ambient (no `git_cwd`) so no producer call happens". But `test_bd141_p4d_role_template_injections.py` sets an absolute `git_cwd` and `current_worktree_path` to a real tmp git repo (L150-163) and calls the real `_invoke_validation_llm` (case `phase_5_implement:6664`, L749 and L775). After GREEN the producer runs there with `red_test_paths == []`.
   - Fix: list the file in §4.
   - State its expected outcome. It should still pass because the producer fails open and no preflight assertion exists, but only if finding 2's KeyError and empty-scope rule is settled.
   - Redo the `git_cwd` / `current_worktree_path` / scratchpad-climb grep across all `_invoke_validation_llm` callers.
2. **MAJOR: no rule for empty, absent or non-list `red_test_paths`, or for missing listed files. The result is a vacuous `fresh` (or a KeyError).**
   - op2 subscripts `prev.data["red_test_paths"]`. The key can be absent, `None` or `[]`.
   - With `[]` or nonexistent paths, the three steps pass on zero files. The receipt says `ok: true` and the ladder table gets a `fresh` row that checked nothing. That contradicts the spec's own "Limit stated": `fresh` is supposed to mean syntax, stub and facts passed on the RED files.
   - Fix: spec rule. Either skip the producer when the list is empty or not a list (the rung then reads `missing`, and argument evaluation sits inside the fail-open try), or have `run_engine_preflight` return a failure with no receipt when `red_tests` is empty or a listed file does not exist.
   - Add an AC and a RED test for both cases.
3. **MAJOR: the toplevel and path-base contract for a subdirectory `git_cwd` is unspecified, which allows a false `fresh`.** op1 takes `top`, op2 passes `tree` (`git_cwd`), and s1 AC17 supports a subdirectory `git_cwd`.
   - If GREEN resolves `--show-toplevel` but keeps the `git_cwd`-relative `red_tests`, `_Run.abs` resolves against the wrong base. The files are "not found", and a mocking RED gets `fresh`.
   - If GREEN uses the subdirectory as `top`, `compute_state_hash`'s `-- .` pathspec scopes to the subdirectory, while `receipt_rung` hashes at toplevel (stale or false-fresh depending on where the changes are).
   - Fix: the spec states that the producer resolves toplevel from the given directory and rebases `red_tests` to toplevel-relative or absolute paths (`Path(git_cwd)/p`).
   - Add an AC and a RED test: subdirectory `git_cwd` plus a mocking RED gives event `red` with `red_step == "stub"`.
