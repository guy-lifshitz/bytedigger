## Findings

1. MAJOR F1: spec rule vs AC2 contradiction. Spec: stems shorter than 4 characters produce no stem match. AC2 RED uses `pkg/mod.py` (stem `mod`, 3 chars) and requires `tests/test_mod_extra.py` to be pulled in by stem and `n_sibling == 2`. A GREEN that follows the spec fails AC2; a GREEN that passes AC2 violates the spec. Fix: change the fixture stem to >= 4 chars (e.g. `pkg/modular.py` / `tests/test_modular_extra.py`) in AC2 and everywhere (AC1/AC3 etc. are unaffected except same-dir behaviour), and add a short-stem negative test.
2. MAJOR F2: AC10 "existing stay green" is not achievable with the normalisation rule "dropped if it does not exist on disk". `test_phase_6_post_fix_pytest_gate_7A940850.py` (`_make_ctx` creates an empty `repo` dir, no files) asserts `tests/test_foo.py`, `tests/test_bar.py` (L193-194) and manifest `tests/test_alpha.py` (L257) ARE in argv although none exist on disk; other tests in that file (L292+, L364, L423, L618, L711) very likely depend on pytest being invoked with such phantom paths, and would now hit the empty-scope skip. The same hazard probably applies to `test_bd85_retry_budgets.py` and `4961254A` (r1 already noted 4961254A AC8 would pass only vacuously). Fix: either (a) enumerate those tests in the spec and require the RED lot to update their fixtures to create the files (list which files change), or (b) narrow the existence filter. Without one of these GREEN will break the existing suite, which is exactly what AC10 forbids.
3. MINOR F3: add `monkeypatch.delenv("GIT_INDEX_FILE"/"GIT_DIR"/"GIT_WORK_TREE", raising=False)` in `_Env` so AC9 (and the repo setup) cannot be bypassed by ambient git env.
4. MINOR F4: edges 1-4 above have no tests (empty list, root-level source, `__init__`, non-py/test-file manifest entries). At minimum add edge 1 and the short-stem negative.
5. MINOR F5: RED docstring says AC1-AC5; spec adds no AC/grep for the `docs/events.md` row.
