# bd#86 (P5) — a fact pack before every model step, and a spec-vs-reality gate

**Status: FROZEN** · **Class:** SYSTEMATIC · **Chokepoint:** `facts_pack.facts_block`
(`engine_py/bytedigger_engine/facts_pack.py`), the one place a prompt builder gets
deterministic repo facts from.

## §1 Problem (measured on `96a749b`)

1. **No facts reach a model before it works.** `_build_spec_prompt`
   (`workflows/phase_45_spec.py:1001`) gives the writer the feature request, a path to the
   architecture doc, the decision doc and rule text. It carries no symbol locations, no
   existing tests, no graph neighbours and no known-reds. The same holds for
   `_build_red_prompt` (`phase_5_implement.py:1143`), `_build_validation_prompt` (`:5438`),
   `_build_green_prompt` (`:6186`) and the phase 6 `_build_review_prompt`
   (`phase_6_review.py:689`). The graph appears only as a tool the model may call
   (`phase_5_implement.py:5541-5547`, `phase_1_discovery.py:389`), and phase 1/2 are skipped
   when there is a decision doc.
2. **A frozen spec is never checked against the repo.** Every deterministic spec gate returns
   `skip` on `is_frozen` (`phase_45_spec.py:1294, 1476, 1731, 1973, 2251, 2666, 2765, 2852,
   2949, 3048, 3161, 3624`), and `/build` with a decision doc is the frozen path. A frozen spec
   that cites a symbol that does not exist reaches RED.
3. **Cite-lint cannot run in this repo.** `_verify_spec_cite_lint` shells out to
   `<repo>/spec-cite-lint.py` (`:2282`). The file is not in the tree, so the step ends in the
   terminal `E_SPEC_CITE_LINT_UNAVAILABLE` (the driver location is #81's).
   `spec_cite.lint_spec` itself is importable and needs no driver.
4. **A spec whose criteria all assert on mocks passes every gate** (issue comment). Nothing
   rejects a spec whose acceptance criteria only check a mock of the thing under test.

## §2 Design

### op1 — `facts_pack.py` (core module, stdlib only)

- **`seed_tokens(text) -> Seeds`**. `Seeds` is a frozen dataclass with `files` and `symbols`,
  both sorted tuples.
  - `files`: `spec_cite._CODE_FILE_RE` matches, leading `./` stripped, at most 20.
  - `symbols`: backtick tokens accepted by `spec_cite._is_valid_symbol` that are not file
    tokens, plus bare `name()` call tokens. A trailing `()` is dropped. At most 40,
    kept in the order `(name.isupper(), name)`, so an all-caps constant (`E_*`, `HAL_*`) is
    dropped before a function name.
  - Deterministic: the same text gives the same seeds.
- **`collect(repo_root, text, *, graph_json=None, ledger=None) -> dict`**. Pure and
  JSON-serialisable. Lists are sorted and capped. It reads the repo through
  `spec_cite._iter_code_files`, one walk. Keys:
  - `version`: `1`.
  - `seeds`: `{"files": [...], "symbols": [...]}`.
  - `files`: `[{"path", "exists"}]` for every seed file, relative to `repo_root`.
  - `symbols`: `[{"name", "defined_at": ["rel/path.py:LINE", ...]}]` for every seed symbol
    found by `spec_cite._symbol_in_repo`.
    - A definition is a line matching `def`/`class`/a module-level assignment (python),
      `function`/`class`/`const`/`let` (ts/js), or `name()` (sh).
    - At most 5 locations per symbol.
  - `unresolved`: `[{"name", "near": [...]}]` for every seed symbol absent from the repo
    index. `near` holds up to 3 `difflib.get_close_matches` over the defined names.
  - `tests`: `[{"file", "references": [...], "test_ids": [...]}]`, at most 25 files. A test
    file is one whose path matches the sibling verifier's test shapes (a `tests` or
    `__tests__` component, `test_*.py`, `*.test.{ts,sh,py}`). It is listed when it names a
    seed symbol as a whole word, or the stem of a seed file.
    - `test_ids` are `def test_*` names (python) or `test("…")`/`it("…")` titles (ts),
      at most 30 per file.
    - This one list covers both sibling tests and the module's existing tests.
  - `graph`: `{"status": "ok"|"absent"|"unreadable", "path", "nodes": [...]}`.
    - `nodes` holds `{"symbol", "source", "callers", "callees"}`: `calls` links in and out,
      labels only, at most 10 each.
    - Nodes are graphify `graph.json` code nodes whose label is the seed or `seed()`.
    - The graph file is the first that exists of: the `graph_json` argument,
      `$GRAPHIFY_OUT/graph.json`, `<repo_root>/graphify-out/graph.json`.
    - Read as JSON. No subprocess.
  - `known_reds`: `{"status": "ok"|"absent", "path", "rows": [...]}`.
    - `rows` holds `{"line", "cells"}` for ledger rows (`known_reds_ledger.parse_table_rows`)
      whose cells mention a listed test file, a seed file or a seed symbol.
    - The ledger is the `ledger` argument, else `<repo_root>/known-reds.md`.
- **`render(pack, audience) -> str`** renders one block. Its first line is the module
  constant `FACTS_HEADER`
  (`FACTS (collected deterministically before this call — verify, do not re-derive):`);
  its second line is the audience's lead line.
  - Sections: `SYMBOLS`, `NOT FOUND IN REPO`, `FILES`, `EXISTING TESTS`, `GRAPH`,
    `KNOWN REDS`.
  - An empty section is rendered as `(none)`. Nothing is silently dropped.
  - One lead line per audience (`spec`, `red`, `gate`, `green`, `review`):
    - `spec`: a NOT FOUND name must not be cited as existing; declare it under
      `## Symbols this spec INTRODUCES` or drop it.
    - `red`: listed tests exist; do not duplicate or delete them.
    - `gate`: check the RED against these facts.
    - `green`: listed tests must stay green, and known-reds are not yours to fix.
    - `review`: check the change against these facts.
- **`facts_block(scratchpad, repo_root, text, audience) -> str`** is the only entry point a
  prompt builder calls.
  - Kill-switch: `HAL_FACTS_PACK=0` returns `""` (`flags_catalog`, kind gate, default `"1"`).
  - Cache: `<scratchpad>/facts/<audience>-<sha256(root, text)[:16]>.json`. A hit is read
    back, not recollected, so a retry of the same step sees the same facts. A cache file
    that does not parse is recollected and overwritten, never served as `""` forever.
  - Emits `facts_pack_collected` with `{audience, cached, symbols, unresolved, tests,
    graph_status, known_reds_status}`.
  - Any exception is caught, logged, and emitted as `facts_pack_failed`
    `{audience, error}`; the builder gets `""`.
    - Missing context degrades the prompt. It must not end the build: every check this
      pack informs still runs after the model.

### op3 — `verify_spec_reality`, a blocking gate that also runs on frozen specs

A new step `verify_spec_reality`, inserted after `verify_spec_ac_dsl` and before
`build_review_prompt`. The reviewer never spends a model call on a spec that cites a
non-existent symbol.

- **It does not skip `is_frozen`.** This is the point.
- **Kill-switch:** `HAL_SPEC_REALITY_GATE=0` → `skip` (kind gate, default `"1"`).
- **R1 — cited things exist.** Runs `spec_cite.lint_spec_text(spec_text, repo_root)` in
  process. `lint_spec_text` is `lint_spec` on a string; `lint_spec` now reads the file and
  delegates to it, with no change in behaviour.
  - Keeps findings with status `unresolved_symbol` or `missing_file`.
  - **An abbreviated path is not an invented one.** Every `missing_file` path that is a
    `/`-aligned suffix of a repo code file (`workflows/phase_45_spec.py`,
    `phase_5_implement.py`) is rewritten in the spec text to that file's repo path; with
    several candidates, the first in sorted order. The rewritten text is linted again, and
    R1 is the second run's findings.
    - Every downgrade `lint_spec` applies to a resolved path therefore applies to an
      abbreviated one too: new-context lines, planned and declared symbols, `INTRODUCES`,
      stdlib, SQL, wrong-file.
    - A symbol that is in none of them is still `unresolved_symbol`.
    - Measured over `docs/decisions` at the RED commit (none of them is frozen-detected;
      they serve as a sample of real specs): bare and package-relative paths make 17 of 21
      docs fail R1 without the rewrite.
  - R1 checks only the (file, symbol) pairs `lint_spec` produces. A symbol cited on a line
    with no code path is not checked here; the writer saw it under NOT FOUND IN REPO.
  - `no_citations` stays cite-lint's concern.
  - Each finding is the `_cite_finding_evidence` line for it. An `unresolved_symbol` line
    ends with ` (near: a, b)` when `facts_pack.near_names` finds close defined names.
  - A spec file that cannot be read ends the step with terminal `E_SPEC_REALITY_FAIL`
    naming the read error. The earlier steps wrote it, so this is not a writer problem.
- **R2 — at least one criterion is anchored** (`facts_pack.unanchored_criteria(spec_text,
  repo_root)`).
  - **Criterion.** A criterion line is a scannable line (`spec_cite._iter_scannable_lines`)
    whose first cell or text, after a bullet, a pipe or bold markers, is an AC id
    `AC[-_ ]?\d+[a-z]?`.
  - **Mock word:** `mock`, `MagicMock`, `patch`, `monkeypatch`, `stub`, `fake`, `spy`, in
    any inflection, case-insensitive.
  - **Mocked token.** A backtick anchor is mocked when any of these holds:
    - it starts `mock_`, `fake_` or `stub_`;
    - it is followed by a past participle: optional `is`/`are`, then `mocked`, `patched`,
      `stubbed` or `faked` (`` `x` mocked ``, `` `x` is patched ``);
    - it follows a mock *verb* (a non-participle form: `mock(s|ing)`, `patch(es|ing)`,
      `monkeypatch…`, `stub(s|bing)`, `fake(s)`, `faking`, `MagicMock`, `spy on`) with at
      most three words between them and no `,` `;` `.` `:` in between. A participle never
      reaches forward: in `` with `a` mocked, `b` returns 3 ``, `b` is not mocked;
    - it is a quoted `patch("a.b")` / `patch.object("a.b")` target.
  - **Mock signal:** a mock word on the line, or a mocked token.
  - **Mock-only criterion.** It carries a mock signal and every anchor on it is mocked.
    - Anchors: backtick symbols, code-file paths, quoted `patch("a.b")` targets.
    - A criterion with no mock word is anchored: it asserts on real behaviour.
    - A mock criterion with an unmocked anchor that exists is anchored. "Exists" means
      resolved by the repo index, an existing file, a declared CREATE file or a declared
      INTRODUCES symbol.
  - **Return shape.** `unanchored_criteria` returns `[{"id", "line", "mocked"}]` for the
    mock-only criteria when none is anchored, and `[]` otherwise.
  - **Verdict.** The gate fails only when the spec has criteria and none is anchored. Every
    mock-only criterion is then a finding. `mocked` lists the criterion's mocked anchors,
    sorted; the finding reads `AC3: every reference is mocked (\`mock_send\`)
    — tie it to a real code path, fixture or data shape`).
- **Failure semantics.**
  - Not frozen: `_spec_gate_retry(error_code="E_SPEC_REALITY_FAIL", ...)`. This is the bd#85
    `spec_gates` budget, and the writer gets the findings.
  - Frozen: terminal `E_SPEC_REALITY_FAIL`, `recoverable=False`, findings in `error` and
    `data["spec_reality_findings"]`. A reviewer REVISE on a frozen spec falls back to the
    model writer (`_gate_on_review`): a judgement call is something a writer can answer. A
    reality failure is different. The frozen document disagrees with the repo it is being
    built on, often because it was written against another base. Only its author can
    reconcile that, and re-copying it cannot change the result.
- **Registry and events.**
  - `E_SPEC_REALITY_FAIL` is registered in `error_codes.py`; both `ERROR_CODES.md` copies
    are regenerated.
  - Emits `spec_reality_checked` `{frozen, r1, r2, status}`.

## §3 DesignReview

| dimension | score | note |
|---|---|---|
| clarity / component design | 4 | One module and one entry point (`facts_block`). The gate reuses `lint_spec` and the bd#85 retry helper. |
| external integrations | 4 | graphify only as a file it may read. No subprocess, no network. |
| security | 4 | The pack puts repo text (names, ledger cells) into prompts. The model can already read that text, so no new surface. |
| performance / resilience | 4 | One bounded walk (≤20k files) per audience per build, cached on disk. The rendered block is capped at 8000 chars and says when it truncates. |
| data management | n/a | |
| maintainability | 4 | Pure `collect` + `render` are unit-testable. Builders change by one call each. |
| risks | 3 | See accepted risks. |
| readability | 4 | |

**Verdict: APPROVE WITH CONDITIONS.** Conditions:

- The render cap (8000 chars, with a `(truncated)` line) is part of op1.
- The accepted risks below are recorded.

**Accepted risks:**

- **Prose-only requests.** A feature request with no backticks, paths or `name()` tokens gives
  an empty seed set. The spec pack is then all `(none)`. It is explicit, not wrong. Later
  stages seed from the spec, which the citation contract makes concrete.
- **R1 on frozen specs.** R1 inherits bd#87's `missing_file` blocking. An abbreviated path is
  rewritten, not blocked. A path that matches no repo file (an invented one, or one relative
  to another repo) stops a frozen spec at phase 4.5 with a named finding. That is the intended
  tightening: the frozen path had no check at all.
- **R2 is a heuristic that leans toward passing.** It fails only when *every* criterion is
  mock-only. A spec that mocks the unit under test through a token with no mock word and no
  `mock_` prefix passes. The RED-side stub-passability gate still catches the vacuous test.
- **R1 overlaps cite-lint on non-frozen specs.** When the driver runs and passes, R1 finds
  nothing new. When cite-lint is skipped by config, R1 is the only check. The overlap is kept
  on purpose.
- **Fixture paths and undeclared new symbols fail R1 on a frozen spec**, exactly as cite-lint
  (bd#87) already fails them on a written one. Some of the sampled docs, this one
  included, cite files of a `tmp_path` fixture repo (`pkg/mod.py`) or placeholder paths.
  They would also fail if they were frozen. A frozen spec has to declare such files under
  `Files this spec CREATES`, and its new symbols under `## Symbols this spec INTRODUCES`.
- **A pack failure degrades the prompt, not the build.** The failure is visible as a
  `facts_pack_failed` event and a warning.

Forks decided:

- **(a) Where the gate sits.** In phase 4.5, not in front of RED in phase 5. A failure there
  retries the writer under the existing budget. In phase 5 it would need a cross-phase
  reroute.
- **(b) A frozen failure is terminal**, not a writer fallback.
- **(c) Cache key per audience.** Each stage sees the repo as it is at that stage. After GREEN
  the definitions have moved.
- **(d) The graph is read from `graph.json` directly**, not via `graphify` subprocesses.
  This keeps it deterministic, hermetic and free when the graph is absent.
