## Binding rulings on the four RED-author ambiguities

**R-1: B5g's positional `SiblingAuditError("E_NO_TEST_CORPUS")`.** Accepted as binding. GREEN must define it as:

```python
class SiblingAuditError(Exception):
    def __init__(self, code: str, message: str = "") -> None
```

- The first positional parameter is named `code` and is stored as `.code`. That makes both `SiblingAuditError(code="E_X", …)` (spec §2.2) and `SiblingAuditError("E_X")` (B5g) valid.
- `str(exc)` may be the message.
- The helper's reason is exactly `exc.code`.
- No spec or RED change is required.

**R-2: B5h patches both `p5._parse_spec_files_allowlist` and `run_allowlist.parse_spec_files_allowlist`.** Accepted as binding.
- phase 5 already imports the module-level alias `_parse_spec_files_allowlist` at line 1698. The rewritten helper MUST call it as `_parse_spec_files_allowlist(spec_path)`, resolved through the module global at call time.
- A function-local `from bytedigger_engine.lib.run_allowlist import parse_spec_files_allowlist` is also acceptable, because the second patch covers it.
- NOT acceptable: a new module-top import that binds a different, un-patched name (for example a bare `parse_spec_files_allowlist`). That would make B5h fail against a correct GREEN.

**R-3: B8c's `--json` error field "contains" `E_SIBLING_AUDIT_INTERNAL`.** Accepted, and tightened for GREEN.
- Per §2.3:148, `"error"` is the bare code string: `"error": "E_SIBLING_AUDIT_INTERNAL"`. The exception class and message go to stderr only.
- The RED's `in str(...)` check is a deliberate superset, and the exact form satisfies it.
- The same shape applies on every exit-2 `--json` path except argparse usage errors (`"error": "<SiblingAuditError.code>"`, or `"E_PARTIAL_CHANNELS_GATE"`). For gate_warn, `"error"` is the first gate warning's `W_*` code.
- Also binding for B8c to work in-process:
  - `main` returns an int and does not call `sys.exit`, except where argparse does so itself.
  - `main` calls the module-global `audit` by name.
  - `main` resolves `sys.stdout`/`sys.stderr` at call time. It must not bind them at import time, or `capsys` is defeated once an earlier test has imported the module.

**R-4: B8g's two legs.**
- The legs are:
  - `corpus_root` given: no `W_GIT_ROOT_UNRESOLVED`
  - not given, cwd outside git: the warning, plus rows from the `os.getcwd()` fallback
  - skip if tmp is inside git
- Accepted as the binding interpretation of §4 B8(g), whose wording is garbled (MINOR-B).
- The skip is acceptable: CI and macOS tmp roots are outside any repo. B5 already requires `git` to be present.
- The reason text for rc≠0 is `W_GIT_ROOT_UNRESOLVED rc=<n>`. For a spawn failure it is `W_GIT_ROOT_UNRESOLVED <ExcName>`, as HAL. The RED checks only the prefix.

**R-5 (own ruling, carried over from r1 MINOR-10):** the `git rev-parse --show-toplevel` argv stays inline in the single `subprocess.run(...)` call, as HAL lib:592-596 has it. The B6b check `"rev-parse" in ast.dump(c)` is binding.

## Adversarial edges (not covered by any §4 AC)

1. **Error-code harvest DEAD trap.**
   - `error_codes.check` fails on registered codes that are not harvested (`dead = registered - harvested`, lines 311-317).
   - `CODE_RE = ["']E_[A-Z0-9_]+["']` only matches a code that is quoted **on its own**.
   - HAL's messages are colon-joined, for example lib:976 `"E_NO_TEST_CORPUS: no test files …"`, and §2.3's `E_PARTIAL_CHANNELS_GATE: --require-clean needs…` follows the same pattern. Neither form is harvested.
   - If GREEN emits `E_PARTIAL_CHANNELS_GATE` or `E_SIBLING_AUDIT_INTERNAL` only inside a longer literal or an f-string, `--check` reports DEAD and `test_bd8_l1_oracle` and `test_gh1067` AC5 go red in CI. B8i does not catch this. See MINOR-A.
2. **Stale-stream capture.** A module that binds `_ERR = sys.stderr` at import passes every subprocess test but fails B8c whenever an earlier in-process test imported it first. This makes the failure order-dependent (bound by R-3).
3. **Graph JSON that is an object with non-list members** (`{"nodes":"x","links":{}}`). The spec covers it (§2.4); the RED only tests `[]`. A GREEN that checks `isinstance(data, dict)` but then iterates `data["nodes"]` gets a TypeError, which exits 2 as `E_SIBLING_AUDIT_INTERNAL` (no longer aliased to 1). Phase 5 records it as `detector_error` on every run against such a repo.
4. **Exit-2 `--json` for gate / partial / `SiblingAuditError`.** §2.3 says `rows: []`. TSV mode on the same paths is unspecified: are rows printed before exit 2 or not? HAL prints the rows (lib exit 4, then the shell maps it to 2). The JSON and TSV modes could disagree silently.
5. **Duplicate channels.** The de-duplicating `partial_channels` deviation is stated but untested. `--channels import,import,…`×7 with `--require-clean` should give exit 2 + `E_PARTIAL_CHANNELS_GATE`.
6. **`W_CORPUS_UNREADABLE`.** It replaces HAL's `W_GREP_SPAWN_FAILED` and is the only new `W_*` with no AC. A chmod-000 corpus file (skip when running as root) would pin it.
7. **B5 helper with the real graph present.** `<git_cwd>/graphify-out/graph.json` exists in real repos. No B5 leg stages one, so the `graph_path` selection in the helper is untested. The graph half itself remains HAL-equivalent and untested (r1 edge 3).
